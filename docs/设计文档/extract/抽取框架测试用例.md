# 抽取框架测试用例

## 概述

基于 `docs/extract/抽取框架设计.md`，覆盖扩展名路由、other、非图片/图片分支、关键词过滤、LLM 抽取器选择及验证。

**测试原则：**
- 使用 Mock 对象（OCR、LLM、抽取器），不依赖真实文件或 API
- 每个用例明确说明：注册的抽取器数量、扩展名、关键词、预期行为
- 验证抽取器调用顺序、调用次数、LLM 调用条件

## 测试程序与报告

- **位置**：`tests/extract/unit/test_extract_framework.py`
- **报告目录**：`tests/reports/extract/抽取框架单元测试/`

## 测试用例详细说明

### 抽取器注册说明

每个测试用例应明确说明：
- **注册的抽取器数量**：如"2个抽取器"
- **每个抽取器的扩展名**：如"A（`.jpg`）"
- **每个抽取器的关键词**：如"关键词`["蓝桥杯"]`"
- **每个抽取器的返回类型**：如"返回`template_type=award`"
- **注册顺序**：如"先注册A，后注册B"

### LLM调用验证

对于多抽取器命中场景，必须验证：
1. **LLM是否被调用**：`len(llm.last_messages) == 1`
2. **LLM提示词内容**：包含所有匹配抽取器的`judgment_text`或`description`
3. **LLM返回解析**：框架正确解析JSON数组
4. **抽取器调用顺序**：按LLM返回的顺序调用
5. **抽取器调用次数**：每个抽取器被调用的次数符合预期

### 抽取器调用验证

每个测试用例应验证：
- **调用次数**：`extractor._extract_called == 预期次数`
- **调用顺序**：通过调用次数和返回结果推断
- **是否跳过**：后续抽取器是否被跳过（首个非other即返回）

## 单元测试覆盖要求

- 框架中**直接调用 LLM** 的分支（多命中时选抽取器）必须有对应单测（含 mock LLM）
- 使用 mock：OCR、LLM、抽取器、验证器，避免真实 API 与数据库
- 路径、扩展名、提示词组装等从配置读取，不硬编码
- **每个用例必须明确说明注册的抽取器数量和配置**
