# 文件审核流程说明

本文档从**需求与操作**角度，详细描述「成果/文件导入」审核页与「成果审核」页的界面结构、操作方式及显示规则，供开发与测试对齐，避免编码偏差。

---

## 1. 概述

### 1.1 涉及的页面

系统中有两个入口共用**同一套审核界面**（同一模板 `results.html`）：

| 入口 | 路由 | 说明 |
|------|------|------|
| **成果/文件导入** | `GET /admin/file-import/results?session_id=xxx` | 本次上传后的审核，仅包含本次导入的待处理记录 |
| **成果审核** | `GET /admin/achievement-review/<type>/<sub_tab>/<index>` | 全局待审核队列，包含所有已提交、待管理员确认入库的记录 |

两者在 **TAB 结构、子TAB 规则、工具栏、全部提交/全部放弃的作用域及成功后行为** 上完全一致，区别仅在于数据范围（是否有 `session_id`）及页面标题（如「文件/成果导入审核」 vs 「成果审核」）。

### 1.2 成果类型与类型名称

类型与显示名称以配置为准（如 `achievement_types.type_names`），通常为：

- `award` → 奖状  
- `patent` → 专利  
- `software` → 软著  
- `innovation` → 大创  
- `other` → 其他文件  

下文均用上述中文名称指代对应类型。

## 2. 主TAB 与子TAB 结构

### 2.1 主TAB（类型切换）

- **位置**：页面顶部，横排 Tab。
- **规则**：  
  - 只展示**当前有数据**的类型；没有待处理记录的类型不出现。  
  - 每个 Tab 显示：图标 + 类型名称 + **徽章数字**（该类型待处理总数）。  
- **点击**：切换到对应类型，并重置到该类型的默认子TAB（见下）。  
- **当前选中**：视觉高亮（如底线、主色）。

**示例**：  
若本次有 3 条奖状、1 条软著，则主TAB 为：`[ 奖状 3 ] [ 软著 1 ]`，不显示无数据的专利、大创、其他。

### 2.2 子TAB 规则（按类型区分）

子TAB 在主TAB 下方，**不同类型的子TAB 规则不同**：

| 类型 | 是否有子TAB | 子TAB 内容 | 说明 |
|------|-------------|------------|------|
| **奖状、专利、软著** | 有 | **识别成功**、**待修订** | 按验证结果 `is_valid` 划分；两种都可有，按实际数量展示 |
| **其他文件** | 有 | **图片**、**文件** | 按文件扩展名划分（图片 vs 非图片）；不区分识别结果 |
| **大创** | **无** | — | 不展示子TAB 区域，直接列表 |

- **奖状/专利/软著**：  
  - 「识别成功」：验证通过（`is_valid` 为真）的记录；徽章可用绿色等区分。  
  - 「待修订」：验证未通过的记录；徽章可用橙色等区分。  
  - 若某子类数量为 0，则该子TAB 不显示。  

- **其他文件**：  
  - 「图片」：图片格式的 other 记录；「文件」：非图片。  
  - 同样仅展示数量大于 0 的子TAB。  

- **大创**：  
  - **不渲染子TAB 区块**，无「识别成功」「待修订」等。  

### 2.3 子TAB 默认与自动切换

- 切换主TAB 时，子TAB 默认选中有数据的第一个子类（如先「识别成功」再「待修订」；先「图片」再「文件」）。  
- 若当前子TAB 下记录被全部提交或全部放弃后数量变为 0，**应自动切到同类型另一有数据的子TAB**；若该类型已无任何数据，则按整体规则切到其他类型或空态（见后）。

## 3. 工具栏与内容区（按类型区分）

### 3.1 通用规则

- 所有类型均展示 **「全部提交」「全部放弃」** 按钮。  
- 两按钮的**作用域**均为**当前主TAB + 当前子TAB**（大创无子TAB，则为当前类型全部）。详见第 4 节。

### 3.2 奖状、专利、软著、其他文件（单项逐条模式）

**工具栏**包含：

- **待处理信息**：类型名称 + 当前子TAB 下的**数量徽章**（如 `奖状 2`）。  
- **当前项指示**：`第 X / Y 项`，可选带 `(ID: xxx)`。  
- **导航**：「上一项」「下一项」按钮；首项时「上一项」禁用，末项时「下一项」禁用。  
- **单条操作**：「提交」「删除」；仅当有当前条时显示。  
- **批量操作**：「全部提交」「全部放弃」（始终显示）。

**内容区**：

- 展示**当前一条**记录的编辑/预览（奖状表单、专利表单、软著表单、其他文件的预览与操作区等）。  
- 通过「上一项」「下一项」或列表内跳转切换 `index`，从而切换当前条。

### 3.3 大创（列表模式）

**工具栏**包含：

- **待处理信息**：类型名称 + **「共 X 条」** 文案（如 `大创 共 5 条`）。  
- **不展示**「第 X / Y 项」、「上一项」「下一项」、单条「提交」「删除」。  
- **仅展示**「全部提交」「全部放弃」。

**内容区**：

- **列表页**：表格，每行一条大创项目。  
- **表格列**（顺序固定）：  
  - ID、项目名称、项目级别、负责人、年份、开始时间、结束时间、验收等级、**操作**。  
- **操作列**（每行）：  
  - **「查看/编辑」**：进入该条的编辑视图；  
  - **「删除」**：删除该条大创待处理记录，删除后刷新当前列表。  

**编辑视图**（同页切换）：

- 从列表点击「查看/编辑」后，**隐藏列表**，仅显示该条的编辑表单（字段与成果管理中大创编辑一致）。  
- 页面提供 **「返回列表」** 按钮；点击后回到列表，不保留编辑态。  
- 编辑表单有「提交」等单条操作；提交或删除单条后，**刷新当前页**（列表或编辑视图），仍停留在成果审核/导入审核页，不跳转到他处。

## 4. 全部提交、全部放弃（作用域与行为）

### 4.1 作用域（必须严格执行）

- **全部提交**、**全部放弃** 仅针对 **当前选中的主TAB + 当前子TAB** 下的记录，**不影响**其他类型、其他子TAB。  
- **奖状/专利/软著**：  
  - 当前子TAB 为「识别成功」→ 仅操作识别成功的记录；  
  - 当前子TAB 为「待修订」→ 仅操作待修订的记录。  
- **其他文件**：  
  - 当前子TAB 为「图片」→ 仅操作图片类 other；  
  - 当前子TAB 为「文件」→ 仅操作非图片类 other。  
- **大创**：无子TAB，操作当前类型下**全部**待处理大创记录。

**编码约束**：批量接口请求体须严格按类型传参。奖状/专利/软著缺 `sub_tab`、其他文件缺 `sub_tab` 或 `validation_status` 时，接口应返回 400；大创可不传 `sub_tab` / `validation_status`。

### 4.2 操作流程

**全部提交**：

1. 用户点击「全部提交」。  
2. 弹出确认框，文案需明确**当前范围**，例如：  
   - 「确认提交所有**识别成功的**奖状？提交后可以在成果审核页面继续处理。」  
   - 「确认提交所有**待修订的**奖状？…」  
   - 大创等无子TAB 时，可为「所有大创」等。  
3. 用户确认后，请求批量提交接口，请求体须包含：  
   - `type`：当前主TAB 类型；  
   - `session_id`：成果/文件导入时有值，成果审核时为 `null`；  
   - `sub_tab`：奖状/专利/软著为 `valid` 或 `invalid`，其他文件为 `image` 或 `file`；**大创不传 `sub_tab`**。  
4. 成功后：  
   - 显示成功提示（如「已提交 N 条记录」）；  
   - **统一执行 `window.location.reload()`**，**不跳转**到上传页或其他页面；  
   - 刷新后仍为当前审核页，主TAB、子TAB 保持不变（若当前子TAB 已空，后端/前端可自动切到同类型另一子TAB或空态）。

**全部放弃**：

1. 用户点击「全部放弃」。  
2. 确认框文案明确当前范围，例如：「确认放弃所有**识别成功的**奖状？此操作不可恢复。」  
3. 请求体包含 `type`、`session_id`、`validation_status`：  
   - 奖状/专利/软著：`validation_status` = `valid` 或 `invalid`；  
   - 其他文件：`validation_status` = `image` 或 `file`；  
   - **大创不传 `validation_status`**（或传 `all`，后端视作全部）。  
4. 成功后：  
   - 提示「已放弃 N 条记录」等；  
   - **同样 `window.location.reload()`**，不跳转；  
   - 刷新后仍停留在当前审核页，按当前类型/子TAB 更新列表或空态。

### 4.3 成功后界面变化示例

- **示例 1**：奖状 3 条（识别成功 1、待修订 2），当前在「识别成功」。  
  - 点击「全部提交」→ 仅提交 1 条识别成功；  
  - 刷新后：奖状 2 条，**待修订 2**；若自动切子TAB，则显示「待修订」且列表为 2 条待修订。  

- **示例 2**：奖状 2（均为待修订）、软著 1。  
  - 在奖状-待修订下「全部提交」→ 提交 2 条奖状；  
  - 刷新后：奖状消失，主TAB 仅剩软著；若仅剩一个类型，可自动选中软著。  

- **示例 3**：大创 5 条，当前在列表页。  
  - 「全部提交」→ 提交全部 5 条；  
  - 刷新后：大创无数据，主TAB 可能不再展示大创，或展示空态。

## 5. 空态与「全部处理完成」

### 5.1 当前类型下无数据

- **奖状/专利/软著/其他**：当前主TAB+子TAB 下无记录时，内容区展示占位文案，如「没有待处理的奖状」「请选择其他类型查看」等，**不展示**表单或列表。  
- **大创**：列表无数据时，同样占位提示「没有待处理的大创项目」等。

### 5.2 所有类型均无待处理（全部处理完成）

- **成果/文件导入**（有 `session_id`）：  
  - 提示「本次导入的文件已全部处理完成」；  
  - 提供跳转「成果审核」的按钮或短时自动跳转；  
  - 不再展示主TAB/子TAB。  

- **成果审核**（无 `session_id`）：  
  - 提示「所有成果已审核完成」；  
  - 提供跳转「成果管理」的按钮或短时自动跳转；  
  - 不再展示主TAB/子TAB。

## 6. 单条操作（奖状/专利/软著/其他）

### 6.1 提交

- 用户编辑当前条后点击「提交」。  
- 若为**成果审核**：即审核通过并入库，成功后可刷新当前页或跳转到下一项等，**不离开**成果审核流程。  
- 若为**成果/文件导入**：将当前条标记为已提交（如 `status` → `submit`），待成果审核中再入库；成功后在当前页刷新，若还有同子TAB 的后续项，可自动切到下一项。

### 6.2 删除

- 点击「删除」→ 确认 → 调用删除接口，删除当前条。  
- 成功后：  
  - 若本子TAB 还有其余项，可跳转到下一项或刷新列表；  
  - 若已无剩余，则按 5.1 显示空态或按 5.2 显示全部完成。

---

## 7. 大创单条操作（列表内）

- **查看/编辑**：点击行内「查看/编辑」→ 同页切换为编辑表单，可修改各字段 → 提交后刷新，回到列表或仍处于编辑态（以产品为准，当前为实现为返回列表）。  
- **删除**：点击行内「删除」→ 确认 → 仅删除该条；成功后 `reload` 当前页，列表更新。

---

## 8. URL 与参数约定

### 8.1 成果/文件导入

- **基础**：`/admin/file-import/results?session_id=<session_id>`  
- **可选**：`tab`（主TAB 类型）、`sub_tab`（子TAB）、`index`（当前项序号）、`edit`（大创编辑时传入 `pending_id`）。  
- 大创列表页无 `edit`；点击「查看/编辑」后，URL 带 `edit=<pending_id>`，同一路由负责列表与编辑两种视图。

### 8.2 成果审核

- **基础**：`/admin/achievement-review/<type>/<sub_tab>/<index>`  
- 大创无子TAB，但 URL 仍保留 `sub_tab`（如 `valid`）以兼容路由；大创列表与编辑通过 `?edit=<pending_id>` 区分。  
- 导航、刷新、全部提交/全部放弃后的跳转，均使用上述规则，且 **不跳转到上传页**。

---

## 9. 与「成果管理」的一致性

- 大创列表的**列**、**操作按钮**（「查看/编辑」「删除」）与成果管理中的大创管理列表保持**同风格、同交互**；  
- 大创编辑表单的**字段、校验、提交逻辑**与成果管理中的大创编辑一致，仅在审核流程中绑定的是待处理记录（`pending_id`）而非已入库记录。

## 10. 总结（开发自检清单）

实现与联调时，可依下表自检：

| 项目 | 要求 |
|------|------|
| 主TAB | 仅展示有数据的类型；徽章为总数；点击切换类型并重置子TAB |
| 子TAB | 奖状/专利/软著：识别成功、待修订；其他：图片、文件；**大创无子TAB** |
| 奖状/专利/软著/其他 | 单项模式：上一项、下一项、单条提交、删除；当前条编辑/预览 |
| 大创 | 列表模式：表格 + 查看/编辑、删除；无上一项/下一项、无单条提交/删除 |
| 全部提交 / 全部放弃 | 仅当前主TAB+子TAB（大创为当前类型全部）；确认文案明确范围 |
| 批量成功后 | **一律 `reload` 当前页**，不跳转上传页；刷新后保持或自动切换子TAB/类型 |
| 空态 | 当前类型无数据 → 占位提示；全部完成 → 提示 + 跳转成果审核/成果管理 |
| URL | 文件导入带 `session_id`；成果审核为 `achievement-review`；大创编辑带 `edit` |

若以上与实现不一致，以本文档为需求基准进行修正。
