# 测试体系使用指南

## 快速开始

### 运行所有测试

```bash
# 统一运行所有测试套件
python tests/run_all_tests.py
```

### 运行单个测试套件

```bash
# 文件流转测试（最全面，包含文件操作、API调用）
python tests/test_files.py

# 页面渲染测试（验证页面能否正常渲染）
python tests/test_page_rendering.py

# 路由完整性测试（验证所有url_for调用）
python tests/test_routes_integrity.py

# 首页渲染测试（快速验证首页）
python tests/test_index_page.py
```

## 测试套件说明

### 1. 文件流转测试 (`test_files.py`)

**用途**：验证文件在整个业务流程中的正确流转

**测试内容**：
- 文件上传 → temp_upload
- 提交审核 → review
- 审核通过 → 业务目录
- 文件访问（查看、下载）
- 编辑页面文件显示
- 实验室文件管理
- 其他文件管理

**测试结果**：
- HTML报告：`tests/report/文件流转验证.html`
- 自动在浏览器中打开

**适用场景**：
- 修改文件管理相关代码后
- 添加新的文件类型支持
- 修改文件流转逻辑

### 2. 页面渲染测试 (`test_page_rendering.py`)

**用途**：验证所有关键页面能否正常渲染

**测试内容**：
- 公开页面：首页、登录页
- 管理员页面：仪表板、列表页
- 教师/学生页面：仪表板

**测试结果**：
- 控制台输出
- 显示每个页面的状态码和错误信息

**适用场景**：
- 修改模板文件后
- 添加新页面后
- 修改路由后

### 3. 路由完整性测试 (`test_routes_integrity.py`)

**用途**：验证所有模板中的 `url_for()` 调用是否正确

**测试内容**：
- 扫描所有 `.html` 模板文件
- 提取所有 `url_for()` 调用
- 验证路由是否存在

**测试结果**：
- 控制台输出
- 显示失败的路由引用详情

**适用场景**：
- 修改模板中的路由引用
- 删除或重命名路由后
- 添加新模板后

### 4. 首页渲染测试 (`test_index_page.py`)

**用途**：快速验证首页能否正常渲染

**适用场景**：
- 快速验证首页功能
- 调试首页相关问题

## 日常开发工作流

### 场景1：开发新功能

```bash
# 1. 开发功能
# 2. 运行相关测试
python tests/test_files.py          # 如果涉及文件操作
python tests/test_page_rendering.py # 如果涉及页面渲染

# 3. 修复问题
# 4. 重新运行测试直到通过
```

### 场景2：修改模板

```bash
# 1. 修改模板
# 2. 运行路由完整性测试
python tests/test_routes_integrity.py

# 3. 运行页面渲染测试
python tests/test_page_rendering.py

# 4. 修复问题
```

### 场景3：修改路由

```bash
# 1. 修改路由
# 2. 运行路由完整性测试（验证引用）
python tests/test_routes_integrity.py

# 3. 运行页面渲染测试（验证页面）
python tests/test_page_rendering.py
```

### 场景4：提交代码前

```bash
# 运行所有测试，确保没有破坏现有功能
python tests/run_all_tests.py
```

## 常见问题

### Q1: 测试失败怎么办？

**步骤**：
1. 查看错误信息，定位问题
2. 检查相关代码
3. 修复问题
4. 重新运行测试

**示例**：
```
[FAIL] GET /admin/awards - 500
  错误: HTTP状态码错误: 500
  模板错误: BuildError
```

**解决方法**：
- 检查路由是否存在
- 检查模板中的 `url_for()` 调用
- 检查数据库连接

### Q2: 测试运行很慢怎么办？

**优化建议**：
1. 只运行相关的测试套件（不要运行全部）
2. 使用测试数据库（如果支持）
3. 并行运行独立测试（如果支持）

### Q3: 如何添加新的测试？

**文件流转测试**：
在 `test_files.py` 中添加新的测试方法：
```python
def test_new_feature(self, file_path: Path) -> CategoryResult:
    """测试新功能"""
    # 实现测试逻辑
```

**页面渲染测试**：
在 `test_page_rendering.py` 中添加新的测试方法：
```python
def test_new_page(self):
    """测试新页面"""
    result = self.test_page('/new/page', login_func=self._login_as_admin)
```

## 最佳实践

### 1. 测试驱动开发（TDD）

- 先写测试，后写代码
- 测试失败 → 写代码 → 测试通过 → 重构

### 2. 持续测试

- 每次修改后运行相关测试
- 提交代码前运行所有测试
- 定期运行完整测试套件

### 3. 测试维护

- 及时更新测试用例
- 删除过时的测试
- 保持测试代码简洁

### 4. 测试数据管理

- 使用独立的测试数据
- 测试前后清理数据
- 避免测试数据污染
