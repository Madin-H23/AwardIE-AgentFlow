# 作品导向范围收缩:P0 从 265 端点全量复刻收缩为核心纵切面

立项方案 §4.1 原口径"v1 全部功能 1:1 复刻(265 端点),任何缺失视为 v2 失败"建立在 2-3 人全职、28 周的假设上。2026-08-29 grilling 确认真实约束为:单人 + AI agent、5-10h/周、首要目标是面试/答辩作品。据此收缩:真范围 = 核心纵切面(登录 / 成果提交 / AI 审核 / 入库+时间线 / AI 问答 / 导出,约 50-63 端点)+ 高频扩展队列;看板、实验室、门户、管理台归档/模板/日志子域定性为长尾,留 v1 只读并存。节奏改为 tracer 前置的四阶段(约 6-9 个月):P0 骨架+tracer 可演示 → P1 纵切面补全+切换 → P2 高频扩展 → P3 稳态收束(可选)。立项仪式取消,方案文档 v1.0 暂不改版,修订由 ADR 承载。

## Considered Options

- **维持全量复刻**:与单人时长直接矛盾,按原五阶段顺序作品 6 个月后才可演示,答辩窗口大概率错过。
- **六组留 v1**(连 ADMIN 用户管理、导出全组也不做):admin 用户管理仅约 10 端点,省不了工作量,却让管理面演示割裂。
- **两组留 v1**(看板也 Vue 化):约 200 端点回到 v2,接近方案原文口径,作品导向名存实亡。

## Consequences

- DoD 口径改写:P2 DoD"265 端点全量冒烟"→"纵切面全量冒烟";整体 DoD"全部 265 端点走 v2"→"纵切面+高频扩展清单";"团队培训""部门周报连续 4 周全绿"等条款删除。
- M4 里程碑"v1 下线"改为"稳态收束"软目标(见 CONTEXT.md)。
- 导出(FR-ACH)进纵切面,Apache POI 提前引入,公式注入过滤规则随迁。
- 每阶段 DoD 数值标准(覆盖率 ≥70%、P95 ≤30ms 等)不变,条目随阶段内容重排。
