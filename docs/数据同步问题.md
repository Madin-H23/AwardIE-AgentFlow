## 发现很多奖状抽取内容有错误

可能是模板修改之后没有对奖状进行重新抽取了。解决方法就是重新抽取。

但是重新抽取奖状之后，奖状和活动之间的关系就又要重新关联了。

这里又讨论回那个问题。活动到底是什么，为什么必须有个活动呢？

原本设计活动（尤其是奖状恢复的活动）是为了方便统计一个比赛的最高奖。用于竞赛填报的时候。

但是如果仅仅是为了这个，其实根本没有必要这样复杂，只需要对奖状本身统计增加一些复杂度就可以了。

活动还是要还原事物本身的逻辑。

一个活动，比如2025蓝桥杯比赛，可以有好几位老师发起的活动，老师们各自带队参赛。

一个竞赛活动，可以定义为：某一届/年比赛，由某个老师带队发起的活动。如果正常情况下是教师发起，可能有多位教师在其中。如果是从奖状中恢复的，则只能根据第一导师去恢复活动。比如2025蓝桥杯，我们俱乐部就有三位老师的三个活动。

竞赛活动定义的意义：

1. 申报和数据跟踪：方便每一年申报存档，比如打印出申报申请，给系里审核通过，就知道参赛人员。方便后续通知跟催竞赛。后续学生会的数据也可以从这里来。
2. 最高竞赛奖项的识别：虽然不如原来的识别方便，但是问题也不是很大。
3. 方便观察。
4. 和其他活动逻辑可以一致。不然后续创建活动，有几十个人报名，就麻烦了。

## 活动重新定义

一项竞赛（竞赛年份+竞赛id唯一确定）+ 指导老师（列表）唯一识别了一项活动。

比如计算机设计大赛，里面好多赛道，每个赛道作品各不相同。但是对于某个老师群体来说，这就只是一次活动。

教师自定义的活动标题可以随意，但是奖状恢复的活动固定命名为：`{year}年{competition_name} {第一指导教师姓名}`

从奖状恢复活动的逻辑：

1. 根据竞赛年份+竞赛id+第一指导老师，匹配现有的所有活动，如果可以匹配上，就将奖状添加到这个活动中。如果匹配不上，就新建一个。奖状必须有指导老师，如果没有就无法导入（在另外的页面处理了）

# 活动设计修改

竞赛活动有两种创建方式：

1. 由教师创建活动。教师可以设置活动的可见范围。也就是说如果教师设置为所有学生可见，就是所有看到的学生都可以报名这个活动；也可以选择本实验室学生可见；或者指定可见学生名单。学生在自己的主页下面可以看到最新报名中的活动，并且可以选择报名。活动关联的教师可以有多个，活动负责人默认在教师列表中。
2. 由奖状恢复。这种情况用于历史数据恢复，或者用于那些之前没有在系统上发起的活动，事后添加信息。此时奖状中如果没有指导教师，则无法恢复活动。活动的可见范围默认就是奖状上的名单（包括教师和学生）

我希望做的修改如下：

1. 将负责人从学生修改为教师。新增一个活动的可见范围。
2. 对于每个学生用户主页，对于活动部分需要区分显示：已经参加活动和正在进行中的活动（显示申报中或者进行中）。打开进行中的活动，学生可以点击申请，加入活动的申请，需要写明申请理由。负责教师可以审批这个活动申请，教师看到的申请信息包括：学生的姓名，学号，年级，专业，申请理由，过往获奖情况。教师可以同意或者拒绝（拒绝可以给出理由）。如果申请通过，学生可以看到自己的活动中增加了这一条。并且在消息中可以看到通过申请或者拒绝的消息。
3. 对于在活动关联表中的教师，都可以在自己的主页上看到这个活动。教师是不需要申报活动的，在创建的时候添加即可。
4. 编辑/添加活动：增加活动可见范围的设置，可以直接设置活动的状态。也就是说，并不是每个活动都允许申报的，有的活动直接设置为开始状态，此时就不接受加入申请了。但是不影响可见性。

从上述业务逻辑的角度，请先帮我基于现有的竞赛活动进行更新设计。同时对于活动申请，批准加入流程进行一个梳理，并且整理出这个业务相关的数据、流程和前端页面的设计方案。

我想再进一步设计。这个系统的活动不仅仅只有竞赛活动，还有其他类型的活动，具体如下：

1. 项目开发：有活动标题和描述，关联教师和学生，负责人是学生。关联文件列表：参考资料等。活动状态：申报，进行，结束
2. 大学生创新创业项目（简称大创）：有活动标题和描述，活动状态：申报、立项、进行中、结束、取消。负责人是教师，关联学生，关联文件列表：申报材料，立项通知，中期材料，结题材料，代码链接等。
3. 大学生竞赛：有活动标题和描述，活动状态：申报、进行中、结束，负责人是教师，关联学生，关联文件列表：竞赛通知，参考资料等等

所有活动，教师和学生都可以有多个，负责人可以是教师也可以是学生。教师和负责人都可以对活动进行编辑和修改。活动可以选择公开范围：全公开，实验室内公开，只针对活动参与者公开。活动申请的时候，一定需要选择对应的学生实验室，所有活动必须属于某个学生实验室。活动必须至少关联一个教师。

对于活动的成果也有下面几种：

1. 获奖：唯一的形式就是奖状。一个活动可以对应多个奖状。
2. 立项通知：针对大创的立项通知，里面包括了立项的编号，起止日期，佐证材料（通常就是一个图片文件）
3. 软件著作权：名称，关联的教师和学生清单，佐证材料（图片），日期
4. 论文：名称，发表刊物，发表日期，佐证材料(文件)

一个活动对应0到多个成果。一个成果也可能属于多个活动。例如获奖的奖状可以同时属于大创和竞赛活动。

活动的管理：

1. 对于活动的负责人：可以在主页上看到这个活动，并且对活动进行修订。如增加活动参与者，审核活动参与申请。
2. 对于参与活动的所有人：可以在主页上看到这个活动，上传成果，文件等，但是不能删除。只有活动负责人可以删除。
3. 活动的教师角色，拥有和负责人相同的权限。
4. 根据活动的公开程度，未参与活动的人也能在主页上看到公开活动信息。可以对看到的活动提前申报申请。

活动的创建：

1. 在页面上创建。活动创建必须指定教师和学生实验室，并且选定活动类别。
2. 由成果恢复。原因是很多历史成果也要导入，并且恢复活动。目前已经完成的就是由奖状恢复活动。这里需要修改的地方是，原本基本上是一个奖状恢复成一个活动，是以学生为主体考虑的。现在要修改为以教师作为主体进行活动恢复。因为竞赛活动必须是教师发起。只要是同年/届,同一个教师发起的活动都算是一个活动。

这次的改动主要集中在以下几点：

1. 活动由学生负责人修改为教师负责人，活动的创建（从奖状恢复）的逻辑大幅度变化。
2. 增加其他活动，因此需要增加类的层次和抽象。
3. 增加学生对活动的申请，负责人、教师对参与活动申请的审批。注：活动创建时候添加的学生，不需要再申请，申请只针对没有事先添加到活动的学生。
4. 考虑除了奖状之外的其他成果，也需要做类的抽象。现有活动关联到成果。
