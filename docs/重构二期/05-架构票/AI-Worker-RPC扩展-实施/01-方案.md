## 契约设计(与票面表述的偏差声明)

- 票面"proto 契约扩展(ExtractRequest/ExtractResponse…)"实作定为**新增独立 RPC**,不扩展现有通用 `Extract`:
  - `ExtractTemplate(ExtractTemplateRequest) → ExtractTemplateResponse`:bytes image 直传(multipart 样本图未落盘场景)+ template_rule_json 扩展位;
  - `GeneratePrompt(GeneratePromptRequest) → GeneratePromptResponse`:规则 JSON + sample_text → prompt。
- 理由:通用 Extract(file_path→doc_type 识别)与模板抽取(强制 award 抽取器+默认 prompt)输入输出语义不同,独立消息避免"一个 RPC 两种行为模式";proto3 纯新增向后兼容,现有 extractAndReview/ask 契约零影响。
- `template_rule_json` 本批为**扩展位**(v1 extract-for-create 语义=强制 award 通用抽取,不消费规则),规则化抽取属后续演进,已在 proto 注释声明。

## v1 复用(零重写)

| v1 资产 | 复用方式 |
|---|---|
| `backend/extract/extractors/base.ExtractContext`(use_default_prompt_only=True, force_type=True)+ `framework.get_extractor("award")` | ExtractTemplate 抽取主链,与 v1 extract-for-create 路由逐参数对齐 |

## Java 侧落点

- `AiWorkerClient` 加 `extractTemplate(...)`/`generatePrompt(...)` 两方法(unary blocking,deadline 由调用方给)。
- `AdminTemplateDetailController` 注入 AiWorkerClient,新增两端点(fake/grpc 双模式,`ai.worker.mode` 切换):
  - `POST /api/v2/admin/templates/extract-for-create`(multipart file)→ `{mode, dataJson, ocrText}`;
  - `POST /api/v2/admin/templates/generate-prompt-for-create`(平铺 JSON body,对齐 v1 表单形态)→ `{mode, prompt[, disclaimer]}`;
  - fake 桩=确定性回显(开发/CI);grpc 直调 Worker,`StatusRuntimeException` → 4003 降级(ChatService 同语义)。
- `/{id}/test` 端点维持现状(fake 桩/4003):模板试测(OCR+匹配+抽取)语义与 GeneratePrompt 不同,待页面批次接 ExtractTemplate。
