# 文件存储域迁移 批1:文件域服务收敛(三段文档 01)

> 归属:《文件存储域统一迁移》架构票交付物 1(2026-09-03 深夜用户拍板 D1a+D2a+D3a+D4 全建议项后启动;票面〇节评审决策单)。
> 本批=后端+数据迁移,前端零改动(模板页走 API 的 create/detail/image 契约不变)。

## 方案

### 存储收敛原则(验收=代码级唯一写入口)

`FileStorageService`(submission 域,已服务 2 调用方)原位扩展为全站通用文件服务——**不改名不搬家**(改名是美观问题,收敛写入口才是验收);新增 `readAll(relativePath)` 与 `contentTypeOf(relativePath)` 两个能力供"只存路径"的域复用。templates 域全部读写经它,与 submission 同一 store 语义(sha256 前 16 位命名+目录 files/v2/)。

### 四处切点(AdminTemplateDetailController)

| 端点 | 旧(BYTEA) | 新(目录存储) |
|---|---|---|
| POST /create | `UPDATE sample_image_blob = bytes` | `assertAllowed` 前置校验(三校验:白名单扩展名/10MB/魔术字节)→ `store()` → `UPDATE sample_image_path` |
| GET /{id}/detail | `hasImage = blob IS NOT NULL` | `hasImage = sample_image_path IS NOT NULL` |
| GET /{id}/image | 列读 byte[]+文件头判型 | `readAll(path)`+`contentTypeOf(path)` |
| POST /{id}/test(grpc 分支) | 列读 blob | `readAll(path)`(无 path 显式 4000) |

### 数据迁移(D2a 一次性)

Flyway `V2__templates_sample_image_path.sql` 加 `sample_image_path VARCHAR(500)`;`scripts/migrate_template_image_blobs.py` 一次性搬迁(blob→文件,与 store 同款 sha256 命名+魔数判型;回读全量哈希校验;成功后置空 blob)。**幂等**(只处理 blob 非空且 path 空的行)。列本体 DROP 留批 3(等脚本在全部环境跑过)。
