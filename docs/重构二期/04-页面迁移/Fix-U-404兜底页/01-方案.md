# Fix-U:未匹配路由 404 兜底页(三段文档 01)

> 来源:三角色全功能巡检(#39)发现的 low UX 项①——访问未匹配路由时页面渲染空白,无任何提示。

## 问题定性

- v2 前端为 SPA(vue-router 4,base=/v2/),路由表无 catch-all;登录用户访问任意未注册路径(如手输错 URL、旧书签)时 vue-router 无匹配项,RouterView 渲染空白,无 404 提示也无返回入口。
- v1 为 Flask 服务端渲染,天然有 404 响应页;此问题为 v2 SPA 化引入,不属于 v1 对照范围(无迁移先例,按 SPA 标准做法补齐)。

## 方案

| 项 | 决策 |
|---|---|
| 兜底页 | 新增 `NotFoundView.vue`(无壳独立页:404 大字 + "页面不存在或已被移动" + 返回首页链接);样式复用全局 tokens 变量(--brand/--ink/--ink-2),不依赖 console-shell 上下文 |
| 路由注册 | router/index.ts 路由表**末尾**追加 `{ path: '/:pathMatch(.*)*', name: 'not-found' }`(vue-router 4 catch-all 标准写法) |
| 返回落位 | "返回首页"为 `router-link to="/"`;守卫既有逻辑保证按角色落位(admin→工作台,student/teacher→各自门户仪表板),无需在兜底页重复判断 |
| 未登录访问 | 守卫 `to.name !== 'login' && !auth.isLoggedIn` 先拦截去登录页,兜底页仅登录用户可达,不新增守卫分支 |

## 明确不做

- 不改 ConsoleLayout/PortalLayout(兜底页不带壳,避免非 admin 角色看到 console 壳)。
- 不做 404 页的角色化文案(单一文案覆盖三角色,保持最小)。

## 测试计划

- E2E(pages.spec.js):登录后访问 `/no-such-page-xyz`,断言 404 标题与"返回首页"链接可见。
- lint/build 本地门禁;全量回归见 03-测试。
