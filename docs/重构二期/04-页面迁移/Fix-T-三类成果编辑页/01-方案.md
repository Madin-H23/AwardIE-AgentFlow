# Fix-T:三类成果 edit/view + templates 挂账说明(三段文档 01)

> 对照 v1:patents edit(246)/view(201)、software edit(197)/view(141)、innovation edit(1121)/view(183)、templates tabs create(524)/detail(364)
> v2 落点:三个编辑页(panent/software/innovation)+ 六端点

## 一、范围决策(两处,均有依据)

| 决策 | 依据 |
|---|---|
| **templates create/detail 显式挂账** | 两页核心能力=OCR 模板提取/校验规则/prompt 生成/试测(extract-for-create、generate-prompt、test、validation-rules 等 AI 域路由),v2 AI Worker 无对应 RPC——与批 5"图片 OCR 批量导入挂账(待 Worker 扩 RPC)"同源。按 goal 约束"未就绪项显式挂账,不硬做"。**收官报告需用户确认此挂账** |
| **view 页并入编辑页(六页→三页)** | 三个 view 页字段清单是 edit 字段子集(逐字段核对),独有内容仅"提交人/时间+文件下载"——前者以只读"系统信息"区并入编辑页底部(R 批审核详情页先例),后者挂账。形态等价先例:排查报告 D 系列"师生编辑独立页→v2 用 dialog"已定为可接受差异 |

## 二、v1 契约(实读路由)

- **patents edit**:patent_name*/patent_type(发明专利|实用新型|外观设计)/application_number/publication_number/inventor/application_date/patentee/laboratory_id + certificate_file 上传(GET 下拉=实验室)
- **software edit**:software_name*/software_version/registration_number/certificate_no/registration_date/copyright_owner/laboratory_id + certificate_file 上传
- **innovation edit**:project_no/project_type(国家级|省级|院级)/project_name*/status(进行中|已结题|终止)/start_date/end_date/funding_amount/student_leader_name/student_leader_id/other_members/supervisors/laboratory_id;GET 带 **leader 匹配状态**(学号精确→姓名精确→ambiguous/not_found 三态)
- 权限均 admin+teacher 关联分支(v2 统一 requireAdmin,同 R 批偏差 5)

## 三、v2 方案

### 后端:AdminAchievementEditController(/api/v2/admin 下 patents|software|innovation 三域)
- 每域 `GET /{id}/edit-detail` + `PUT /{id}`(@Transactional)
- **别名双引号**;other_members JSONB 读写:`CAST(? AS jsonb)`(台账坑)、GET `::TEXT`
- 必填校验 4000(专利名/软著名/项目名);不存在 4004;leader 状态三态返回
- 与 vault(/api/v2/admin/vault/*)无路由冲突;既有行编辑保留

### 前端:PatentEditView / SoftwareEditView / InnovationEditView
- 布局沿用 R 批 AwardEditView 惯例(页头三按钮+表单卡+系统信息区);类型枚举用 v2 CHECK 约束值
- 入口:成果库对应 tab 行操作加"详情编辑"链接(award tab 已有,R 批)

### 挂账(与 R 批同源)
1. certificate_file 上传/下载/展示(patents、software 证书文件,v1 存储域)
2. templates create/detail 整页(AI 提取域,见范围决策)
3. innovation 学生负责人"选择器"(v1 Select2+匹配)简化为文本+三态徽章展示(与 v2 用户体系单表一致)
