# 功能小批:审核双列表补"查看详情"入口(2026-09-04)

> 来源:用户实测反馈——成果审核与待审管理只能看行参数,无法点进详情页查看就批/驳,"只有查看了才能知道能不能批准"。

## 现状与根因

详情页 `/admin/review/:id`(AdminReviewDetailView,Fix-F)本身完整:状态提示/提交信息/成果数据(JSON)/验证结果/**审核操作(通过+驳回带意见)**/审核历史——**缺的只是列表页入口**(两页操作列都只有行内快捷动作,无查看链路)。另:该页数据端点为 admin-only,教师角色直接复用会 403。

## 实现(入口+教师侧补链)

| 层 | 改动 |
|---|---|
| `TeacherReviewController` | 新增 `GET /api/v2/teacher/pending/{id}`(requireRole teacher;4004 兜底)——教师侧详情数据端点 |
| `router/index.ts` | portal 子路由 `teacher/review/:id`(roles teacher/admin)复用 AdminReviewDetailView——教师留在 portal 壳,不逃逸到 console |
| `AdminReviewDetailView.vue` | **角色感知**:auth.role=teacher→数据 `/teacher/pending/{id}`+动作 `/teacher/review/{id}`+返回 `/portal/teacher/review`;admin→原 admin 端点+返回 `/admin/review` |
| `TeacherReviewView.vue` | 审核操作列首加"查看"(router-link→portal 详情),**所有行可见**(已审行也可回看) |
| `AdminAwardsView.vue` | 操作列首加"查看"(router-link→console 详情),**所有行可见** |

## 实测(MCP 双角色)

- admin:待审管理→查看→`/admin/review/5881` 详情渲染(审核操作+验证结果"缺少必填字段: date"即审批依据);
- teacher:审核台→查看→`/portal/teacher/review/5881` 详情渲染(教师端点出数+审核操作齐全);
- 已审/已驳回行同样有查看入口(回看审核历史)。
