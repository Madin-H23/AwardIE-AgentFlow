## 一、大创 status:三方向定夺

2026-08-25 诊断结论(非 bug,数据治理现状):`innovation_projects` 20 条全「进行中」,根因三合力——xlsx 导入默认「进行中」+ ORM/表单兜底「进行中」+ 管理员从未进编辑页逐条改。三方向:

| 方向 | 内容 | 本批处置 |
|---|---|---|
| 1 · 告知业务 | 用户指南写明状态维护的日常操作 | **做**(见 `docs/用户指南/大创项目状态管理.md`) |

## 二、方向2 设计

### 数据事实(2026-09-22 实测 awardie_dev)

- 20 条全「进行中」;11 条有 end_date 且**全部已过期**(格式三种:`2025-06` ×5、`2024.5.1` ×2、`2026-05` ×4);9 条无 end_date;
- `end_date` 为 **TEXT 列**(非 DATE),存量格式混杂,PG 无法直接 `::date`(实测 `text < date` 运算符不存在)→ 解析必须在 Java 侧做可测函数;
- `status VARCHAR(20) CHECK(status IN ('进行中','已结题','终止'))`,`updated_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP`。

### 语义边界(全部有测试锁定)

1. 只选 `status='进行中'` 的行——终止/已结题**永不被覆盖**(幂等,可重复点击);
2. 判定线 = end_date **严格早于今天**(Asia/Shanghai);结束日期=当天=项目最后一天,**不校准**;
3. 日期不可识别(含 13 月、2 月 30 日)→ 跳过并计数(`skippedUnparsed`),**绝不猜**;
4. 无 end_date(NULL/空串)→ 不在候选集,不计 skipped。

### 接口契约

`POST /api/v2/admin/vault/innovation/calibrate-status`(admin only,无 body)

响应 `data`(CalibrationResult record):
```json
{ "considered": 11, "calibrated": 11, "skippedUnparsed": 0, "calibratedIds": [39,40,41,42,43,53,54,55,56,57,58] }
```
message = `已校准 N 条`。

### 实现落点

- 新 `InnovationStatusService`(@Service,@Transactional;对齐 InnovationImportService 风格):查询候选 → `parseLooseDate` 宽松解析 → 逐行 UPDATE `status='已结题', updated_at=NOW()` → 审计;
- `AdminVaultController` 增 POST 端点(该控制器原无 POST;与 `DELETE /{type}/{id}` 方法/段数不撞);
- 审计:`system_event_log` **`event_category='system'`**(CHECK 白名单仅 ocr/llm/breaker/auth/upload/db/security/system,写 maintenance 会 500)、level='info'、message='大创状态校准:…'、operator_code、detail::jsonb 含 counts+ids;
- 前端 `AdminAchievementsView.vue`(成果库五 tab 页):filter-bar 加大创 tab 专属「状态校准」按钮(`v-if="activeTab==='innovation'"`,busy ref 防重复点击,仿 AdminImportView),确认框文案写明四类不受影响,成功消息带 skipped 提示。

### 前端按钮放置依据

Explore 实证:成果库页无全局工具栏,filter-bar(L142-158,flex gap 10)是唯一自然的 per-tab 动作位;大创 tab 操作列仅 90px 宽且只有删除,不放行内按钮。
