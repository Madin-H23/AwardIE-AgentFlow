## 一、统计卡归零：两个叠加 bug，都不在数据侧

用户截图：五张汇总卡全 0，但**同页**的分类表（奖状 197/软著 1/大创 20）和 Top12 有真实数据。
这个"同页一半有一半没有"就是定位钥匙——两块数据走的是同一个接口 `/business/stats/overview`。

### 根因 1（前端，主因）：绑定错了一层

```js
// 修复前
summary.value = overview || {}            // overview 是整个响应体 {summary, category}
summary.value.awardsTotal                  // → undefined → 页面显示 0
// 修复后
summary.value = overview?.summary || {}
```

后端其实返回了 `usersTotal=1834 / competitionsTotal=130 / whitelist=84`，
前端全部绑在错误的层级上。分类表恰好绑的是 `overview?.category`，所以有数。

### 根因 2（后端，次因）：`awardsTotal` 从未被赋值

`StatsService.getOverview` 只 set 了 pendingSubmit/usersTotal/competitionsTotal/whitelist
四项，`setAwardsTotal` 整个方法里不存在（字段在 VO 里声明了，注释还写着"五类合计"）。
即使修好前端，成果总数也只会是 null→0。

**修**：五类计数求和赋值（与 VO 契约一致）。
**回归测试**：`StatsAndAuditTest.overviewSummaryIsExact` 补断言
`awardsTotal == 10`（固定夹具 4+2+1+1+2），锁死"恰好等于"，不是"字段存在"。

### 验证

- API：`{"awardsTotal": 219, "pendingSubmit": 0, "usersTotal": 1834, "competitionsTotal": 130, "whitelist": 84}`
- 浏览器（Playwright 实测）：五卡 **219 / 0 / 1834 / 130 / 84**，控制台 0 错误
- 后端全量测试 92+135 = **0 失败 0 错误**

### 「待审核 0」不是 bug

V1 的 45 条待审**全部是 `status='archived'` 历史归档**（批12 已实测），没有 pending 在途。
这个 0 是真实业务状态。观察期内有新提交进来这个数才会变。

### 踩坑记录（两件，都与"改了没生效"有关）

1. **`mvn -pl yudao-server spring-boot:run` 的模块依赖走本地仓库 jar**：
   `mvn test` 只编译 target/classes 不 install，改完 `StatsService` 直接重启后端，跑的还是旧 jar。
   必须先 `mvn install -pl yudao-module-business -am -DskipTests` 再重启。症状就是
   "代码明明改了、测试也过了，接口返回纹丝不动"。
2. **后台任务退出会连带清掉 java 子进程**：`taskkill` 杀掉占用 48080 的旧 java 后，
   用 run_in_background 起的后端在任务失败退出时被连带回收，页面请求 `ERR_CONNECTION_REFUSED`。
   改用 `Start-Process cmd /c mvn ...`（脱离 agent 进程树）启动，进程不再被清理。
   与 2026-08-28 记的「Bash 后台子进程随调用清理」同族，本次补的是**可靠的替代做法**。

### 租户切换器：摘 UI，不关后端

顶部「请选择租户」下拉来自 `ToolHeader.vue` 的 `TenantVisit` 组件
（条件 = `VITE_APP_TENANT_ENABLE==='true'` + `system:tenant:visit` 权限）。

**关键陷阱**：`axios/service.ts` 用**同一个** env 开关决定是否携带 `tenant-id` 请求头。
把 `VITE_APP_TENANT_ENABLE` 翻成 false，所有请求都会缺租户头被后端拒收——
后端多租户过滤是全局的，`getRequiredTenantId` 在业务服务里到处在用。

**做法**：env 保持 true，从 `ToolHeader.vue` 摘除 `TenantVisit` 及其 computed、
import（含 `checkPermi` 孤儿引用——ts:check 抓出来的）。登录页租户字段保留
（默认"芋道源码"即 tenant=1，与 ETL/对账写死的口径一致）。
