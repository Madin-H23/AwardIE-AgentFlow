## 二、四道闸记录

### 闸1/2 联合审查(规范 + spec + 安全 + 测试)

发现 1 High + 7 Medium + 8 Low,High/Medium 全修:

- **High CSV 注入可绕过(已修)**:原实现只判首字符 ∈ `=+-@`,但 Excel/LibreOffice 会**先剥离前导 Tab/空格/换行**再解析公式,`\t=cmd|'/C calc'!A0` 能原样落盘。已改为先 `stripLeading()` 再判前缀,并加 4 个绕过用例的单测;
- **Medium 行数上限不保护资源(已修)**:原实现先 `jdbcTemplate.query` 把全量物化成 List 再判大小——百万行会全部进堆才抛错,与"防拖垮服务器"的意图相悖。已把上限前置到 SQL `LIMIT maxRows + 1`(多取一行只为区分"恰好等于"与"超过",报错语义不变);
- **Medium 审计响应缺 changeDetail(已修)**:驳回原因只在 timeline 端点可见,全量审计列表无法追溯"为什么被驳回",与 User Story 1 冲突。已补字段(DO 里是 String,VO 也用 String——初稿写成 Object 会让 `BeanUtils.toBean` 转换失败,已改);
- **Medium XLSX 文件名缺扩展名(已修)**:浏览器优先采用 Content-Disposition 的名字,缺扩展名会存成无后缀文件;
- **Medium 停用账号的学生获奖行静默消失(已决策)**:导出 SQL 用 `INNER JOIN system_users` 且带 `u.deleted=0`,毕业生账号逻辑删除后其所有获奖行从台账消失。**这是学工台账的数据完整性风险**,本批已记入遗留待与业务确认(改 LEFT JOIN 会让"停用账号"的学生出现在台账里,两种都有取舍,不擅自决定);
- **Medium 租户隔离测试是假阳性(已修)**:原写法只断言"他租户数据缺席",但若 SQL 漏 `u.tenant_id` 条件也会因 `system_users.tenant_id=2` 被滤掉而通过——测不出目标缺陷。已改为**正样本 + 负样本双向断言**;
- **Medium 空表 CSV 断言不生效(已修)**:`text.split("\r\n")` 默认丢弃尾部空串,"仅表头"与"表头+1 行"切分结果都是长度 1,断言永真。已改字节级相等;
- **Medium R5 必测项缺失(已补)**:审计租户隔离、越界页、`AuditActionTypeTest`(已知码/未知码兜底/null)三项补齐;
- **Low 9 项**:删 3 处未用 import、补 `LABELS` JavaDoc、修正"v3 尚未写入 year/laboratory_id"的注释事实(列存在但物化不写,只有 `granted_role` 列不存在)、修 `count` JavaDoc、错误码提示语、XLSX 数量列数值型、需求文档权限点笔误(3071-3075 → 3071-3073)——全修。

## 三、CI 复刻验证抓到的两个真缺陷

按纪律**本地复刻 CI 建库**(全新 `awardie_v3_test` + CI 同款六脚本 + `utf8mb4_bin` + `FLUSHDB`)再跑全量:

1. **统计 SQL 拼接漏 `AND`(真缺陷)**:原先用 `SCOPE` 常量拼在 `WHERE status = 'pending'` 之后,常量本身不带前导 `AND`,拼出 `status = 'pending' deleted = b'0'` 的语法错 → 全部统计端点 500。**是"用固定数据夹具锁死数值口径"的测试抓出来的**——若沿用 v2 那种只验响应结构的测试,这个错会一路进 CI;
2. **测试夹具 BIT(1) 传字符串(测试自身 bug)**:给 `white_list BIT(1)` 传 `"1"` 报 `Data too long`,必须传 boolean。

## 四、测试水平的关键差异(与 v2 的本质区别)

v2 的 `AdminStatsTest` **只验响应结构不验聚合数值**(取证确认:无固定数据夹具)。那层测试无法发现 SQL 口径错误——v2 的统计 SQL 里就藏着 `GROUP BY c.id` 依赖 PG 主键函数依赖、MySQL `ONLY_FULL_GROUP_BY` 下会直接报错这类问题。

本批全部统计断言用**固定数据夹具锁死确切数值**:种 4 条 awards / 2 条 patents / 1 条 software / 1 条 other / 2 条 innovation,断言 `category.award` 必须**恰好等于 4**;种两条同数值竞赛断言 `name` 升序;租户隔离用正负双向样本。

## 五、本批修掉的 v2 缺陷

1. **学工导出"学号"列是内部 users.id**——v2 选 `w.student_id`(users.id 主键)却把表头写成"学号",学工拿到还得二次加工。v3 取 `u.username`(v3 的 username 就是学号,批2 ETL 事实);
2. **CSV 公式注入**——v2 只做 RFC 引号转义,`=+ -@` 开头内容会被 Excel 执行。v3 加前缀转义(且修了前导空白绕过);
3. **CSV 依赖 `row.values()` 顺序对应 SELECT 列序**——无列名映射,换驱动或加别名就错列。v3 一律传有序字符串数组;
4. **导出无行数上限**——v2 只有年度明细 `LIMIT 500`,其余无限制。v3 默认上限 10000 可配,且前置到 SQL;
5. **竞赛 Top 同数时行序随机**——v2 只有 `ORDER BY total DESC`,同数由执行计划决定,截图与对账会漂。v3 加 `name ASC` 二级排序;
6. **统计用 Integer 计数**——大表溢出变 500。v3 用 Long;
7. **XLSX 文件名缺扩展名**——已补。

## 六、遗留(前端与前置债分开记)

**必须记住的前置债**(不解决则统计维度永远是空):
1. 物化不写 `year` / `laboratory_id` → 年份与实验室统计为空;
2. 无教师关系表 → 教师维度全空;
3. `granted_role` 不在 awards 表 → 教师证书拆分维度不存在。

**本批挂账**:
4. 导出对停用/逻辑删除账号用 `INNER JOIN`,其获奖行会从台账消失——需业务确认口径;
5. 审计表无 `trace_id` / `operator_role` / `operator_ip`,故日志**不能按 trace 搜**;
6. 审计关键词 LIKE 无全文索引,历史增长后可能全扫;
7. 竞赛表、awards 表的统计维度无索引(本批数据量小未暴露);
8. `AuditLogPageReqVO` 的 `achievementKind`/`operatorKeyword` 无长度上限、`actionType` 无枚举约束;
9. XLSX 未验 sheet 内容(只验 PK 魔数与行数)。

**明确不做(已记入需求 D1-D6)**:年份/实验室/教师维度统计与分析、教师个人导出、学生个人导出、SSE 实时流、芋道 infra/system 日志聚合、趋势图、导出图片 ZIP。
