# 批8-大创+导入 需求文档(00-需求)

> 2026-09-25 | 分支 refactor/v3-yudao-migration | 上一提交 862582c4(批7)
> 立项依据:`00-立项.md` 第三节批8 行

## 一、背景与目标

批6 只建了 `awardie_innovation_projects` 与 `awardie_innovation_project_students` 两张表,没有业务代码;批5 审核流明确"大创不物化"。本批补上 v2 大创资产表的**正式写入通道**与 **status 维护能力**。

**先纠正立项文档的一处措辞**:立项写"innovation 物化",但取证证明 **v2 也没有大创物化**——`ReviewService.materialize()` 对 innovation 直接返回 `skipped`,学生提交的大创审核通过后只归档,不写项目资产表。v3 批5 照搬这个语义是**对的**。v2 真正往大创资产表写数据的通道只有一条:admin 的 xlsx 导入。

故本批正式命名为 **大创 Excel 入库通道 + status 方向1+2 等价实现**,不做"审核通过自动物化"(那是凭空发明业务)。

## 二、事实调查(agent 实测 + 本机数据库取证,facts)

### F1 v2 大创审核不物化

- `ReviewService.materialize()`:`case "innovation" -> "skipped"`,不写 `innovation_projects`,也不写 `innovation_project_students`(`awardie-backend/.../ReviewService.java:71-81`);
- 仍写 `action_type=8` 审计,detail 为 `{"message":"入库","comment":"skipped"}`;
- v2 测试明确锁住这一点(`AdminAwardTest.java:142-171`)。
- **结论**:v3 保持 skipped,本批不改审核流。

### F2 v2 xlsx 导入是唯一入库通道

- 端点:`POST /api/v2/admin/import/innovation/preview`(multipart)+ `/confirm`(JSON rows);
- 写库固定 `status='进行中'`、`submitter_type='admin'`、`project_type` 空时默认"院级"(`InnovationImportService.java:111-123`);
- **不写** `innovation_project_students`;
- 幂等判据是 `project_no UNIQUE`,重复编号捕获 `DuplicateKeyException` 后 `skipped++` 并同时记进 `errors[]`——前端若把 `errors.length` 显示成"失败",重复行会同时算"跳过"和"失败"(v2 缺陷)。

### F3 关联表是刚需,但 v2 导入不写(本机 PG 实测)

- `innovation_project_students` **有 28 行真实数据**,覆盖 20 个项目;
- `match_type` 取值只有 `student_id_exact`;`role` 取值 `leader` / `member`;
- 20 个项目**全部**有负责人学号;
- Java 侧只有 3 处 `SELECT`,**无任何 INSERT**——这 28 行是一次性数据修复时用脚本灌的,之后导入的新项目不会再产生关联;
- 学生门户"我的大创"只查这张表(`StudentPortalController.java:43-47,82-90`),不会按 `student_leader_id` 临时匹配;
- **后果**:v2 现状下,导入的新项目在学生端永远看不到。这是缺陷,不是语义。

### F4 经费单位 v2 自相矛盾,且从未被真实数据触发

- 导入页列序说明写"经费(**万元**)"(`AdminImportView.vue:124`);
- 编辑页表单标签写"资助金额(**元**)"(`InnovationEditView.vue:133`);
- 后端 `tryDouble()` 原值存库,**不换算**;
- **本机 PG 实测:20 条大创的 `funding_amount` 全是 NULL**,没有一条有值——这个矛盾从未被真实数据触发过。

### F5 status 校准规则(v2 已实现并验收,2026-09-22)

- 候选集:`status='进行中' AND end_date IS NOT NULL AND btrim(end_date)<>''`;
- 判定:时区 `Asia/Shanghai`,**严格早于今天**才校准;当天不动;未来不动;
- 只动"进行中";终止/已结题不动;
- 日期解析支持 `2025-06` / `2024.5.1` / `2025-06-30` / `2025/6/1` / `2025年6月` / `2025年6月30日` / 混合分隔;只写年月按**月首日**处理;
- 不可识别(待定/只有年份/13 月/2 月 30 日/多余段)→ 跳过并计数,**绝不猜**;
- 顺序重复点击幂等(已结题行不再进候选集);
- 返回 `considered/calibrated/skippedUnparsed/calibratedIds`;写 system event 审计;
- 并发非严格幂等(查询无 `FOR UPDATE`)。

### F6 v3 现状

- 两张表字段完整(表结构见 `awardie-business.sql:290-330`),比 v2 多了租户/逻辑删除/审计列;
- **无任何 innovation 专用 DO/Mapper/Service/Controller**;
- 通用成果库用 `AchievementVaultService` 的 JdbcTemplate 硬撑 innovation 的列表/编辑/删除;
- `awardie_innovation_project_students` **缺** project FK、`(project_id,student_id)` 唯一约束、role/match_type CHECK、查询索引;
- `awardie_innovation_projects.project_no` 是**全表唯一**(不含 tenant_id),逻辑删除后仍占位;
- v3 已有 `yudao-spring-boot-starter-excel`(FastExcel),**不缺 xlsx 依赖**;multipart 上限单文件 16MB;
- **v3 `system_users.username` 就是学号**(批2 ETL 把 v2 `login_code` 映射过来,实测 1792 个纯数字账号)——关联匹配查这张表,无需改表。

### F7 v2 导入的其余缺陷(不迁移)

- `sha256` 是**伪校验**:preview 返回哈希,confirm 接收但 controller 与 service 都不用,不缓存 preview,不验证 rows 是否来自该文件,测试传 `"x"` 仍成功;
- confirm **信任客户端回传的 rows**,可任意篡改;
- `importRows()` **无 `@Transactional`**,中途异常会留下半截数据;
- 无表头校验、无行数上限;经费非法字符串静默变 null;Excel 原生日期 numeric 会被转成序列号;
- 前端 preview 用裸 `fetch` **漏 CSRF header**,真实浏览器链会 403。

## 三、需求条目

### R1 innovation 领域模型(补齐分层)

- 新建 `InnovationProjectDO` / `InnovationProjectMapper` / `InnovationService`,把 innovation 从通用 JdbcTemplate 成果库里独立出来;
- 表约束补齐:`project_students` 加 project FK 与 `(project_id, student_id, deleted)` 唯一约束、role/match_type 枚举、`project_id`/`student_id` 查询索引;`projects` 加 status/project_type 的应用层枚举校验(v3 不用 DB CHECK,沿既有口径);
- 校准与导入的更新语句**必须带 `tenant_id` + `deleted=0` 条件**(通用 `AchievementVaultService.update()` 当前只按 id 更新,这是既有缺口,本批新代码不得照抄)。

### R2 xlsx 导入(preview + confirm)

- 端点:`POST /business/innovation/import/preview`(multipart)+ `POST /business/innovation/import/confirm`;
- 固定十列列序(项目编号|项目名称|项目类型|起始日期|结束日期|负责人姓名|负责人学号|其他成员|指导教师|经费),首行表头,只读第一个 sheet;
- **行数上限 1000**(v2 无上限,是资源耗尽面);**校验表头文字**;
- 行级校验:项目名称必填、项目类型白名单、经费必须可解析为数字(不静默置 null);
- preview 产出**服务端 preview token**(随机 UUID + 行摘要哈希),confirm 凭 token 取回服务端缓存的行数据——**不接受客户端回传的行内容**(修 v2 伪校验缺陷);
- 幂等:同一 preview token 只能 confirm 一次(消费即失效);
- 导入整体**一个事务**,任一行结构性失败整体回滚(行级业务错误仍按 v2 语义跳过);
- 返回 `imported/skipped/errors[]/studentsLinked/studentsUnmatched`;
- 留痕:导入结果写审计(芋道操作日志或 innovation 业务日志,能承载 imported/skipped/ids)。

### R3 经费单位(决策 C:列存元,导入按万元换算)

- 列语义统一为**元**(`DECIMAL(12,2)`,列注释写明);
- 导入页列序说明仍写"经费(万元)"(贴合学校立项表填报习惯),**导入时 ×10000 存元**;
- 编辑页显示与编辑都用元;
- 非法经费字符串 → 行级错误,**不再静默变 null**;
- 测试须覆盖:导入 2.5(万元)→ 库里 25000(元)。

### R4 导入时自动建立学生关联(决策 B-lite)

- **leader**:按 `student_leader_id` 到 `system_users.username` 精确匹配,命中则建 `role=leader` / `match_type=student_id_exact`;
- **member**:其他成员列按分隔符切分,能解析出**学号形态**的项尝试匹配,命中建 `role=member`;只有姓名无法匹配的跳过;
- 匹配不上**不阻断导入**,计入 `studentsUnmatched` 返回给管理员;
- 同一项目重复导入(编号已存在被跳过)不重复建关联;
- 关联表 `(project_id, student_id, deleted)` 唯一约束防重复。

### R5 status 方向1+2 等价实现

- 方向1(单项编辑):innovation 专用编辑端点,维护 v2 编辑页的全字段(项目编号/类型/名称/状态/起止日期/经费/负责人/成员/指导教师/关联实验室),**带 status 枚举校验**;
- 方向2(批量校准):`POST /business/innovation/calibrate-status`,严格按 F5 规则;
- 校准返回 `considered/calibrated/skippedUnparsed/calibratedIds`;
- 写审计;
- 重复调用幂等。

### R6 权限与菜单

- 菜单 3006(AwardIE 大创管理)+ 权限点 3061-3065(`business:innovation:query/create/import/update/calibrate`);
- 授权 super_admin 与 awardie_admin,**`system_role_menu` INSERT 必写 `tenant_id=1`**(批6 头号缺陷);
- 学生/教师不授权(大创管理是 admin 专属);学生的"我的大创"门户属批10。

### R7 测试

- 集成测试 ≥ 16 例:preview/confirm 正常路径、token 校验、token 消费幂等、超行数、坏表头、非法类型/日期/经费、重复编号跳过、事务回滚、经费换算、leader 匹配、member 匹配、未匹配计数不阻断、关联唯一约束、calibrate 全部边界(过期/未来/当天/NULL/空串/不可解析/终止/已结题/重复调用)、越权 403;
- 单元测试:日期解析(覆盖 v2 全部格式 + 边界)、经费换算、关联匹配;
- 测试**不依赖真 Worker/前端**。

## 四、决策(用户 2026-09-25 已拍板)

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| D1 | 导入是否自动建学生关联 | **建 leader;member 尽力匹配** | 实测关联表有 28 行真实数据且是学生看到项目的唯一途径,v2 导入不建关联是缺陷不是语义;leader 学号可靠、规则简单、风险可控 |
| D2 | 经费单位 | **列存元,导入按万元 ×10000 换算** | 消除 v2 两处文案差 10000 倍的歧义;学校立项表习惯填万元,换算只在导入边界做一次,库内语义统一 |
| D3 | 是否做"审核通过自动物化大创" | **不做** | v2 也没有;做了就是凭空发明业务 |
| D4 | 前端按钮归属 | **本批只交付端点与契约,按钮在批10** | v3 前端源码目录当前为空,批10 才是前端壳;批8 若硬做前端会与批10 冲突 |
| D5 | 通用成果库的 innovation 分支 | **保留不动,新代码不依赖** | 批6 已交付且有测试;本批新建专用分层,不去动既有服务(减少回归面) |
| D6 | `project_no` 唯一性 | **暂不改**(全表唯一,逻辑删除后占位) | 改成分租户唯一会影响既有 ETL 与引用检查;记入遗留,不在本批扩大范围 |

## 五、范围边界

**做**:R1-R7。

**不做**:
- 审核通过自动物化大创(D3);
- 大创前端页面与校准按钮(D4,属批10);
- `project_no` 唯一性改造(D6);
- v2 → v3 的 innovation 数据 ETL(属批11 统一 ETL);
- 关联表的历史数据修复脚本(批11 ETL 时一并处理)。

## 六、总验收

1. 大创 Excel 导入可用:preview 出 token + 逐行校验结果,confirm 凭 token 入库,重复编号跳过,经费按万元换算成元;
2. 导入自动建 leader 关联,学生"我的大创"能查到新导入项目;
3. status 方向1+2 等价可用,校准边界与 v2 一致,重复调用幂等;
4. preview token 机制有效:客户端篡改行数据无效,token 不可重复使用;
5. 新增测试全绿,全量 0 失败(基线 801);
6. p3c 增量 0;四道闸 0 High/Critical;
7. 推前本地复刻 CI 建库后全量仍 0 失败;CI 绿。
