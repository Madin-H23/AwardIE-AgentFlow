## 决策链(用户拍板,记录在案)

1. 教师维度统计口径 = **文本匹配,不建关系表**(v1 因"导入时人名匹配失败导致表空"
   弃用关系表是本项目自己踩过的坑;文本匹配与教师指导成果页同口径,数字永远一致)
2. 同名教师 = **编号约定**:全员编号张三1/张三2、不留裸名;编号同时落账号昵称与
   奖状 supervisor_name 两处(批6 行编辑已支持)。实测当前 40 名教师零同名,约定备用
3. 匹配实现 = **FIND_IN_SET 精确成员比较**(非子串):编号陷阱与子串陷阱一并消灭

## 踩坑两记(都进了代码注释/测试)

1. **FIND_IN_SET 列对列比较的 collation 冲突**:system_users(芋道原生,utf8mb4_unicode_ci)
   vs awardie_*(utf8mb4_0900_ai_ci),Illegal mix of collations 实测报错;
   显式 `u.nickname COLLATE utf8mb4_0900_ai_ci`。Controller 的同名匹配是**参数对列**,
   走连接默认 collation 不受影响——同类查询两种写法,坑只在列对列
2. **跑测试丢 -am = 测的是旧 jar**:mvn test -pl yudao-server 不带 -am 时
   yudao-module-business 用本地仓库上次 install 的产物,新端点/FIND_IN_SET 全不在——
   首轮 3 个失败全是这个(与批15"改了没生效"同族)。排障时先看失败模式是否像"代码没生效"
