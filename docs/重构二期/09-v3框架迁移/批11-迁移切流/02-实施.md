## 三、切流前置的 schema 补齐(不做就丢数据)

`v3_schema_diff.py` 的列级比对结论:

```
awards            → awardie_awards            缺 4 列
                       granted_role, llm_prompt, llm_response, validation_result
award_teacher_winners / award_related_students / review_logs → 目标无此表
```

**`granted_role` 就是批9 前置债「awards 表无 granted_role 列」的真实成因**——不是没实现,
是表根本没这列。切流正好补上,顺带解掉「无教师关系表」那条(24 条教师获奖数据本来会在
切流时永久丢失)。

落地两份:
- `awardie-business.sql` 尾部追加(与既有 11 处 ALTER 同惯例,**只给全新库跑**,CI 零改动);
- `scripts/v3_apply_missing_columns.py` 用 `information_schema` 判存在性,可在**已建好的库**
  上重复执行(批10 吃过亏:`awardie-business.sql` 的 ALTER 无幂等守卫,重跑会在第 283 行
  报 1060 重复列而中断)。

## 四、本批修掉的 4 个自己的 bug

这批工具本身出过一次错,记录下来是因为**闸门工具自己错了比闸门没跑更危险**。

| # | bug | 后果 | 修法 |
|---|---|---|---|
| 1 | 列名手写两处 | 写 `student_id_no`(实为 `student_id_str`)、`sort_order`(实为 `display_order`) | 改 `MAPS` 单一事实来源,读源表时列名错**当场抛 UndefinedColumn** |
| 2 | `pymysql` 直接传 `dict` | `TypeError: dict can not be used as parameter` | 写库前把 dict/list 统一 `json.dumps` |
| 3 | `norm()` 用 `if v` 判 `BIT(1)` | `b'\x00'` 长度 1 是 truthy → 0 和 1 都算成 `'1' → **218 行竞赛全报假警** | 按字节真值 `int.from_bytes(...) != 0`;补 8 输入单元自验 |
| 4 | 演练脚本没把 `AWARDIE_TARGET_DB` 传给 ETL | **ETL 打到了真实 `awardie_v3` 而不是演练库**,演练等于没演 | 加防呆:执行前先探 ETL 实际指向哪个库,不是演练库就拒绝执行 |

bug 3 与 bug 4 都是「演练/对账机制自己失真」——如果不真跑一遍全流程,它们会一路带到
切流闸门口。

## 七、遗留与下批入口

1. **存量文件二进制未迁**:v2 的 `file_path` 是本机绝对路径,v3 走内容寻址存储
   (`files/v3/<sha16>.<ext>`)。本批只保证路径字段迁到位,**切流后证书图会显示不出来**,
   需单独立项做文件搬运。
2. **批9 三条前置债**:`award_teacher_winners` 已在切流时建表(24 条数据保住),
   但 v3 运行时**物化链仍不写 `year`/`laboratory_id`** → 年份与实验室维度统计仍为空。
3. **观察期**:切流后建议 ≥3 个工作日冻结业务写入,v2 保持可启动,确认无问题再下线。
4. **下一批**:切流窗口执行(用户拍板后)+ 存量文件搬运立项。
