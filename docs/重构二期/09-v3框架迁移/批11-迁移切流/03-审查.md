## 二、发现

### 🔴 Critical — ETL 漏写框架列,2895 行成果数据对应用不可见

**位置**:`scripts/etl_v2_business_to_v3.py` `write_all()`

**现象**:首次实跑后实测:

```
awards         tenant_id=0  creator=''  312 行
pending        tenant_id=0  creator=''  588 行
innovation     tenant_id=0  creator=''   20 行
templates      tenant_id=0  creator=''   20 行
review_logs    tenant_id=0  creator='' 1955 行
stu_winners    tenant_id=1  creator=etl 334 行   ← 只有无主键的关联表是对的
```

**根因**:框架列 `creator/updater/deleted/tenant_id` 不是 v2 源列,不在 `MAPS` 里;
`write_all` 用 `elif 'creator' in write_cols:` 分支去补它们——而该条件对**所有有主键的
主表恒为假**,框架列被整体跳过,INSERT 不含这些列,于是落回 DDL 默认值
`tenant_id BIGINT DEFAULT 0`。无主键的关联表走另一条分支,恰好补上了,把这个 bug 掩盖了。

**后果**:芋道多租户按 `tenant_id = 当前租户(1)` 过滤。**切流后 2895 行成果数据
一行都查不到**——而当时的对账报的是「16 表全部一致」:行数对、主键在、业务字段哈希对,
唯独没查框架列。

**修法**:
1. `FRAME_COLS`/`FRAME_VALUES` 显式声明,对**所有表统一追加**,不再按表分叉;
2. 追加前先查 `information_schema` 拿目标表实际列——各表框架列并不齐
   (批4 建的 `awardie_award_student_winners` 就没有 `updater`/`update_time`),
   盲加会 `Unknown column`;
3. 加列数/值数自检,不等就 `SystemExit` 中止——宁可中止也不写半张表。

**验证**:重跑后全部 `tenant_id=1, creator='etl'`;
应用可见性实测 `awards 311/311`、`pending 590/590` 可见(差额是 v3 自己的旧测试行)。

### 🟠 High — 切流门禁的 CI 凭据口径错(已在审查前修,记录留痕)

**位置**`.github/workflows/ci-v3.yml`「Cutover schema completeness」

CI 里 `AWARDIE_MYSQL_PASSWORD` 装的是**应用用户**口令(`ci-test-pass`),
与 root 口令不是同一个值。该 step 一开始用 `-uroot` + 应用口令 → `Access denied`,
连挂两次(先是 `pymysql` 缺依赖,再是这个)。

**修法**:账号由 `AWARDIE_MYSQL_USER` 决定,默认 `awardie_v3`(本地/演练库正确),
CI 显式设 `root` —— 与同一 job 相邻的建库步骤 `-uroot -proot` 完全一致。

**这条是「本地绿≠CI绿」第五次**,本批栽两次,根因都是**验证环境与目标环境不一致**,
而我当时只复刻了数据库结构,没复刻凭据。

### 🟡 Medium — `v3_reconcile.py` 缺框架列核验(Critical 的直接后果)

三层对账只覆盖业务列。Critical 那个 bug 恰好落在覆盖之外。已补 **L4**:
只对 `creator='etl'` 的行查 `tenant_id<>1 OR deleted<>0`(不管 v3 自己的测试行——
那是 v3 的事,不该由迁移门禁背锅),不通过即闸门 FAIL。

**双向验证**:正向全绿 exit 0;人为把 `awardie_awards` 一行改成 `tenant_id=0`
→ 精确报出并 exit 1。

### 🟡 Medium — `v3_cutover_rehearsal.py` 用 `shell=True` 拼口令与 SQL

`run(f'"{MYSQL_CLI}" ... -p"{password}" -e "{grant_sql}"')`:口令里出现 `"`/`$`/
反引号/`;` 就会破,极端情况被当成命令执行。已改为**参数列表 + stdin 喂 SQL**,
与 `v3_apply_missing_columns.py` 统一。演练重跑通过。
