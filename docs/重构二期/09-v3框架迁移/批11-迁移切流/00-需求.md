# 批11-迁移切流 00-需求

> 2026-09-26 | 分支 refactor/v3-yudao-migration | 上一批 daa613d2→e3d93475(批10)
> 定位:路线 12 批的**最后一步**——把 v2 真实数据迁进 v3,并把服务切到 v3。

## 一、问题陈述

批0-10 建完了 v3 的全部能力:底座、用户与角色域、基础数据域、成果提交与文件域、审核流、
成果库、模板与 AI 抽取、大创与导入、统计导出日志,以及批10 的前端壳(九管理页 + 教师两页 +
学生门户)。**但 v3 库里没有真实业务数据**——批2/批3 只迁了用户(1834)与基础数据(竞赛 218 /
实验室 5),成果域是空的。

用户现在还在用 v2(Flask + PG)。切流要解决的是:把 v2 的 1 万行真实业务数据搬进 v3,
验证搬对了、搬全了,然后把流量切过去。

## 二、范围

### 在范围内

- 成果域全量 ETL:awards / pending / 获奖三类关联 / 大创 / 软著 / 其他文件 / 模板 /
  实验室附件 / 两类审核留痕;
- 切流前置的 schema 补齐(列差 + 表差);
- 三层对账(行数 / 主键集合 / 关键字段内容哈希);
- 全新库切流演练(证明流程能从零跑通);
- 回滚方案与风险清单。

### 明确不在范围内

- **不停机切换的灰度/双写**(v2 与 v3 同时对外提供服务):本项目是校内单点系统,
  切流窗口内停机可接受,双跑的复杂度与收益不匹配;
- **文件二进制迁移**(证书图等):v2 的 `file_path` 是本机绝对路径
  (`D:\code\教学工具\...`),v3 走内容寻址存储(`files/v3/<sha16>.<ext>`)。
  存量文件的物理搬运单独立项,本批只保证**路径字段**迁到位;
- 批9 的三条前置债中与统计口径相关的部分(物化补写 year/laboratory_id)——那是 v3
  运行时的问题,不是存量数据的问题。

## 三、用户故事

1. As 运维, I want 切流前知道**两库哪些列/表对不上**, so that 我不会在写数据那一刻
   才发现字段没了。
2. As 运维, I want 迁移能**重复执行**而不产生重复数据, so that 中途失败可以直接重跑。
3. As 运维, I want 迁移后能**独立核验**数据搬对了(不只是脚本自己说成功), so that
   我敢开切流闸门。
4. As 运维, I want 能在**一次性演练库**上把全流程跑一遍, so that 真实库上不再试错。
5. As 运维, I want 明确的**回滚路径**, so that 切流后发现问题时能退回去。

## 五、验收标准

| 项 | 判据 |
|---|---|
| A1 schema 补齐 | `--check` 模式报「列与表都已就位」 |
| A2 ETL 幂等 | 连跑两次,第二次不产生重复行 |
| A3 对账三层 | 16 张表:行数、id 集合(源有目标无=0)、关键字段内容哈希全一致 |

| A5 CI 绿 | 推后 `ci-v3` 两 job success |
| A6 闸门 | **实际切流由用户拍板**,不自动执行 |
