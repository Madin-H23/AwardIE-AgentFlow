### 已实证排除的高危项(避免后续重复排查)

- **XSS 干净**:36 个文件内 `v-html` **0 次**;`innerHTML`/`eval`/`new Function`/`document.write`
  全 0。`achievementData`、`review_comment`、`ocrText`、`changeDetail` 四条**用户可控文本**路径
  全部走 `{{ }}` 插值(编译为 `textContent`,自动转义)。
- **凭据干净且置空彻底**:`.env`/`.env.local` **未被 git 跟踪**(根 `.gitignore:21,23` 命中);
  `VITE_APP_BAIDU_CODE` 置空后 `plugins/tongji/index.ts:9,19` 的 `if (!HM_ID) return` 自守卫成立;
  `VITE_BAIDU_MAP_KEY` 唯一读取点 `components/Map` 的 `MapDialog` 全仓零引用,不进构建。
- **上传边界完整**:`AwardieFileStorage` = 扩展名白名单 → 10MB → 魔术字节 → sha256 内容寻址 →
  `resolve().normalize()`,文件名无法构造路径;前端 `accept` 与后端白名单完全一致。
- **下载无 token 拼接**:全部走 axios 包装器的 `Authorization` 头,无 URL 带 token。
- **动态路由 component 注入不可利用**:`modules` 是 `import.meta.glob` 编译期展开的**静态对象字面量**,
  `modules[key]` 是对固定 map 的**键查找**;菜单表里的 `component` 字符串只能做子串筛选,
  无法引入新路径。且菜单表只有 `super_admin` 能写。

### 🟠 Medium 1(已修)— `/teacher-pending-list` 缺 staff 校验,任一学生可枚举全租户待审队列

`PendingAchievementController.java:235`。该端点只有 `@PreAuthorize(query)`,方法体无 `hasStaffRole`;
而同文件三个兄弟端点(`:152` download、`:219` timeline、`:270` ai-suggest)**都有**。

**可利用路径**:`business:pending-achievement:query` 就是菜单 3032,`awardie-user-domain.sql:45,47`
把它同时授予了学生角色——学生的 `/my-page` 用同一权限点,无法从权限上剥离。任一学生账号
`GET /business/pending-achievements/teacher-pending-list` 即拿到全租户每条待审成果的
`submitterId` / **`submitterName`** / 提交时间。(SQL 带 `tenant_id = ?`,不跨租户。)

**成因**:该端点由**批5** 引入(批10 只移除了学生的 3034)。批10 给 `review` 补 `hasStaffRole` 时
把 download/timeline/ai-suggest 称作"三个兄弟端点",**恰好漏掉了第四个**。

**修法**:方法体首行补 `if (!hasStaffRole(getLoginUser())) throw exception(PENDING_ACHIEVEMENT_FORBIDDEN);`

**运行时实证**(无误伤):

```
学生 → teacher-pending-list : {"code":1003002004,"msg":"无权操作他人的提交"}   ← 已拦
教师 → teacher-pending-list : {"code":0,"data":[{...}]}                        ← 仍可用
学生 → my-page             : {"code":0,"data":{"total":539,...}}                ← 未误伤
```
