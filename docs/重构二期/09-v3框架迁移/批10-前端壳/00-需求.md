批1-9 后端就绪(101 例测试、CI 绿),但**用户在浏览器里看不到任何东西**——v3 没有前端。批10 交付第一个能用的界面。

## 二、事实调查(facts)

### F1 v3 前端现状:只有一个 README 占位

`awardie-v3/yudao-ui/yudao-ui-admin-vue3/` 开批前只有 `README.md`,指向 Gitee/GitHub 上游 `yudaocode/yudao-ui-admin-vue3`。**无任何源码**。

### F2 上游 HEAD 自身构建不过(取证发现)

克隆上游 HEAD(`aab14fb0`)后直接 `pnpm build:local` **失败**:`src/views/oa/attendance/*` 三个文件 import `@/views/oa/utils/constants`,而该文件在仓库里不存在。也就是说**上游自己的 HEAD 是构建不过的半成品**。

这有三重意义:
- 我们的基线必须靠"删掉 OA 模块"绕过,而不是"照抄上游就能用";
- 说明跟随上游时,上游 HEAD 不可直接作为可信基线;
- 已在 02-实施 记录,后续同步时必须知道这一点。

### F3 芋道框架的动态路由来自后端菜单(关键机制)

`src/store/modules/permission.ts` 的 `generateRoutes()` 从**后端菜单表**读取,`src/utils/routerHelper.ts` 把菜单的 `component` 字段(如 `business/laboratory/index`)解析为 `@/views/business/laboratory/index.vue`。

**含义**:批1-9 已建的菜单 SQL(3000-3009 + 权限点)**直接就是侧边栏来源**,前端不必硬编码菜单。但前端**必须**按 component 路径提供对应的 `.vue` 文件,否则路由解析失败。

### F5 v2 前端的真实构成(对照物)

`awardie-frontend`(v2 自建,Vue3 + EP):
- **39 个 .vue 页面**,`src/` 体积 674K;
- 业务页齐全:管理端(成果/竞赛/实验室/模板/大创/日志/分析/导出/导入)、学生端(提交/仪表板/成果)、教师端(审核/成果/导出/看板);
- **但缺一整块能力**:无用户管理、角色权限管理、菜单管理、字典配置——而 v3 后端已迁了完整的芋道 system 模块(用户/角色/菜单/字典/租户);

### F6 v2 的 UX-1 交互投入(记忆实证,五批)

v2 前端在重构二期做过 UX-1 五批打磨,产物:

- `PageHeader` / `TableSkeleton` 组件

### F7 上游框架的真实规模与坑

- 上游 `src/` 有 24 个业务模块(ai/bpm/crm/erp/fms/hrm/im/infra/iot/mall/member/mes/mp/oa/pay/pms/report/system/wms),保留 `infra`/`system` 后剩 119 个 .vue;
- 依赖:60 个 dependencies + 45 个 devDependencies,`node_modules` 约 1.1G;
- 构建:`pnpm build:local`(vite 8.1.4),基线构建 26s,产物 30M;
- **中文路径不阻塞构建**——早期怀疑是 rolldown 对非 ASCII 路径敏感,实测 ASCII 路径下同样失败(唯一障碍是 OA 缺文件),排除该假设;
- 请求前缀已配好:`.env.local` 的 `VITE_API_URL=/admin-api`,`src/config/axios` 自动拼接;
- `request.download()` 存在且会读错误响应(**优于 v2 的裸 `<a>` 直链**,v2 下载失败时会静默下载错误响应)。

## 三、方案推演与定稿(用户 2026-09-26 拍板)

用户明确:**仓库体积与首次工作量不是约束,尺子是"使用中的效果"和"后续维护难度"**。

据此评估了七个方案:

| 方案 | 仓库增量 | 上游同步负担 | 使用效果 | 维护难度 | 结论 |
|---|---|---|---|---|---|
| 一 芋道全量入库 | +20M | 每次升级重放改动 | 通用后台交互 | 中(工作集中) | 采纳(混合方案的基座) |
| 二 submodule | +0 | 换号+重放,指向他人仓库 | 同上 | 中高(心智负担) | 否 |
| 三 独立 fork | +0 | 标准 merge | 同上 | 中(多仓库) | 否 |
| 四 自建极简壳 | +1M | **无** | 自定 | **高**(基础组件全重写) | 否 |
| 五 芋道+静态菜单 | +20M | 同方案一 | 同上 | 中 | 否(违背动态路由设计) | 
| 六 纯复用 v2 前端 | +5M | **无** | **v2 调校过的交互** | 中(带 v2 技术债) | 部分采纳(业务页与 UX 移植) |
| 七 芋道框架+只摘 Layout | +3M | 局部同步 | 同上 | 中 | 否(与一重复) |

### 定稿:混合方案

```
基础设施层(用芋道框架,不动)
  ├─ src/layout        布局/侧边栏/头部
  ├─ src/components    表格/弹窗/分页/上传等通用组件
  ├─ src/config        axios 封装(含 download 会读错误响应)
  ├─ src/store         Pinia(含 permission 动态路由)
  ├─ src/router        路由(含 remaining 兜底路由)
  └─ src/views/{infra,system}   119 个系统管理页(用户/角色/菜单/字典/租户)

业务层(按 v3 API 重写,自主维护)
  ├─ src/api/business/**       已完成(3 个文件,路径已与后端逐条核对)
  └─ src/views/business/**     9 个页面(菜单 component 路径决定)

交互层(从 v2 移植,作为自定义组件)
  ├─ PageHeader        页头(标题+操作区)
  ├─ TableSkeleton    表格骨架屏
  ├─ 150ms 路由过渡    挂到 router 全局
  ├─ 筛选折叠          列表页筛选区可收起
  └─ --tag-* 徽章色板  CSS 变量
```

**这个切法的维护边界(最关键)**:
- 跟随上游时**只需同步** `src/layout`、`src/components`、`src/config`、`src/store`、`src/router`;
- `src/views/business`、`src/api/business`、`src/views/business/components` **完全自主**,上游升级不影响;
- 交互层是自定义组件,上游不覆盖。

## 四、需求条目

### R1 基座就位(已完成部分,需确认落盘)

- 上游源码同步入库(基于 `yudaocode/yudao-ui-admin-vue3@aab14fb0`),README 标注同步点与改造摘要;
- 删除 24 个示例业务模块(views + api),只留 `infra`/`system`;
- 清理删除模块带来的悬空引用(`remaining.ts` 业务路由段、`main.ts` 的 BPM wangEditor 插件、`ToolHeader` 的财务科目切换器、`AppLinkSelectDialog` 的商品分类选择器、DiyEditor 的 6 个商城营销卡片);
- 修复 `remaining.ts` 的 `export default`(截断时被砍);
- **构建全绿**(基线 4.99s)。

### R2 API 层

- `src/api/business/` 三文件已建(基础 CRUD/成果流/统计导出日志),路径已与后端 Controller 逐条核对;
- 补齐剩余端点(学生端、模板 AI 三端点、大创导入、校准)。

### R3 九个管理页面

按 F4 表格建 9 个页面,每个都要:列表/分页、增删改(按权限)、空态、加载态、错误提示。
优先级:先做数据只读的(统计/日志/导出),再做 CRUD 的(实验室/竞赛),最后做复杂的(模板 AI/大创导入/成果库编辑)。

### R3.5 教师端两页(grilling P4 新增)

- **教师待审**:待审列表 + 审核详情(时间线 + AI 建议),对齐批5 审核端点;
- **教师指导成果**:教师名下被指导的获奖列表;
- 新增两菜单(教师待审 / 教师指导成果),**走动态路由机制**(不是静态路由特例),授权 100 admin + 101 teacher;
- 教师角色 101 已有 `pending-achievement:query` / `review` 权限点,加菜单即生效;
- 理由:教师是审核流执行者,批5 整个审核流建立在教师初审上,无入口即业务断链。

### R4 学生端三场景(用户 2026-09-25 拍板的硬要求)

- **提交成果**:五类选择 + 动态表单 + 文件上传(对齐批4 提交端点);
- **查审核进度**:我的提交列表 + 状态 + 时间线;
- **证书查看**:已入库成果的证书图片查看;
- **必须在网页端可用**,移动端浏览器可直接完成以上全部动作。

### R5 移动端适配

- 侧边栏在小屏折叠为抽屉;
- 表格在小屏转卡片式(或横向滚动 + 关键列优先);
- 表单弹窗在小屏全屏;
- 触控目标不小于 44x44;
- 学生端三个场景在 375px 宽度下完整可用(这是硬验收)。

### R6 UX-1 交互移植

从 v2 移植:PageHeader、TableSkeleton、150ms 路由过渡、筛选折叠、徽章色板。

### R7.5 运行时验证(grilling P6,不可省)

构建只验静态 import,查不出动态路由与运行时解析;学生端白屏是灾难性的。必须实际启动后端+前端,逐项验证:
登录→侧边栏渲染(验动态路由,配错会白屏)→九个管理菜单逐个点→教师两菜单→学生端三场景→系统管理几页(用户/角色/菜单/字典)→**页面装修器能打开**(DiyEditor 我们删过 6 个商城卡片)→375px 与 430px 双宽度截图。

### R7 质量门禁(前端没有后端那套现成机制,需从零建)

- `pnpm build:local` 必须绿(唯一硬门禁);
- `pnpm ts:check` 类型检查(上游自带 `vue-tsc`);
- `pnpm lint:eslint` + `lint:style`(上游自带 eslint/stylelint 配置);
- 引入 E2E(建议 Playwright,覆盖登录 + 九个管理页 + 学生端三场景)。

### R8 联调与截图

- 启动后端(48080)+ 前端 dev server,走通登录 → 各页面;
- 截图入档(九管理页 + 学生端三场景 + 移动端视图);
- 记入批10 文档。
