## 二、本批最重要的取证发现

### 上游 HEAD 自身构建不过(影响基线可信度)

克隆 `yudaocode/yudao-ui-admin-vue3` HEAD(`aab14fb0`)后直接 `pnpm build:local` **失败**:

```
src/views/oa/attendance/list/OaAttendanceForm.vue:53
  import { OA_ATTENDANCE_STATUS, OA_ATTENDANCE_TYPE } from '@/views/oa/utils/constants'
                                       ╰──── 系统找不到指定的路径
```

`src/views/oa/utils/` 目录**在仓库里不存在**。三个 oa/attendance 文件都引用它。

**含义**:上游自己的 HEAD 是构建不过的半产物。我们按"同步上游就能用"的假设拉下来会直接撞墙——**靠删掉 OA 模块绕过了,但这件事必须记录**,否则下次同步会以为是自己的问题。

### 排除了一个错误假设:中文路径

初遇构建报错(rolldown 报的 "系统找不到指定的路径")时,怀疑是 `D:\Develop\AI 应用开发\...` 的中文路径对 Rust 原生模块不友好(批7 的 protoc 踩过同类坑)。

**实测排除**:把工程复制到纯 ASCII 路径 `C:\Users\28951\AppData\Local\Temp\asciitest` 重装依赖再构建,**报同样的错**。所以中文路径不是根因,唯一障碍就是 OA 缺文件。

**方法论**:与批7 的 protoc 经验不同——那次中文路径确实是根因(需复制到 ASCII 短路径编译),这次不是。**相似症状不同根因,必须实测对照才能下结论**。

## 四、T02/T03 已完成部分的两个实测坑

### 4.1 API 路径不能凭记忆写(踩了两次)

初稿凭记忆写的路径,与后端 Controller 逐条核对后发现两处错:

| 我写的 | 实际 | 教训 |
|---|---|---|
| `GET /pending-achievements/get?id=` | **没有 get 端点**,只有 `my-page`/`download`/`{id}/review`/`{id}/timeline`/`{id}/ai-suggest` | 枚举/详情类端点最容易记错 |
| `POST /business/templates`(根路径) | `POST /business/templates/create` | 创建端点命名不统一(有的是根路径,有的带 /create) |

**已落进 ticket 02 的验收项**:所有路径必须与 Controller 逐条核对。

### 4.2 框架的 download 工具没有 CSV 方法

`src/utils/download.ts` 的默认导出对象只有 `excel/word/zip/html` 四个方法,**没有 csv**。而批9 的导出端点同时提供 CSV 与 XLSX。

**处置**:`export/index.vue` 里自建 `download0(blob, fileName, mimeType)` 走原生 blob 下载处理 CSV,XLSX 用框架的 `download.excel`。

**顺带的正确性收益**:批9 修好了服务端的行数上限报错(`1003009000`),前端用 `request.download()` 能读到这个错误并弹提示——v2 的裸 `<a>` 直链在这种情况下会把错误响应体当文件下载下来。
