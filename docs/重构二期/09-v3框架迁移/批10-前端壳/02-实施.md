## 一、本批最重要的一件事:P6 运行时验证抓到了 6 个构建永远查不出的缺陷

前端不像后端有单测兜底。`build` 绿只证明静态 import 能解析,**动态路由、菜单
component 解析、权限下发、env 注入这些都在运行时**。P6 要求实际启动逐项验证,
这次验证抓到的每一个都是构建绿灯时看不见的:

| # | 缺陷 | 构建能不能发现 | 怎么抓到的 |
|---|---|---|---|
| 1 | `export/index.vue` 写了缺 `@/` 前缀的 `useMessage` import | **能** | T01 复跑 build 直接红 |
| 2 | 删 24 模块时漏了 `bpmnProcessDesigner`/`SimpleProcessDesignerV2`/`store/modules/{bpm,mall}`(104 文件) | 否 | `ts:check` 报 `@/api/bpm/*` 找不到 |
| 3 | `useMessage` 由 unplugin-auto-import 注入,框架页一律不写 import | 否 | 读框架源码对照 |
| 4 | **登录页 `loading.value.close()` 在 `finally` 里,但 `loading` 只在登录成功后赋值** | 否 | 浏览器实测登录,TypeError |
| 5 | **`router/modules/remaining.ts` 写 `@/views/Home/Index.vue`(大写 I),实际文件 `index.vue`** | 否(Windows 大小写不敏感) | `ts:check` 清缓存后报 TS1261 |
| 6 | **392 个菜单里 335 个 component 指向已删的 .vue,点进去必白屏** | 否 | 管理员登录后侧边栏塞满死目录 |

第 4 条值得展开:`LoginForm.vue` 的 `handleLogin` 在 `try` 成功后才给 `loading`
赋值,`finally` 里无条件 `loading.value.close()`。登录一旦失败(任何 `return` 或
异常),`loading.value` 是 `undefined` → TypeError **把真实错误吞掉**。第一次实测
只看到 `Cannot read properties of undefined (reading 'close')`,看不到后端到底
说了什么。

第 5 条是 **Linux-only 缺陷**:Windows 文件系统大小写不敏感,本地跑一百遍都正常,
换 Linux CI 就解析失败。为此加了独立门禁 `scripts/v3_check_import_case.py`。

## 二、跨批次越权修复(批4 授权 + 批5 端点)

**发现**:学生角色 102 被授了 `business:pending-achievement:review`(菜单 3034)。
SQL 注释写「三个操作权限点必须给」,实际给了四个。而 `/{id}/review` 端点只有
`@PreAuthorize` 一道门,**没有** `hasStaffRole` 兜底——它的三个兄弟端点
`/download`、`/{id}/timeline`、`/{id}/ai-suggest` 都有 `owner || staff` 校验,唯独审核没有。

**后果**:任一学生可 POST 审核任意待审成果,`approve` 还会触发物化写入成果库。
库内实测确认该授权真实存在。批10 是学生第一次真正登录的时点,不修就带着进批11。

**处置**(两处):
- `awardie-user-domain.sql`:学生只给 3031/3032/3033,去掉 3034;教师保留四个;
- `PendingAchievementController.review`:补 `hasStaffRole` 校验,抛
  `PENDING_ACHIEVEMENT_FORBIDDEN`,与三个兄弟端点一致。

**运行时实证**:学生 token 调审核端点 → `{"code":403,"msg":"没有该操作权限"}`。

### 顺带修的:`system_role_menu` 授权不幂等

`system_role_menu` 主键是自增 `id`,无 `(role_id, menu_id)` 唯一约束,所以
`INSERT IGNORE` **永远不会去重**——实测重跑 6 次就有 6 份重复。SQL 头注释声称的
「幂等:可重复执行」对授权表不成立。改成「先 DELETE 该角色在这批菜单上的旧关联,
再 INSERT」,既幂等,又能让授权清单的**收窄**(学生去掉 3034)对已存在的库真正生效。

## 三、⚠️ 一次自造事故:在已 ETL 的 dev 库上跑了 cleanup 脚本

**我犯的错**:为了清死菜单,直接在 dev 库 `awardie_v3` 上跑了
`awardie-cleanup.sql`。该脚本的既定语义是「只保留 id=1 的最小系统集」,里面
`DELETE FROM system_users WHERE id <> 1` 把**存量用户 ETL 导入的 1834 个师生
账号全部删空**,并把 id=1 的身份改写成 admin 资料。登录随即全部失效。

**为什么没提前想到**:`awardie-cleanup.sql` 一直在 CI 建库流程里当第一步跑,
我一直把它当「建库脚本」而不是「清库脚本」,没想到它对已有 ETL 数据的库是破坏性的。

**恢复**:v2 PG(5433)还在,重跑 `scripts/etl_v2_users_to_v3.py`(幂等,按主键
upsert)→ 1834 users / 1834 profile / 1835 role_links 全部回填,约 1 分钟。

**已固化的防线**:在 `awardie-cleanup.sql` 头部加了 ⚠️ 警告块,写明
「**只允许在刚导入官方 sql、还没跑 ETL 的库上执行**」,以及已有数据时要改用
`DELETE ... WHERE created_by='etl'` 这类带条件的语句。

**教训**:CI 建库流程里的脚本不等于「可以在任何库上跑」。跑之前先问
「这个库的当前状态,和这个脚本假定的状态一致吗」。

## 四、死菜单剪枝:改用文件系统判据,不手工维护 ID 清单

死菜单的规模远超预期:392 个带 component 的菜单里 **335 个指向已删除的 .vue**。
最初想按「顶级目录」写 ID 清单,结果第一版就漏了「报表管理」(id=207,它是
**type=2 且 parent_id=0**,不是目录)。

**判据换成真实的那个问题**:菜单的 component 拼成 `<前端>/src/views/<component>.vue`,
**磁盘上有没有这个文件**。写成 `scripts/v3_prune_dead_menus.py`:

- A 轮:component 非空但文件不存在 → 死菜单;
- B 轮:走完 A 轮后,component 为空且**无任何存活子菜单**的 → 空壳,逐层向上剥;
- 白名单 `business/` `portal/`(我们的业务层)任何情况下不剪;
- `--check` 只检查不落盘,退出码 1,可挂 CI;重跑幂等(实测「文件缺失 0 个」)。

剪完后管理员侧边栏只剩:系统管理 / 基础设施 / AwardIE 业务管理(9) /
AwardIE 教师工作台(2) / AwardIE 学生门户(3)。

## 五、框架层的三处改动(冻结框架的逃生口)

P1 冻结的判准是「批11 就是切流,切流前不应有例行上游同步」,但 spec 也写明
**冻结不等于不能动,遇框架 bug 仍需能改,改了算脱离上游**。本批动了三处,都是
能力缺口而非风格偏好:

| 文件 | 改动 | 为什么必须动 |
|---|---|---|
| `utils/routerHelper.ts` | 顶级目录若在菜单里填了 `component`,就用它当壳而不是后台 `Layout` | 框架对顶级目录**硬编码** `Layout`,学生门户无法有独立壳;P4 又要求走菜单不走静态路由。存量菜单 `component` 一律为 `''`,对它们是 no-op |
| `router/modules/remaining.ts` | `Home/Index.vue` → `Home/index.vue` | Linux CI 解析失败(TS1261) |
| `views/Home/index.vue` | 换掉框架演示首页(假数据 + ruoyi-vue-pro 的 GitHub 链接) | 学生教师一登录就看到上游广告,必须处理 |

`views/business/components/useBlobUrl.ts` 是新增的业务层工具:鉴权图片必须
`request.download` 取 Blob → `createObjectURL` → 卸载时 revoke。裸 `<img src>`
必然 401(鉴权走 `Authorization` 头),且存储根 `files/v3` 没有任何静态资源映射。

## 六、API 层的几个硬事实(写页面时踩出来的)

1. **模板样本图与成果证书图都不能直接 `<img src>`**——鉴权走头,存储根无静态映射。
   待审成果的 `/download` 还固定 `Content-Disposition: attachment`。唯一可行路径是 blob。
2. **`/business/pending-achievements/my-page` 被服务端强制按当前用户过滤**
   (`submitterId` 被覆盖)。管理员要看待审队列必须用 `teacher-pending-list`,
   它返回全量 List(无分页、无类型筛选)且行是 `jdbc.queryForList` 直出,
   **驼峰键名即契约**。
3. **模板 AI 三端点无 VO**,键名只在 `TemplateAiService` 里:
   `test` / `extract-for-create` → `{mode, dataJson, ocrText, disclaimer}`;
   `generate-prompt` → `{mode, prompt, disclaimer}`。`dataJson` 是 **JSON 字符串**,
   内层键无契约。无降级 Map——Worker 不可用时直接抛 4003。
4. **权限串不能从 URL 段推**:`/business/innovations` 的权限是 `business:innovation:*`(单数),
   `/business/pending-achievements` 是 `business:pending-achievement:*`。
5. **`export-excel` 不能传分页参数**:后端在 `@Valid` 之后才把 `pageSize` 置 -1,
   前端传 `pageSize=-1` 会被 `@Min(1)` 拦成 400。
6. **FormData 不需要传 `headersType`**。芋道的 axios 封装**总是**强设
   `Content-Type: application/json`,但 axios 1.16.0 的 `resolveConfig.js:72-75`
   在标准浏览器环境会 `headers.setContentType(undefined)` 让浏览器自己带 boundary。
   (查源码实证,不是凭记忆——凭记忆会误判成「必须传」。)
7. **keep-alive 缓存键是菜单的 `component_name`**,不是路径。页面
   `defineOptions({name})` 必须与之逐字一致,否则缓存静默失效(不报错,只是不缓存)。
   接手时 `stats/index.vue` 写的是 `StatsIndex` 而菜单是 `Stats`,已对齐九个页面。

  等于把本应用的访问量上报到**上游作者的百度统计账号**。该插件有
