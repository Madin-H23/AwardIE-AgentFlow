## 二、偏差与处置

1. **幂等判据换掉(继承批5 立项 F3)**:v2 靠"审计有 action_type=8"判物化幂等,但 v2 存量有 **164 条 archived 无该留痕**——判据在存量上不可靠。v3 改**查业务事实**(awards/other 按 file_hash;patent/software 按唯一键或 certificate_file),测试实证重复审批后成果表仍 1 行;
2. **批3 测试的探针表地雷(跨批污染)**:批3 时 `awardie_awards`/`awardie_patents` 不存在,`ReferenceCheckTest` 把它们当**临时探针表 CREATE/DROP**;批5 建了真表后,全量测试里该测试的 teardown **把真表删了**(`DELETE FROM awardie_awards → bad SQL grammar`,14 例炸)。处置=按批3 spec 预案改为**直接向真表插引用行**(teardown 只 DELETE 行不 DROP 表),"表不存在"路径改为组件级直测(传一个不存在的表名);同时真表 NOT NULL 列(patent_name 等)在测试里补最小值;
3. **awards 表漏 laboratory_id(自查发现)**:`AchievementReferenceChecker.LABORATORY_REFERENCES` 清单含 `awardie_awards.laboratory_id`,但批5 建的 awards 表漏了该列——测试插 laboratory_id 时炸"Unknown column"。v2 的 awards 有该列(194 条成果挂实验室),故补列(DDL + 两库 ALTER);
4. **操作人账号取法(token 认证坑)**:初版用 `getAuthentication().getName()` 取账号——芋道 token 认证下该方法返回的是 **token 字符串本身**(数十位),写进 operator_code 触发 Data truncation(500)。处置=按用户 id 查用户表取 username + nickname,查不到时留空不阻断审核;
5. **SQL 注释分号坑**:`run_awardie_sql.py` 按分号切语句,新增列注释里含 `;` 会把注释截断导致语法错。处置=注释内禁用分号(改用逗号)——脚本纪律补一条;
6. **p3c 形态调整**:`"grpc"` 魔法值提为 `MODE_GRPC` 常量(1 处违例→0)。
