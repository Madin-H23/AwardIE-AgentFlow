## 三、需求条目

### R1 审核动作与状态机

- 教师初审 + admin 复核共用一套 `ReviewService`:approve(→archived)/reject(→rejected);
- **守卫**:非 pending 状态再审 → 业务错误码(1003004002"状态机非法流转");
- 驳回必填原因(BR-5),空原因 → 错误码;
- 审核人/时间/意见落 pending 的 reviewer_id/review_time/review_comment(批4 已预留)。

### R2 审计留痕与时间线

- 建 `awardie_achievement_audit_log` 表(对照 v2 achievement_audit_log 18 列,actor 取芋道 user);
- 四个动作码:提交 1(批4 补写)、通过 6、驳回 7、物化 8;change_detail 存 JSON(message/comment);
- 时间线端点:按 achievement_id 升序返回留痕(教师/管理员/本人可见)。

### R3 物化入库(批5 核心,决策 D1:award 即时物化、四类分发)

- approve 时按类型物化:award→awards、patent→patents、software→software_copyrights、other→other_files;**innovation 不物化**(v1 语义);
- 竞赛按名匹配,缺失自动建(is_auto_added=true,与 v2 同);
- 空串转 NULL 兜底(UNIQUE 约束防撞);
- **幂等改用"成果表按 file_hash 查重"而非审计留痕**(F3 证明 v2 靠 action_type=8 判幂等在存量上不可靠;v3 幂等查业务事实);
- 成果五表本体属批6,本批**只建物化所需的最简表**(见决策 D2)。

### R4 AI 建议(决策 D3:fake/grpc 双模式,不阻塞审核)

- 端点 `GET /business/pending-achievements/{id}/ai-suggest`(SSE 或一次性返回,见 spec);
- fake 模式:确定性建议(开发/CI 无 Worker 时);
- grpc 模式:调 Worker `ExtractAndReview`;**Worker 不可用 → 降级 4003 + 人工审提示,不抛错**;
- 响应带 BR-2 免责声明"AI 建议仅辅助参考"。

### R5 端点与权限

- 教师端点挂 `business:pending-achievement:*`,新增 review 权限点;admin 复用同款权限点(芋道无"仅admin"粒度,用角色判定复核);
- 待审列表 join 提交者姓名(F6 的键名契约教训:Map 端点键名即契约)。

## 四、决策(按推荐案落地,待用户复核)

- **D1 物化时机**:approve 即时物化(与 v2 同,不等批6)——待复核;
- **D2 成果表最小集**:本批建 awards/patents/software_copyrights/other_files **四张最小表**(物化所需列),innovation 不建(不物化);批6 在此基础上补全编辑链字段——待复核。理由:物化是审核闭环的终点,不建表则 approve 无意义;四张表只建 v2 物化用到的列,批6 扩展;
- **D3 AI 建议模式**:fake/grpc 双模式,默认 fake(Worker 未常驻),不阻塞审核——待复核;
- **D4 时间线可见性**:本人/教师/admin 可见(与 v2 一致)——待复核。

## 六、总验收

1. 状态机:approve→archived、reject→rejected;非 pending 再审拒;驳回空原因拒;
