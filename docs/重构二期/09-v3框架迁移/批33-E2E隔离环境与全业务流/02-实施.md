## ★ D-31:本批抓出的真实生产缺陷(已修)

**审核通过后成果库查不到**。三层取证:
1. `insertByMap` 只写业务列不写框架列 → 运行时物化行 `tenant_id=0`(列默认值)
2. 成果库页按当前租户 1 过滤 → 物化行不可见
3. **真库存量 197 行是 ETL 写的 1,仅运行时路径出现** → 批19 人工 GUI 走查与后端集成测试(都只断数量/状态)双双漏过

修:`ReviewService.insertByMap` 统一补 `tenant_id=当前租户`(五张物化表均有该列,实证);
`ReviewFlowTest` 加租户断言锁回归;API 级实证物化行 tenant_id=1 且 vault 可见。

## 排障实录(13 轮迭代,四个真教训)

1. **列表列不含业务数据** → 不能 `hasText` 找行(achievement_data 不上列);E2E 库数据干净,取首行+状态徽章断言
2. **待审页返回全部三态** → 审核后行不消失只变状态,断言该看徽章("已入库"/"已驳回")
3. **el-checkbox 原生 input 视觉隐藏**,点 inner/根/dispatch 三种手段全不触发 v-model;真相=**识别成功默认已勾选**(批18 设计),我的勾选操作反而在取消——五方式对照实证钉死
4. **残留 token 让 `/login` 被守卫即刻弹回首页**,fill 的元素随导航销毁 60s 超时;治法=`login()` 自身先清 storage 从干净态开始(治整类竞态,非单点补丁)
