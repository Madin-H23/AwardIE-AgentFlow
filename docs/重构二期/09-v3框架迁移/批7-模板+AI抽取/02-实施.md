## 三、本批修复的 v2 缺陷(明确不是"照搬")

1. **编辑可绕过唯一性**:v2 的 `default_fields` 整体可写,改它就能改掉 `granted_role`,使"同竞赛同角色一个模板"失效。v3 把角色提为独立列且编辑白名单不含它,并额外剔除 `defaultFields.granted_role` 保留键。
2. **前后端 JSON 契约错位**:v2 后端收 `List<String> keywords` 而前端发 JSON 编码后的字符串。v3 出入参统一为结构化对象/数组。
3. **模板无法删除**:v2 无删除端点(且无逻辑删除列)。v3 补逻辑删除端点 + 样本图回收。
4. **孤儿文件**:批4 挂账,本批清偿(去重前置 + 事务回滚回收)。
5. **AI 建议越权读他人材料**:H1,已修。
6. **损坏数据失败开放**:validation_result 损坏时给 pass、JSON 序列化失败静默写 null,均已改为显式失败。

## 四、与 v2 的语义差(有意保留)

1. gRPC 模式配置项从 `ai.worker.mode`/`ai.review.mode` 合并为单一 `awardie.ai.worker.mode`;
2. AI 建议对非 pending 状态返回"已审结"而非重复计算;

4. Worker 传输异常统一映射 4003(v2 同);业务码原样透传(v2 同);
5. 样本图仍允许 pdf(沿三校验,v2 等价),但 Worker 侧对 PDF 抽取**未验证**,标注待验。

## 七、推前 CI 复刻验证抓出的三个真缺陷(第二次验证有效)

按批4/批6 纪律,推之前**本地复刻 CI 建库**(全新 `awardie_v3_test` + CI 同款六脚本顺序 + `utf8mb4_bin` collation)再跑全量——首轮即 3 例失败,全是真缺陷:

1. **测试清理用逻辑删除,行永久残留**:`OrphanFileCompensationTest` 的 `pendingMapper.delete(null)` 是 MyBatis-Plus 逻辑删除,行以 `deleted=1` 留在库里。后续用例里"取第一条待审行"会拿到历史行,断言落空。**修**:清理改物理 `DELETE`,并在 `@BeforeEach` 与 `@AfterEach` 双清(BeforeEach 也清模板表——共享引用用例会往模板表插行);
2. **断言取到别人的文件**:内容寻址下同字节落同一路径,`filesOnDisk().get(0)` 断言的是列表首项而非本用例的文件。**修**:按本次提交的 id 精确取 `file_path`,并给该类换独占字节夹具(其它测试类造的行不该让本例的"无引用应回收"失效);
3. **模板域测试未清待审表**:`TemplateDomainTest` 造"共享引用行"验引用保护,`@AfterEach` 却没清待审表,残留会让后续用例的样本图被判为"仍被引用"而**正确地不删**——代码没错,测试互相污染。**修**:清理纳入待审表。

**这三条都是"代码正确、测试自欺"的类型**:共享数据库 + 逻辑删除 + 内容寻址三者叠加,让断言失去意义。教训:**凡是断言"某文件应不存在/应存在"的用例,必须按本次操作的主键精确定位,不能用列表首项**。

**方法论确认**:批6 立下的"推前复刻 CI 建库"纪律第二次生效,且这次抓到的不是环境差异而是**测试设计缺陷**——本地旧库跑不出来,只有全新库 + 干净起点才暴露。
