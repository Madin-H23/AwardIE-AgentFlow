# 05 — 文件引用检查器 + 孤儿文件补偿(清偿批4 挂账)

**What to build:** 处置批4 挂账的"提交失败留孤儿文件"。关键约束是文件按内容哈希命名,同一内容可能被待审行(含 archived/rejected)、物化后的成果证书、其他文件、实验室附件共同引用,所以**不能无条件删**。做法:给文件存储服务补幂等删除与"删前查引用"两个能力;新增按"表名 → 路径列"配对清单驱动的引用检查器(口径与既有引用检查器完全一致:表不存在跳过、有 `deleted` 列则 `deleted=0` 才算引用、标识符正则白名单、值参数化),清单覆盖全部 8 张存路径的表(待审成果 `file_path`、实验室下载 `file_path`、实验室图片 `image_path`、成果证书 `certificate_path`、专利 `certificate_file`、软著 `certificate_file`、其他文件 `file_path`、模板 `sample_image_path`——列名不同故按表:列配对;专利/软著两列由 OCR 审查补上,初稿漏列)。提交流程改为"三校验 → 字段校验 → **算 sha256 → 去重查询** → 落盘 → 入库 → 留痕":去重前置使哈希不必落盘就知道,消灭最常见的孤儿场景;落盘后入库失败由事务回滚钩子触发"删前查引用"式回收。T03 的模板删除接同一套回收能力。已知边界:补偿本身失败会留残留文件,按可接受处理,不引入事务代理重写。

**Blocked by:** 01(表结构——引用清单含模板样本图列)

**Status:** ready-for-agent

- [ ] 重复提交**不产生新文件**(用文件系统目录清单断言,而非只看数据库)
- [ ] 落盘后入库失败 → 文件被回收
- [ ] 与另一条记录同内容时**不误删**(构造"同哈希两行"场景,回收后两行仍可读回文件)
- [ ] 引用清单 8 张表逐表可查;至少抽查待审成果、其他文件、模板三处(列名不同)
- [ ] 删除不存在的文件不抛异常(幂等)
- [ ] 模板删除走同一回收能力,且与他域同内容文件共存时保文件
- [ ] 批4 既有提交集成测试全绿(顺序调整不破坏既有行为)
