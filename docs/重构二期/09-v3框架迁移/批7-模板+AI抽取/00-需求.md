# 批7-模板+AI抽取 需求文档(00-需求)

> 2026-09-24 | 分支 refactor/v3-yudao-migration | 上一提交 50858821(批6)
> 立项依据:`00-立项.md` 第三节批7 行 = templates 域 + ExtractTemplate/GeneratePrompt RPC 对接

## 一、背景与目标

批1-6 已把系统层、用户域、基础数据域、成果提交+文件域、审核流、成果库搬上芋道底座。批7 收掉两件挂账:

1. **templates 域**(证书模板管理)在 v2 是"只有 Controller 没有 Service"的自建形态,且**没有逻辑删除、没有租户列、没有独立权限点**,是全项目离芋道规范最远的一块;
2. **gRPC stub 从未进过 v3**——批5 的 `AiReviewService` 第 55 行是硬编码降级("Worker gRPC stub 属批7"),`awardie-v3` 至今零 `io.grpc` 依赖、零 `.proto`。本批把两个 unary RPC 接到真 Python Worker,并把审核流的 grpc 分支一并激活(否则 stub 引进却只有一个消费者,等于半拉子)。

附带处置批4 挂账的**提交失败留孤儿文件**(handoff 点名的"可在本批一并处置")。

## 二、事实调查(agent 实测,facts)

### F1 v2 模板域全貌(8 端点,无分层)

| 项 | 事实 |
|---|---|
| 端点 | 列表(`AdminConsoleController`)+ 创建/详情/编辑/样本图/试测/创建前抽取/生成 prompt(`AdminTemplateDetailController`)共 8 个 |
| 分层 | **无 TemplateDO / Service / Mapper**;SQL 全写在 Controller,用 JdbcTemplate |
| 权限 | 仅 `ROLE_ADMIN` 硬判,无权限点、无菜单种子、无数字菜单编号 |
| 唯一性 | 查重是 `competition_id = ? AND default_fields->>'granted_role' = ?`;**granted_role 藏在 JSONB 里**,无 DB 唯一索引,并发可穿透 |
| 编辑 | `defaultFields` 整体可写 → 可改掉 granted_role 绕过唯一性;`keywords` 后端收 `List<String>` 而前端发 JSON 字符串(**契约 bug**) |
| 状态/软删 | **均无**;也没有删除端点 |
| 样本图 | `sample_image_path VARCHAR(500)`,存 `files/v2/<sha16>.<ext>`,物理 BYTEA 已在 V5 退役 |
| 前端 | 3 页(list/create/detail),无模板专属 api 模块;仅 admin 侧,学生/教师零入口 |
| 数据流 | **模板未被提交/审核链消费**;调 Worker 时 `template_rule_json` 恒传 `"{}"`(Worker 侧也不消费该字段) |

### F2 AI Worker 契约(package 是 `awardie.ai`,不是 `com.awardie.ai`)

- `ai_worker/protos/ai_service.proto` 共 6 个 RPC:`Extract` / `ExtractTemplate` / `GeneratePrompt` / `ExtractAndReview`(server-streaming)/ `Ask`(server-streaming)/ `Health`;
- Worker 硬编码监听 `127.0.0.1:50060` 明文,8 线程;host/port **无环境变量开关**;
- **业务错误码写在响应体的 `code` 字段里,transport status 恒 OK**(`server.py` 两个目标方法都没调 `context.abort/set_code`)。Java 侧必须双层判错:先看 `resp.getCode()`,再看有没有 `StatusRuntimeException`;只看后者会漏掉 4000/4003/4004/5xxx;
- deadline 现状(v2):ExtractTemplate 120s、GeneratePrompt 60s、ExtractAndReview/Ask 320s;
- `ExtractTemplate.template_rule_json` 当前是**预留位,Worker 不消费**,固定走默认 award prompt;
- `Health` 只验 langgraph 能否 import,**不能证明 OCR/LLM 可用**;真可用性只能靠实跑一次带图的 ExtractTemplate;
- Worker 侧**没有 mock/fake 开关**,fake 只存在于 Java 代理层;
- Python 侧 `requirements*.txt` **均未声明 grpcio/grpcio-tools/protobuf**,本机 venv 有(`grpcio 1.83.1`),README 的启动命令依赖 venv 已装——本批不修 Worker 依赖声明(范围外,标注)。

| 项 | 事实 |

### F4 批4 孤儿文件的补偿难点(决定方案的关键)

`store` 是**内容寻址**:同一 sha256 + 同扩展名落同一路径,`REPLACE_EXISTING`。所以提交失败后**不能无条件删文件**——同一内容可能已被下列行引用:其他 pending 行(含 archived/rejected)、物化后的 `awardie_awards.certificate_path`、`awardie_other_files.file_path`(该列有 UNIQUE 索引)、实验室下载/图片。误删会打断已有记录。补偿必须**先查引用再删**。

## 三、需求条目

### R1 templates 表结构(补齐芋道基础设施列)

新建 `awardie_templates`,在 v2 16 字段基础上:

- 补芋道标准列:`tenant_id`、`creator`、`create_time`、`updater`、`update_time`、`deleted`(逻辑删除);
- `competition_id` 加索引(批3 已在 `COMPETITION_REFERENCES` 里预留 `awardie_templates.competition_id`,建表即自动生效——竞赛删除保护本批首次真正激活);
- `granted_role` 提为**独立列**(v2 藏在 `default_fields` JSONB 里),唯一性语义"同竞赛+同角色"改为可索引的列比较;
- JSON 列用 MySQL `JSON` 类型(与批4/6 一致),不用 TEXT;
- 不加 `name`/`status`/`template_no`:v2 无此语义、无存量值可回填,凭空建模=静默发明业务(记为范围外)。

### R2 templates 域 CRUD(首次建立 Service 分层)

- `TemplateService` + `TemplateMapper` + `TemplateDO` + VO,按芋道分层;
- 端点(对照 v2 8 个,路由改芋道风格):
  - `GET /business/templates` 分页列表(competitionId 精确过滤 + grantedRole 精确过滤,v2 只有 competitionId;加角色过滤因它是唯一性维度);
  - `POST /business/templates` 创建(multipart:样本图 + competitionId + grantedRole + 规则字段);
  - `GET /business/templates/{id}` 详情;
  - `PUT /business/templates/{id}` 编辑;
  - `GET /business/templates/{id}/image` 样本图字节回显;
- 唯一性:"同竞赛 + 同角色 + 未删除"应用层校验,重名抛业务码(沿 v2 4009 语义,映射为芋道错误码);
- 编辑**不允许改 grantedRole**(v2 可改 → 绕过唯一性,这是缺陷不是语义,明确修掉);
- 创建前 JSON 合法性前置校验(Jackson),不让驱动层 500;
- 样本图走批4 `AwardieFileStorage`(三校验 + sha256 去重),不新建存储。

### R3 模板删除(逻辑删除 + 引用检查 + 文件补偿)

- `DELETE /business/templates/{id}` 逻辑删除;无下游业务引用(v2/v3 均无任何表引用 templates.id),故不做引用拒绝,但**删行同时删样本图物理文件**;
- 删文件前走 R5 的引用检查(样本图路径理论上可与其他域同内容共享)——这正是 F4 同一个坑,两处共用一个 checker;
- 竞赛删除保护:批3 预留的 `awardie_templates.competition_id` 引用检查本批自动激活(无需改批3 代码),需测试实证。

### R4 gRPC 对接真 Worker(两个 unary RPC + 审核流分支)

- 引入 proto 与生成物:`ai_worker/protos/ai_service.proto` 复制进 v3,**加 `java_package`/`java_outer_classname` 选项**落到 `cn.iocoder.yudao.module.business.framework.grpc.awardie.ai`(v2 生成物在 `awardie.ai` 顶层包,直接搬会破坏 v3 包规范);用本地 protoc 3.25.3 + protoc-gen-grpc-java 1.64.0 重新生成(不复制 v2 那两个文件:v2 的 OuterClass 有 15563 行且是旧包名,重生成可控);
- **`yudao-dependencies` 补 grpc 版本管理**(1.64.0)+ protobuf-java(3.25.3),business 模块加 grpc-netty-shaded/grpc-protobuf/grpc-stub;
- `AiWorkerClient`(v3 版,`cn.iocoder.yudao.module.business.framework.grpc`):单 channel + blocking stub + `usePlaintext` + keepAlive,与 v2 同范式;**懒连接**(构造不连,Worker 不在不影响启动);
- 配置参数化:`awardie.ai.worker.host/port`、`awardie.ai.worker.extract-timeout-seconds`(120)、`awardie.ai.worker.prompt-timeout-seconds`(60)、`awardie.ai.worker.review-timeout-seconds`(320);
- **模式统一**:批5 的 `ai.review.mode` 与本批 Worker 模式合并为**单一 `awardie.ai.worker.mode`**(fake/grpc,默认 fake),`AiReviewService` 改读同一项——两个配置项会分叉成一个开关;
- 模板域三端点(试测/创建前抽取/生成 prompt)在 grpc 模式下调真 Worker,fake 模式走确定性桩(v2 桩语义);
- **审核流 `AiReviewService` 的 grpc 分支接真 `ExtractAndReview`**(server-streaming,消费到 `final` 事件映射为 Suggestion),清偿批5 挂账;降级契约不变(转人工审 + 4003 + disclaimer);
- **双层判错**贯穿:响应 `code != 0` 原样透传业务码;`StatusRuntimeException` → 4003;
- Worker 不可用时**降级不崩**:模式 grpc 但通道不通 → 模板域 AI 端点返回 4003 业务错误(不是 500/挂死),审核流转人工审。

### R5 孤儿文件补偿(批4 挂账)

- `AwardieFileStorage` 补 `delete(relativePath)`(幂等:不存在不报错)与 `deleteIfUnreferenced(relativePath)`;
- 新增 `FileReferenceChecker`:清单驱动(表名 → 路径列),口径与 `AchievementReferenceChecker` 一致——表不存在跳过、有 `deleted` 列则 `deleted=0` 不阻断、标识符正则白名单、值参数化;
- 引用清单必须覆盖**全部存路径的表**:`awardie_pending_achievements.file_path`、`awardie_laboratory_downloads.file_path`、`awardie_laboratory_images.image_path`、`awardie_awards.certificate_path`、`awardie_other_files.file_path`、`awardie_templates.sample_image_path`(列名不同,故按"表:列"配对而非只按表名);
- `PendingSubmissionService.submit()` 改造:**去重查询前置到落盘之前**(sha256 可由字节直接算,不落盘也能查),消灭"重复提交留孤儿"这个最常见场景;落盘后 insert/留痕失败仍在事务内,注册 `TransactionSynchronization` 在 `afterCompletion(ROLLED_BACK)` 时删文件(删前查引用);
- 明确已知边界:**事务提交阶段的连接断/死锁导致回滚,方法内 catch 观察不到**,由 `afterCompletion` 覆盖;再窄的窗口(补偿本身失败)记为可接受残留,不引入事务代理重写。

### R6 权限与菜单

- 菜单 3005(AwardIE 证书模板管理)+ 5 权限点 3051-3055:`business:templates:query/create/update/delete/export`;
- 授权 super_admin(1)+ awardie_admin(100);`system_role_menu` INSERT **必写 `tenant_id=1`**(批6 头号缺陷);
- 样本图回显、AI 三端点归 `query`;不单独发 AI 权限点(AI 是模板编辑的辅助动作,单开权限点会让管理员配出"能配不能试"的半残态);
- 无 student/teacher 授权(v2 模板域是 admin 专属)。

### R7 测试

- `TemplateDomainTest`(集成,≥12 例)+ `FileReferenceCheckerTest`/`AwardieFileStorageTest` 扩充 + `AiWorkerClientTest`(用 gRPC in-process 或 stub 断言双层判错与降级);
- 必测:正常路径、边界(空 keywords/超长文本/非法 JSON/非法 grantedRole/不存在的 competitionId/文件失存/路径越界)、异常(重复创建/编辑不存在/删除不存在)、权限(教师与学生 403)、状态保持(逻辑删后列表不再出现但竞赛引用检查仍生效)、多来源叠加(样本图与其他域同内容时不误删);
- AI 端点测试**不得依赖真 Worker 在线**:fake 模式测桩契约,grpc 模式用不可达端口测 4003 降级。

## 四、决策(按推荐案落地,待用户复核)

| # | 决策 | 推荐案 | 理由 |
|---|---|---|---|
| D1 | granted_role 提独立列 | **提列** | v2 藏 JSONB 导致唯一性不可索引、编辑可绕过;提列后列比较可索引,且唯一性语义是 v2 明确表达的意图 |
| D2 | 模板域是否加 name/status | **都不加** | v2 无此语义、无存量值;凭空建模违反"业务语义不借债" |
| D3 | 模板删除 | **加逻辑删除端点 + 删样本图文件** | 验收指标写明"CRUD 可用";v2 无删除是能力缺口不是语义;芋道基座要求逻辑删除 |
| D4 | 编辑能否改 grantedRole | **不能** | v2 能改 = 绕过唯一性的缺陷,明确修掉并写入语义差 |
| D5 | stub 来源 | **重生成(加 java_package),不复制 v2 生成物** | v2 生成物在顶层 `awardie.ai` 包、15563 行;重生成可控且符合 v3 包规范 |
| D6 | gRPC 模式配置 | **合并为单一 `awardie.ai.worker.mode`** | 批5 已有 `ai.review.mode`,两个开关必然分叉 |
| D7 | 审核流 grpc 分支本批是否接真 | **接(ExtractAndReview)** | handoff 明写"批7 接真 Worker";stub 只服务一个端点等于半拉子;降级契约已有,风险可控 |
| D8 | 孤儿补偿形态 | **去重前置 + afterCompletion 删文件(删前查引用)** | 内容寻址下无条件删会打断已有记录;F4 已证 |
| D9 | Worker 依赖声明(requirements 缺 grpcio) | **本批不修,标注** | 属 Worker 侧资产,不在 v3 代码库;但部署前必须补(风险登记) |
| D10 | 样本图是否收紧为仅图片 | **不收紧,沿用三校验(jpg/jpeg/png/pdf)** | 等价迁移优先;Worker 侧对 PDF 抽取未验证这一事实写入文档待验 |

## 五、范围边界

**做**:R1-R7。

**不做**:
- 模板接入运行时抽取匹配链(v2 也没有,`template_rule_json` Worker 侧不消费)——挂账;
- `name`/`status`/导出/批量操作等 v2 没有的能力;
- Worker 侧代码改动(Python 依赖声明、host/port 参数化、Health 增强);
- v2→v3 的 templates 数据 ETL(属批12 统一 ETL;样本图跨库搬迁也在批12);
- 前端页面(批10 统一做,本批只保证端点契约 + swagger 可验)。
