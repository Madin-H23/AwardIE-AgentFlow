## GUI 实测(Playwright,证据 gui-test-screenshots/t18_*.png)

1. 菜单出现 → 页面渲染(菜单高亮/横幅/上传钮)
2. 上传 1 张 → 自动识别「已识别」+ 自动勾选
3. 提交 → toast「已提交 1 条」→ 行内「提交成功 #4259」
4. **抓出批17 缺陷**:提交落库 `data={}`,状态列「提交成功 #」空 id ——
   `request.upload` 返回 CommonResult 整包(interceptor 成功路径 return data,
   get/post 再取 .data,upload **不取**),调用方按解包形态取值全 undefined。
   修:parse/submitPending 统一在 API 层 `res?.data` 解包,注释写明层级差异。
5. 修复后重跑:JSON 进 textarea ✓;提交报「内容重复」= 旧行同字节还在 pending
   (去重正确行为);清旧行再提交 → 「已提交 1 条 #4260」,落库
   competition=批量导入GUI测试(行内编辑生效)、submitter=admin(1832)。
6. 测试行清理,库恢复迁移基线 45+16。

## 顺手记的坑

- **JSON 列与字符串比较删除不生效**:`DELETE ... WHERE achievement_data='{}'`
  对 JSON 列静默 0 行(类型不匹配),改主键直删。与批11「jsonb 直插 ?::jsonb」
  同族——JSON 列的比较/插入都要显式类型。
