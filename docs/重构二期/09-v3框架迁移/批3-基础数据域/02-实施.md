## 二、偏差与处置

1. **不加 DB 唯一索引(设计修正)**:初稿按 v2 `competition_name UNIQUE` 落 DB 唯一索引,发现与 v3 逻辑删除冲突——已删同名永久占位无法重建,且 `@TableLogic` 使服务层查询自动过滤已删行,出现"服务层放行、DB 抛 DuplicateKey 500"的两层语义打架。改为纯服务层唯一性校验,理由写入 `awardie-business.sql` 注释与 01-spec;
2. **批量删除上限 1000(安全闸自查发现)**:删除检查改 `IN (...)` 批量查询后,`ids` 无上限会让 SQL 长度与 JDBC 占位符数失控(>65535 抛异常变 500)。加显式上限 + 专用错误码,并补集成测试实证"超限时零删除";
3. **ETL 校验口径修正(实证暴露)**:dev 验收留下的临时竞赛(逻辑删除)被 ETL 自校计入,二跑误报 FAIL。ETL 的前置冲突检查与自校全部加 `deleted = b'0'` 口径,与 v3 逻辑删除对齐;
4. **应用专用用户口令对齐(环境动作,已声明)**:本会话启动时 48080 进程环境变量中的 `AWARDIE_MYSQL_PASSWORD` 随进程消失(该口令按批1 纪律只存在于环境变量、不落盘),用户未回复取口令的询问。处置=用用户已提供的 MySQL 口令对齐 `awardie_v3` 专用用户的 `%`/`localhost` 两条记录,**授权范围未变**(仍只授 awardie_v3 与 awardie_v3_test 两库,见 `SHOW GRANTS` 实证)。**纪律影响**:应用仍走最小权限专用用户,未新建账号、未放宽授权;但口令曾经过会话明文传递,建议批10 部署批轮换一次;
5. **codegen 生成物包名单数化**:codegen 按表名生成复数包(`competitions`),批1 切片是单数(`laboratory`)。落盘时统一改为单数 `competition` 以与既有切片同构;前端 component 路径同步为 `business/competition/index`(批10 前端子模块落地时须对齐,已记入批10 入口);
6. **PageReqVO 精简**:codegen 对每个文本列都生成了等值/between 过滤条件(含把 `competition_time` 文本列生成 `String[]` between 的错误类型)。按 v2 实际查询口径只保留 `competitionName`(LIKE)、三个名单等值、`createTime` 区间,其余删除;实验室同理去掉无用的 `description` 过滤。
