# 批31 实施记录:错误提示完善——文件缺失业务码化(以证书 500 为代表)

> 执行:2026-10-01|基线:`53b1e87b`(批30)|问题源:批30 定性登记的 portal-certs「服务器错误」toast

## 根因链(三层,逐层取证)

1. **后端**:pending download 端点对文件缺失裸抛 `NoSuchFileException` → yudao 全局兜底
   `code=500`。V1 迁入的历史行(如 id 3709)文件本就未迁(用户 2026-09-28 拍板接受)，
   属**可预期业务状态**却走了不可预期错误通道。
2. **拦截器**:`code===500` 分支弹的是**写死的 i18n 文案**(`sys.api.errMsg500`"服务器错误,
   请联系管理员!")——后端 msg 根本不透传，后端改文案对 500 无效(service.ts:191)。
3. **体验**:certificates 页 loadCert 虽有 catch+卡片降级态，但 toast 在拦截器层弹出，
   页面 catch 拦不住；页面加载即批量取证书 → N 个误导性 toast。

## 修法(前后端各一层,先例=模板侧 TEMPLATE_SAMPLE_IMAGE_LOST"存量死引用:明确报错而非 500")

| 层 | 改动 |
|---|---|
| 后端 | 新业务码 `PENDING_FILE_NOT_FOUND(1_003_003_004,"成果文件不存在或已被清理(历史迁移数据可能未包含原始文件)")`;download 端点 catch `NoSuchFileException` → 业务码。业务码走拦截器的 **msg 透传分支**(ElNotification title=msg)，文案学生可读 |
| 前端 | `ignoreMsgs` 追加该文案(与 ErrorCodeConstants 联动,注释声明)→ 文件缺失类错误**完全静默**，三处调用方(我的证书/待审管理/教师待审)各自的卡片降级态呈现——降级 UI 三处批16/28 已备齐 |
