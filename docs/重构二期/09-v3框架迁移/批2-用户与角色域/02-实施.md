## 二、偏差与关键处置

1. **v2 的 id=1 是学生不是 admin**(stock admin 占着 MySQL id=1):处置=stock admin 被 v2 用户 id=1 覆盖,v2 admin(id=1832,login_code=admin)成为唯一 'admin'(否则 selectByUsername 双行 TooManyResults);
2. **v2 admin 追加 super_admin**:芋道系统菜单挂超管角色,纯 awardie_admin 只有业务菜单管不了用户/角色——D2 映射的增量偏差,已在 SQL 注释与本文记录;
3. **scrypt 哈希 167 字符超出 system_users.password varchar(100)**:awardie-business.sql 加 `ALTER TABLE ... MODIFY password VARCHAR(255)`(ETL 前置条件,CI test 库同受益);
4. **事件监听器路线死亡**:芋道登录是服务级手工校验(AdminAuthServiceImpl.authenticate→userService.isPasswordMatch),不经 AuthenticationManager,不发布认证事件——改 AOP 切 isPasswordMatch(跨 bean 调用可被代理;自调用不可切是选它的原因);
5. **@Resource 按名注入绕过 @Primary**:芋道 `@Resource PasswordEncoder` 按名解析到上游 bean;BFPP 摘除上游定义后按名落空回退按类型命中唯一 @Primary;**BFPP 必须是非同名+待自动配置注册后摘除**(试过同名接管:自动配置在 ConfigurationClassPostProcessor 内注册,BFPP 来不及,直接 BeanDefinitionOverrideException);
6. **spring-security-core provided 不传递** + 事件类在 `...authentication.event` 子包(两处编译坑,均当时修复);
7. **本地服务必须 `mvn install` 后再 `-pl yudao-server` 启动**:否则 business 模块从 .m2 旧 jar 解析(症状=bcrypt 能登录/scrypt 不能、切面不触发、测试却全绿的诡异分裂);`-am` 会炸 spring-boot 插件前缀解析。**dev 流程固化:改 business 代码→mvn install -DskipTests→再起服务**;
8. 「学号」登录 500 为 **curl GBK 发送非法 UTF-8** 的客户端假象(服务端 HttpMessageNotReadableException→上游 handler 走 500),非服务端缺陷。
