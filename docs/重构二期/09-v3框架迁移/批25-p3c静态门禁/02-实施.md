## 设计依据:基线分析(CLI 全量扫描,2026-09-30)

| 范围 | 违规 | 处置 |
|---|---|---|
| AiServiceProto/AiServiceGrpc(gRPC 生成桩) | 457(内含 P1×136、P2×182) | pom excludes 整体排除——生成代码非人工可修 |
| business 手写 | 20,全部 P3 | 不动,进报告作存量清单 |
| server(芋道原生 main + 自有集成测试) | 27,全部 P3 | 同上 |
| StatsAndAuditTest:167 switch | **P2×1(唯一强制级)** | 规则误报豁免(见下) |

手写代码强制级(优先级 1-2)存量 = **零**——批14 起人工 p3c 对照纪律的直接成果。
因此门禁以 `failurePriority=2` 起步即全绿:**推荐级(3)只报不拦,新增强制级违例即红**,
"只对增量负责"的口径由 CI 自动执行,不再依赖人工记忆。

**唯一 P2 的处置**:p3c `SwitchStatementRule` 报"switch 块缺少 default",但该 switch 的 178 行
确有 `default ->` ——规则识别不了 Java 14 箭头语法(冒号语法时代的规则),属事实性误报。
以行级 `// NOPMD` + 原因注释精确豁免,不用文件级排除(保住该文件其余规则的覆盖)。
