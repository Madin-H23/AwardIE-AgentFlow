## 问题 2(先报,影响面最大):v2 数据 432 条 vs v1 219 条——测试数据污染

### 排查事实
- v1 真库(SQLite)现状:awards=**197**,pending=0;迁移基线 197 行一致。
- v2 库(awardie_dev@5433):**pending_achievements=858**(迁移基线+新增)、**awards=334**(=197+137 测试物化)、users=1835+(基线 1832+测试创建)。
- 08-29 以来新增 pending 813 条,按提交者分布:**student#1370(陈品天,真实账号)名下 795 条**、admin#1832 名下 18 条;按日分布 08-30:146 / 08-31:475 / 09-01:179——与本地 `mvn test` 开发节奏完全吻合(surefire 报告 17 轮)。

### 根因
**集成测试直连开发库**:`BaseIntegrationTest.seedAccounts()` 用的 login_code=212306413 与真实学生陈品天是**同一账号**(users 表按 login_code 幂等),每轮 mvn test 的 StudentSubmissionTest(11 例提交)/AdminAwardTest(审核物化 4-5 条)/InnovationImportTest/批量导入测试的写入全部落在真实数据上,且跨轮累积、从不清理。这是 v1 时期同类问题(test_main_services 污染需 restore 脚本)在 v2 的重演——**v2 缺测试库隔离,也缺数据还原脚本**。另:浏览器手动测试与 tracer E2E 的提交也直接进开发库。

### 修改方案
1. **P0 数据清理**(一次性脚本 `scripts/v2_cleanup_testdata.py`,先备份后执行):
   - 删 pending_achievements:`created_at > '2026-08-29'`(迁移基线之后全部为测试/演示产物,逐条核对 file_path 前缀 `files\v2\` 二次确认);
   - 删 awards 中测试物化行:`id > 迁移基线最大 id`(137 条)并连带清理 award_student_winners/award_supervisors/audit_log 关联;
   - 删 users 测试创建行(CRUD/巡检产生的 QATEST/巡检学生等,保留三真实账号+迁移基线);
   - 执行后核对:pending/awards 计数回到迁移基线,dashboard 数字与 v1 对齐(约 197/173 口径)。
2. **P0 测试库隔离**(根治):`application-test.yml` 指向独立库 `awardie_test`(Flyway 同构建表),BaseIntegrationTest 加 `@ActiveProfiles("test")`;CI postgres service 建双库。此后 mvn test 永不再触开发库。
3. **P1 手动测试数据出口**:E2E/tracer 与浏览器验证用的提交,提供 `--purge-e2e` 清理入口或在脚本尾部自动还原。

## 问题 3+4(同一根因):admin 掉入学生门户导航/AI 助手页侧边栏消失

### 排查事实(playwright 复现)
- admin 在 console 点"成果审核"→ `/v2/portal/teacher/review`:**脱离 console 壳**,portal 顶栏出现且导航项=**学生菜单**(仪表板/成果展示/成果提交/AI 助手/个人资料);此时点"仪表板"→ `/portal/student/dashboard`——即用户报告的"严重错误"链路。
- admin 点"AI 智能体协作"→ `/v2/portal/chat`:console 侧边栏消失(count=0),页面只剩 portal 顶栏(同样是学生菜单)。
- **教师会话本身正常**:登录落 teacher/dashboard,导航 6 项(仪表板/成果展示/成果审核/数据导出/AI 助手/个人资料),点仪表板落 teacher/dashboard。
- 三角色逐导航项走查:学生 5 项、教师 6 项落点与壳全部一致;**admin 14 项中 2 项逃逸**(成果审核/AI 智能体协作),其余 12 项正常。

### 根因
双壳路由改造(#35)时:①`PortalLayout` 导航只有 teacher/student 两分支,**admin 缺失**→落入 else 分支=学生菜单;②chat/review/profile 三个共享页被挂进 **portal 壳**并从旧路径 301 到 `/portal/*`,admin 从 console 点这些入口就被带出侧边栏体系。v1 语义:审核与 AI 助手在 admin 控制台内是**同一页面挂在 admin 导航下**(admin_review 在侧边栏"常用"组)。

### 修改方案
1. **P0 路由归属重构**:审核页/Chat 页回迁 console 壳(admin 路径 `/admin/review`、`/chat`),portal 壳保留师生各自入口(`/portal/teacher/review`、`/portal/chat`)——**同组件双路由注册**(页面组件无壳依赖,改造量小);admin 侧边栏"成果审核"改指 `/admin/review`,"AI 智能体协作"指 `/chat`。
2. **P0 PortalLayout 补 admin 分支**:admin 万能兜底进入 portal 壳时,导航显示 admin 菜单(或直接重定向回 console),杜绝"学生菜单"误显。
3. **P1 守卫加固**:portal 壳路由按角色守卫(student 页拒 teacher/admin),防串仓。

## 问题 1+5(对照差距):/admin/awards ≠ v1 /admin/achievements

### 排查事实(双端截图对照,见排查-0901/P1-*.png)
v1 achievements(1435 行巨页)是**已入库成果库管理**:①五类成果 tabs(奖状 173/专利/软著/大创/其他——管理 awards/patents/software/innovation/other 五张表);②十维筛选(竞赛/赛道/年份/竞赛等级/获奖等级/指导教师/获奖者/学生实验室/异常状态/证书类型 学生|教师);③批量能力(复选框+批量删除、排除教师奖状、自动关联实验室、重置图谱);④表格特征(实验室青色标签列、异常行黄底高亮+"异常"徽标、编辑/删除行操作、图片可见入口);⑤分页(上一页/数字/下一页)。
v2 admin/awards 当前是**待审池管理**(pending_achievements:状态筛选+通过/驳回+下载)——**数据源与页面定位都不同**,仅筛选维度达成了对照。

### 差距清单(按 v1 结构逐块)
| v1 区块 | v2 现状 | 差距定级 |
|---|---|---|
| 五类成果 tabs(五表管理) | 无(只有 pending 池) | **P0 定位性缺失** |
| 成果行内编辑/删除(v1 edit 页) | 无 | P1(CRUD 缺口,此前已挂账) |
| 异常标记/黄底高亮 | 无 | P1 |
| 实验室关联列+标签 | 无 | P1 |
| 批量选择/批量删除 | 无 | P1 |
| 自动关联实验室/排除教师奖状开关 | 无 | P2(批处理语义) |
| 文件导入入口(该页内嵌) | 已有独立导入页 | 已覆盖(入口形态不同) |
| 十维筛选 | 已有(#37) | 已覆盖 |
| 分页 | 已有 | 已覆盖 |

### 修改方案
1. **P0 新增"成果库管理"页**(对照 v1 achievements 五 tabs):后端五表只读列表+分页(复用 #26/#37 的 PageView 口径,awards 表已有 competition_id/granted_role/laboratory_id 可支撑实验室列与证书类型筛选);前端 AdminAchievementsView 五 tab,表格对照 v1 列结构(实验室标签/异常徽标/编辑删除入口);
2. **P1 编辑/删除**:awards 行内编辑(对齐 v1 award_edit 核心字段)与删除(FK 拒绝语义同 #38);patents/software/innovation/other 四类同构;
3. **P1 异常标记**:is_abnormal 列展示+筛选+人工标记切换;
4. **P2 批量选择删除/自动关联实验室**;
5. admin 侧边栏"成果管理"语义拆分:待审池(现有页,建议改名"待审管理")与成果库管理(新页)两入口,对照 v1"成果管理+成果审核"双入口语义。
