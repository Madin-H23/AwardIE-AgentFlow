# #26 后端真分页 对照记录

> 基调:逐页对照 v1 原模板的能力面(分页+条件筛选),数据契约沿用 v2 既有 ApiResponse+Spring Page JSON。
> v1 源:`app/routes/admin_awards.py::api_achievements_awards`(L1116-1200)+ `app/templates/admin/achievements.html`。

## 一、v1 参数口径(实现前提取)

`GET /admin/api/achievements/awards`:

| 参数 | 类型/默认 | 语义 |
|---|---|---|
| page | int=1(1 基) | 页码 |
| per_page | int=20 | 每页条数 |
| competition_id / track / year / competition_level / award_level | 可选 | 竞赛维度筛选 |
| supervisor_name / winner_name | 可选 | 人名模糊筛选 |
| laboratory_id('none' 支持) / lab_view | 可选 | 实验室视图 |
| is_abnormal | '1' | 异常标记筛选 |
| certificate_type | student | 证书类型 |

响应:`total_count` + `total_pages = (total+per_page-1)//per_page` + 服务端渲染 HTML 片段。

## 二、v2 落法(能力面对照,契约沿用 v2)

v2 管理面列表的数据源是 `pending_achievements`(提交待审表),列维度与 v1 awards 物化表不同——人名/竞赛等业务属性在 jsonb `achievement_data` 内。因此筛选维度做**列级能力对照**:

| v1 能力 | v2 对应 |
|---|---|
| page/per_page 分页 | page(0 基,Spring Pageable)/size(≤100) |
| winner_name/supervisor_name 人名模糊 | keyword:jsonb 文本模糊(`cast(achievement_data as text) like`) |
| tab 类型分离 | achievementType 等值 |
| is_abnormal/状态语义 | status 等值(pending/archived/rejected) |
| year 时间维度 | dateFrom/dateTo(yyyy-MM-dd,Asia/Shanghai 墙上时间→Instant,作用于 submit_time) |

改动点:
1. `PendingAchievementRepository` extends `JpaSpecificationExecutor`——真分页,删除内存过滤假分页(#18 挂账至此清偿)。
2. `GET /api/v2/admin/achievements` 增 keyword/dateFrom/dateTo;status/achievementType 下推 SQL。
3. `GET /api/v2/student/pending` 补可选 page/size(不传保持全量——tracer E2E 与时间线依赖兼容)。
4. `GET /api/v2/admin/competitions` 的 `LIMIT 200` 硬截改真分页(page 1 基+size+q 模糊),响应 PageView{content,totalElements,totalPages,page,size};JdbcTemplate 手写 LIMIT/OFFSET+COUNT(竞赛无 JPA Entity,保持 #24 三对账门禁口径,`?` 占位对账)。
