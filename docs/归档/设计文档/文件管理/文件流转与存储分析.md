# 文件流转与存储分析

本文档对照 `文件流转汇总.md` 与 `成果审核流程设计文档.md`，说明当前自动/手动导入的文件存储与流转实现、与设计的差异、以及修复后的最新行为；并说明用户放弃或直接离开产生的垃圾及清理方式。

---

## 一、设计文档中的约定（文件流转汇总.md）

| 阶段 | 操作 | 文件位置 | 入口/说明 |
|------|------|----------|-----------|
| **阶段1 上传** | 保存 | `temp_upload/{session_id}/{hash}.{ext}` | `FileUploadService.upload_file()` |
| **阶段2 提交审核** | 移动 | `temp_upload` → `review/{session_id}/{filename}` | `PendingAchievementManager` 在状态 pending→submit 时调用 `UnifiedFileManager.move_to_review()` |
| **阶段3 审核通过** | 移动 | `review/...` → 业务目录（如 `awards/{hash}.ext`） | `ReviewService` 内调用 `move_from_review_to_business()` |
| **审核拒绝/放弃** | 删除 | 删除 `review/` 或 `temp_upload/` 下文件并清理空目录 | `safe_delete_with_file`、驳回逻辑 |

要点：**用户点击「提交审核」时，文件应从 `temp_upload` 挪到 `review`；审核通过后再从 `review` 挪到业务目录。**

## 二、当前实现：自动导入 vs 手动导入

### 2.1 自动导入（批量上传 → 解析 → 结果页 → 单条提交/全部提交）

| 步骤 | 文件位置 | 代码位置 | 说明 |
|------|----------|----------|------|
| 上传 | `files_root/temp_upload/{session_id}/{hash}.{ext}` | `FileUploadService.upload_file()` | 学生/教师/管理员自动导入均先上传到统一 `temp_upload` |
| 解析后创建 pending | 不变，仍为 `temp_upload/{session_id}/...` | `create_from_extract_result(..., file_path=upload_result.relative_path)` | `session_id` 为本次导入会话 ID，写入表列 `session_id` |
| 用户点击「提交审核」 | **应由** `temp_upload` **挪到** `review/{session_id}/...` | `pending_achievement.update(..., status='submit')` 内根据 `session_id` 调用 `move_to_review()` | 见下节「问题与修复」 |
| 审核通过 | `review/...` → `awards/` 等业务目录 | `ReviewService._submit_award()` 等内部 `move_from_review_to_business()` | 与设计一致 |

- **自动导入**：文件自始至终在 `files_root` 下；上传即进 `temp_upload`，提交审核时应进 `review`，审核通过后进业务目录。

### 2.2 手动导入（单文件上传 → 解析 → 结果页 → 提交审核）

| 步骤 | 文件位置 | 代码位置 | 说明 |
|------|----------|----------|------|
| 上传 | **config `temp_dir`/manual_import/**（如 `temp/uploads/manual_import/{uuid}_{filename}`） | `handle_manual_upload()` | 与自动导入不同，先落在配置的临时目录 |
| 解析 | 读取 `temp_dir` 下文件，**再复制到** `files_root/temp_upload/{session_id}/{filename}` | `handle_manual_parse()` → `create_from_extract_result(..., path_for_db=temp_upload/...)` | 解析后写入 pending 时，存的是 **temp_upload** 相对路径；`session_id` 写入表列 |
| 用户点击「提交审核」 | **应由** `temp_upload` **挪到** `review/{session_id}/...` | 同上，`update(..., status='submit')` 内 `move_to_review()` | 与自动导入共用同一套「pending→submit 时移动」逻辑 |
| 审核通过 | 同自动导入 | 同自动导入 | 一致 |

- **手动导入**：上传在 `temp_dir/manual_import/`，解析后**拷贝**一份到 `files_root/temp_upload/{session_id}/`，DB 中只记 `temp_upload/...`；提交审核、审核通过与自动导入一致。

### 2.3 自动与手动的差异小结

| 项目 | 自动导入 | 手动导入 |
|------|----------|----------|
| 首次落盘位置 | `files_root/temp_upload/{session_id}/{hash}.ext` | `config temp_dir/manual_import/{uuid}_{filename}` |
| 进入 pending 时文件 | 已在 `temp_upload`，不拷贝 | 从 `temp_dir` **拷贝**到 `temp_upload/{session_id}/` |
| DB 中 file_path | `temp_upload/{session_id}/{hash}.ext` | `temp_upload/{session_id}/{filename}`（原文件名） |
| 提交审核时 | 应从 temp_upload → review | 同上 |
| 审核通过后 | review → 业务目录 | 同上 |

## 三、问题与修复：提交审核后文件未进 review

### 3.1 现象

学生/教师手动提交奖状，在结果页确认后点击「提交审核」，记录状态变为 `submit` 并进入审核列表，但文件仍留在 `files/temp_upload`，`files/review` 为空。

### 3.2 原因

- 设计上：状态从 `pending` 变为 `submit` 时，应在 `PendingAchievementManager.update()` 里调用 `move_to_review(session_id, file_path)`，并把更新后的路径写回 DB。
- 实现上：`update()` 中取 `session_id` 时使用了 `ext_info.get('session_id')`。而 `create_from_extract_result` 写入的 `ext_info` JSON 只包含 `ocr_cache_hit`、`llm_cache_hit`、`match_score`、`template_id`、`template_name`，**并未包含 `session_id`**；`session_id` 是单独写入表列 `pending_achievements.session_id` 的。
- 因此 `ext_info.get('session_id')` 始终为 `None`，条件不成立，`move_to_review()` 从未被调用，文件一直留在 `temp_upload`。

### 3.3 修复

在 `backend/models/pending_achievement.py` 的 `update()` 中，当「状态从 pending 变为 submit 且需要移动文件」时：

- **优先使用表列** `pending_item.session_id`（从 DB 加载时已有）；
- 若不存在，再回退到 `ext_info.get('session_id')`（兼容旧数据或其它写入路径）。

这样学生/教师/管理员在「提交审核」时都会正确执行 `move_to_review()`，文件会从 `temp_upload` 进入 `review`。

## 四、修复后的最新设计（与设计文档对齐）

| 操作/阶段 | 文件位置 | 说明 |
|-----------|----------|------|
| 自动：上传 | `files/temp_upload/{session_id}/{hash}.ext` | FileUploadService |
| 手动：上传 | `config temp_dir/manual_import/...` | 仅上传阶段 |
| 手动：解析后 | 拷贝到 `files/temp_upload/{session_id}/...`，DB 记此路径 | 与自动导入统一为 temp_upload |
| 用户确认并点击「提交审核」 | 文件从 `temp_upload` 移到 `review/{session_id}/...`，DB 中 file_path 更新为 review 路径 | `update(..., status='submit')` 内用 `pending_item.session_id` 调用 `move_to_review()` |
| 审核通过 | 文件从 `review/...` 移到业务目录（如 awards/），pending 删除 | ReviewService + move_from_review_to_business |
| 审核拒绝 | 删除 review 下文件，删 pending，清理空目录 | 现有逻辑 |
| 用户删除单条（放弃） | 删除 pending，若文件在 temp_upload 或 review 则删文件并清理空目录 | safe_delete_with_file |

自动与手动的区别仅在于**首次落盘**（自动直接进 temp_upload，手动先 temp_dir 再拷贝到 temp_upload）；**提交审核、审核通过、拒绝、放弃**的流转与设计文档一致。

## 五、用户放弃或直接离开产生的垃圾与清理

### 5.1 可能产生的垃圾

1. **手动导入：`config temp_dir/manual_import/`**
   - 用户上传后未解析就离开，或解析后未点提交就离开：原始上传文件会一直留在 `manual_import/`。
   - 解析后已拷贝到 `temp_upload`，但 **manual_import 下的原文件不会自动删除**，会形成孤儿文件。

2. **`files/temp_upload/{session_id}/`**
   - 状态为 `pending` 的记录对应的文件（用户未点「提交审核」或未点「删除」就离开）。
   - 可通过定时任务按「过期 pending」清理（见下）。

3. **`files/review/{session_id}/`**
   - 正常应为「已提交审核」的文件；若之前未执行 move_to_review，review 会空。修复后，只有提交审核后才会在此目录产生文件。
   - 审核拒绝或放弃时，由 `safe_delete_with_file` 等删除文件并清理空目录。

### 5.2 清理方式

| 类型 | 方式 | 说明 |
|------|------|------|
| 过期 pending + temp_upload | `tools/clean_expired_pending.py` | 删除 `status='pending'` 且早于配置时间（如 30 分钟）的 pending，并删除对应 `files/temp_upload/{session_id}/` 下文件及空目录。配置：`config/settings.json` → `pending_cleanup.expire_minutes`。 |
| 管理员一键清空 | 管理端「缓存清理」等 | 删除所有 pending、清空 temp_upload、以及 review 中未引用会话/文件（见 admin 路由）。 |
| manual_import 孤儿文件 | **当前无自动清理** | 需定期手动清理 `temp_dir/manual_import/`，或后续可增加按修改时间清理该目录的脚本。 |

### 5.3 建议

- 若希望手动导入的上传文件在「解析并成功写入 pending」后不再保留，可在 `handle_manual_parse` 中在拷贝到 `temp_upload` 并成功 `create_from_extract_result` 后，删除 `temp_dir` 下该原始文件（需注意并发与错误处理）。
- 对 `temp_dir/manual_import/` 可增加按修改时间超过 N 小时的清理任务，与 `clean_expired_pending` 类似，避免长期堆积。

---

## 六、小结

- **设计**：上传 → temp_upload；提交审核 → review；审核通过 → 业务目录；拒绝/放弃 → 删文件并清空目录。
- **实现**：自动导入全程在 `files_root/temp_upload`；手动导入先存 `temp_dir/manual_import`，解析后拷贝到 `temp_upload`，之后与自动一致。
- **问题**：提交审核时未移动文件到 review，因 `update()` 中用 `ext_info.get('session_id')` 取不到值。
- **修复**：`update()` 在 pending→submit 时优先使用 `pending_item.session_id` 调用 `move_to_review()`，与设计文档一致。
- **垃圾与清理**：过期 pending 与 temp_upload 由 `clean_expired_pending.py` 清理；manual_import 当前无自动清理，可后续加脚本或在上传解析成功后删除原文件。
