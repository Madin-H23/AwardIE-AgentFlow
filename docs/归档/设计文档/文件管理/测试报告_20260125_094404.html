修复 #1: submit_for_review方法在pending状态时错误移动文件
已修复
问题描述:
`submit_for_review`方法在创建pending记录时，如果`ext_info`中有`session_id`，会立即将文件从`temp_upload`移动到`review`目录，但此时状态是`pending`，不应该移动文件。文件应该只在状态变为`submit`时才移动。
修复方案:
修改`backend/models/pending_achievement.py`的`submit_for_review`方法： - 添加状态检查：只有当`initial_status == 'submit'`时才移动文件 - 确保`pending`状态时文件保持在`temp_upload`目录
修复位置:
backend/models/pending_achievement.py:267-279
验证结果:
✅ 奖状测试通过：文件在pending状态时保持在temp_upload，提交审核后正确移动到review目录
修复 #2: update方法未处理状态变更时的文件移动
已修复
问题描述:
`update`方法在将状态从`pending`更新为`submit`时，没有移动文件从`temp_upload`到`review`目录。这导致提交审核后文件仍在`temp_upload`目录。
修复方案:
在`backend/models/pending_achievement.py`的`update`方法中添加逻辑： - 检测状态从`pending`变为`submit` - 如果状态变更，且`ext_info`中有`session_id`，调用`move_to_review`移动文件 - 更新数据库中的`file_path`字段
修复位置:
backend/models/pending_achievement.py:589-600
验证结果:
✅ 所有类型测试通过：提交审核后文件正确移动到review目录
修复 #3: 测试代码使用错误的查询方法参数
已修复
问题描述:
测试代码中调用`query_patents(limit=1000)`，但`query_patents`方法只接受`filter_obj`参数，不接受`limit`参数，导致`TypeError`。
修复方案:
修改`tests/test_files.py`： - 将`query_patents(limit=1000)`改为`query_patents(filter_obj=None)` - 确保所有查询方法调用使用正确的参数格式
修复位置:
tests/test_files.py:589
验证结果:
✅ 专利测试通过：查询方法调用正确

修复位置:
backend/services/review_service.py:1228-1246
验证结果:
✅ 大创测试通过：项目成功入库，文件正确删除
修复 #5: 测试代码AppContext实例不一致
已修复

修复位置:
tests/test_files.py:66-81, 221-243
验证结果:

1. 临时文件对象未正确关闭，导致文件句柄仍被占用 2. Windows文件系统延迟，文件刚创建就被尝试删除 3. `save_lab_file`方法中的临时文件处理逻辑有问题 4. 文件路径处理不正确，导致使用了错误的文件路径
