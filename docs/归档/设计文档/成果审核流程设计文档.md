# 成果审核流程设计文档

## 一、设计目标

### 1.1 解决的问题

| 问题 | 现状 | 目标 |
|------|------|------|
| **提交权限受限** | 只有管理员可以上传 | 学生、教师、管理员都可以自主提交 |
| **文件重复提交** | session机制导致重复记录 | 基于文件hash去重，覆盖更新 |
| **审核流程单一** | 只有管理员审核 | 支持分权审核（教师审核本实验室学生） |
| **状态管理混乱** | 状态值过多且不一致 | 简化为 2 个核心状态 |
| **审核过程不可追溯** | 没有审核日志 | 完整的审核日志记录 |

### 1.2 设计原则

1. **渐进式实施** - 分步骤完成，每步可独立测试验证
2. **向后兼容** - 不影响现有功能，逐步迁移
3. **数据一致性** - 审核完成后清理临时数据
4. **权限清晰** - 基于角色和实验室归属的明确权限划分
5. **统一文件管理** - 所有文件操作通过 `UnifiedFileManager` 进行，路径统一管理
6. **空目录清理** - 文件移动/删除后自动清理空目录，避免目录堆积

### 2.2 状态定义

只有**两个持久化状态**：

| 状态值 | 含义 | 可执行操作 | 操作后状态 |
|--------|------|------------|-----------|
| `pending` | 等待提交人审核 | 修改数据/提交审核/删除 | submit 或 删除 |
| `submit` | 等待审核人审核 | 审核人：通过/拒绝 | pending（修改后）或 删除 |

**重要说明**：
- 审核通过/拒绝是**原子事务操作**，不改变 pending 记录的状态，而是直接删除记录
- 审核后的状态信息由 `review_logs` 表记录
- 提交人修改已提交的记录后，状态从 `submit` 回退到 `pending`

### 2.3 权限设计

#### 角色权限矩阵

| 角色 | 可提交 | 可查看 | 可审核 | 审核范围 |
|------|--------|--------|--------|----------|
| **管理员** | ✅ | 所有记录 | ✅ | 所有记录 |
| **教师** | ✅ | 本实验室学生+自己的 | ✅ | 本实验室学生提交的成果 |
| **学生** | ✅ | 自己的记录 | ❌ | - |
| **学生助教** | ✅（作为学生） | 自己的记录 | ❌ | - |

## 三、数据模型设计

### 3.1 pending_achievements 表结构

```sql
CREATE TABLE pending_achievements (
    -- 主键
    id INTEGER PRIMARY KEY AUTOINCREMENT,

    -- 成果基本信息
    achievement_type TEXT NOT NULL
        CHECK(achievement_type IN ('award', 'patent', 'software', 'innovation', 'other')),
    achievement_data TEXT NOT NULL,        -- JSON: 提取的结构化数据
    validation_result TEXT,                -- JSON: 验证结果

    -- AI提取调试信息（可选）
    ocr_text TEXT,                         -- OCR识别的原始文本
    llm_prompt TEXT,                       -- LLM提示词
    llm_response TEXT,                     -- LLM响应
    ext_info TEXT,                         -- JSON: {ocr_cache_hit, llm_cache_hit, match_score, template_id}

    -- 提交人信息
    submitter_type TEXT NOT NULL
        CHECK(submitter_type IN ('student', 'teacher', 'admin')),
    submitter_id INTEGER NOT NULL,
    submit_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

    -- 审核状态
    status TEXT DEFAULT 'pending'
        CHECK(status IN ('pending', 'submit')),

    -- 预分配审核人信息（可为空，用于确定审核人类型）
    assigned_reviewer_type TEXT CHECK(assigned_reviewer_type IN ('teacher', 'admin')),

    -- 实际审核人信息（审核时填写）
    reviewer_type TEXT CHECK(reviewer_type IN ('teacher', 'admin')),
    reviewer_id INTEGER,
    review_time TIMESTAMP,
    review_comment TEXT,

    -- 文件信息
    file_path TEXT NOT NULL,               -- 文件相对路径（temp_upload/... 或 review/...）
    file_hash TEXT NOT NULL,               -- 文件hash（用于去重）

    -- 时间戳
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 索引
CREATE INDEX idx_pending_status ON pending_achievements(status, achievement_type);
CREATE INDEX idx_pending_submitter ON pending_achievements(submitter_type, submitter_id);
CREATE INDEX idx_pending_assigned_reviewer ON pending_achievements(assigned_reviewer_type);
CREATE INDEX idx_pending_file_hash ON pending_achievements(file_hash);  -- 去重查询
CREATE INDEX idx_pending_submit_time ON pending_achievements(submit_time);
```

## 四、关键功能设计

### 4.1 文件去重机制

```
上传文件
  ↓
计算文件 hash (MD5)
  ↓
查询 pending_achievements WHERE file_hash = ?
  ↓
┌─────────────────┬─────────────────┐
│  hash 已存在     │  hash 不存在    │
│  ↓               │  ↓              │
│ 覆盖temp_upload文件│ 保存新文件到temp_upload│
│ 重新AI解析        │ AI解析          │
│ 更新记录          │ 创建新记录      │
│ (保留原 id)      │ (新 id)         │
│ 状态重置为pending │ 状态: pending   │
└─────────────────┴─────────────────┘
```

**好处**：
- 避免重复记录
- 支持重新上传更正文件
- 简化用户操作

### 4.2 审核人查询逻辑

#### 教师可审核记录查询

```sql
-- 查询教师可以审核的记录（本实验室学生提交的）
SELECT pa.* FROM pending_achievements pa
INNER JOIN laboratory_students ls ON pa.submitter_id = ls.student_id
INNER JOIN laboratory_instructors li ON ls.laboratory_id = li.laboratory_id
WHERE li.teacher_id = ?
  AND pa.submitter_type = 'student'
  AND pa.status = 'submit'
  AND pa.assigned_reviewer_type = 'teacher';
```

#### 管理员可审核记录查询

```sql
-- 查询管理员可以审核的记录
SELECT pa.* FROM pending_achievements pa
WHERE pa.status = 'submit'
  AND (
      pa.submitter_type IN ('admin', 'teacher')           -- 教师/管理员提交
      OR pa.assigned_reviewer_type = 'admin'              -- 或明确指定由管理员审核
      OR pa.submitter_id NOT IN (                         -- 或不属于任何实验室的学生
          SELECT DISTINCT student_id FROM laboratory_students
      )
  );
```

#### 学生查看自己的记录

```sql
-- 学生查看自己的记录
SELECT pa.* FROM pending_achievements pa
WHERE pa.submitter_type = 'student'
  AND pa.submitter_id = ?
  AND pa.status IN ('pending', 'submit');
```

### 4.3 审核操作流程

#### 审核通过（原子事务）

```python
def approve_pending(pending_id, reviewer_id, reviewer_type, comment):
    """
    审核通过 - 原子事务
    """
    conn = get_db_connection()
    try:
        conn.execute('BEGIN TRANSACTION')

        # 1. 获取 pending 记录
        pending = get_pending_by_id(pending_id)

        # 2. 创建成果记录
        achievement = create_achievement(pending)

        # 3. 移动文件到永久存储
        from backend.services.unified_file_manager import get_unified_file_manager, FileType
        file_manager = get_unified_file_manager()
        
        # 根据成果类型确定 FileType
        file_type_map = {
            'award': FileType.AWARD,
            'patent': FileType.PATENT,
            'software': FileType.SOFTWARE,
            'other': FileType.OTHER,
            'innovation': FileType.OTHER
        }
        file_type = file_type_map.get(pending.achievement_type)
        
        # 获取 image_hash（奖状类型需要）
        image_hash = None
        if pending.achievement_type == 'award':
            data = json.loads(pending.achievement_data)
            image_hash = data.get('image_hash')
        
        # 移动文件
        permanent_path = file_manager.move_from_review_to_business(
            review_path=pending.file_path,
            file_type=file_type,
            image_hash=image_hash
        )

        # 4. 更新成果记录的文件路径
        update_achievement_file_path(achievement.id, permanent_path)

        # 5. 记录审核日志
        create_review_log(
            pending_id=pending.id,
            action_type='approved',
            result_type=pending.achievement_type,
            result_id=achievement.id,
            result_file_path=permanent_path,
            reviewer_id=reviewer_id,
            reviewer_type=reviewer_type,
            comment=comment
        )

        # 6. 删除 pending 记录
        delete_pending(pending_id)

        conn.commit()
    except Exception as e:
        conn.rollback()
        raise
```

#### 审核拒绝（原子事务）

```python
def reject_pending(pending_id, reviewer_id, reviewer_type, comment):
    """
    审核拒绝 - 原子事务
    """
    conn = get_db_connection()
    try:
        conn.execute('BEGIN TRANSACTION')

        # 1. 获取 pending 记录
        pending = get_pending_by_id(pending_id)

        # 2. 删除审核目录中的文件
        from backend.services.unified_file_manager import get_unified_file_manager
        file_manager = get_unified_file_manager()
        file_path = file_manager.files_root / pending.file_path
        if file_path.exists():
            file_manager._safe_unlink(file_path)
            # 清理空目录（文件在 review/ 目录中）
            file_manager._cleanup_empty_parent_dirs(file_path, ['review'])

        # 3. 记录审核日志
        create_review_log(
            pending_id=pending.id,
            action_type='rejected',
            reviewer_id=reviewer_id,
            reviewer_type=reviewer_type,
            comment=comment
        )

        # 4. 删除 pending 记录
        delete_pending(pending_id)

        conn.commit()
    except Exception as e:
        conn.rollback()
        raise
```

#### 提交人删除（原子事务）

```python
def delete_pending_by_submitter(pending_id, submitter_id):
    """
    提交人删除 - 原子事务
    """
    conn = get_db_connection()
    try:
        conn.execute('BEGIN TRANSACTION')

        # 1. 获取 pending 记录（验证权限）
        pending = get_pending_by_id(pending_id)
        if pending.submitter_id != submitter_id:
            raise PermissionError("无权删除他人的记录")

        # 2. 删除文件（可能在 temp_upload 或 review 目录中）
        from backend.services.unified_file_manager import get_unified_file_manager
        file_manager = get_unified_file_manager()
        file_path = file_manager.files_root / pending.file_path
        if file_path.exists():
            file_manager._safe_unlink(file_path)
            # 清理空目录（根据文件所在目录决定）
            source_rel = str(file_path.relative_to(file_manager.files_root))
            if source_rel.startswith('temp_upload'):
                file_manager._cleanup_empty_parent_dirs(file_path, ['temp_upload'])
            elif source_rel.startswith('review'):
                file_manager._cleanup_empty_parent_dirs(file_path, ['review'])

        # 3. 记录审核日志
        create_review_log(
            pending_id=pending.id,
            action_type='deleted',
            reviewer_id=submitter_id,
            reviewer_type=pending.submitter_type,
            comment="提交人删除"
        )

        # 4. 删除 pending 记录
        delete_pending(pending_id)

        conn.commit()
    except Exception as e:
        conn.rollback()
        raise
```

## 五、文件存储设计

### 5.1 目录结构（统一文件管理）

```
files/
  temp_upload/              -- 临时上传目录（用户上传后，等待提交审核）
    {session_id}/
      {file_hash}.{ext}
  
  review/                   -- 审核目录（已提交审核，等待审核人处理）
    {session_id}/
      {file_hash}.{ext}
  
  awards/                   -- 奖状业务目录（审核通过后）
    {image_hash}.{ext}
  
  patents/                  -- 专利业务目录（审核通过后）
    patent_{timestamp}.{ext}
  
  software/                 -- 软著业务目录（审核通过后）
    software_{timestamp}.{ext}
  
  other/                    -- 其他类型业务目录（审核通过后）
    other_{hash}_{timestamp}.{ext}
  
  laboratories/             -- 实验室文件目录（审核通过后，Other类型关联实验室时）
    {lab_id}/
      photos/               -- 实验室图片
        {hash}.{ext}
      downloads/            -- 实验室下载文件
        {hash}.{ext}
```

**注意**：
- 实验室封面图片不通过文件管理，直接保存到 `app/static/images/laboratory_covers/` 目录
- 路径格式：`images/laboratory_covers/lab_{lab_id}_{timestamp}.{ext}`

### 5.2 文件路径管理

| 阶段 | 位置 | 数据库记录 | 文件管理器方法 |
|------|------|-----------|---------------|
| **1. 上传阶段** | `temp_upload/{session_id}/{hash}.{ext}` | `pending_achievements.file_path` = 相对路径 | `FileUploadService.upload_file()` |
| **2. 提交审核** | `review/{session_id}/{hash}.{ext}` | `pending_achievements.file_path` = 相对路径（更新） | `UnifiedFileManager.move_to_review()` |
| **3. 审核通过** | 业务目录（见下表） | 各业务表的 `file_path` 或 `image_path` 字段 | `UnifiedFileManager.move_from_review_to_business()` |
| **4. 审核拒绝** | 删除 | - | 直接删除 `review/` 中的文件 |

### 5.3 各类型文件最终入库路径

| 成果类型 | 审核通过后文件位置 | 数据表 | 命名规则 | 去重策略 |
|---------|------------------|--------|---------|---------|
| **奖状** | `awards/{image_hash}.{ext}` | `awards` | hash 命名 | 基于 `image_hash` + `certificate_id` |
| **专利** | `patents/patent_{timestamp}.{ext}` | `patents` | 时间戳命名 | 基于 `application_number` |
| **软著** | `software/software_{timestamp}.{ext}` | `software_copyrights` | 时间戳命名 | 基于 `registration_number` |
| **其他（图片）** | `laboratories/{lab_id}/photos/{hash}.{ext}` | `laboratory_images` | hash 命名 | 基于文件 hash |
| **其他（文档）** | `laboratories/{lab_id}/downloads/{hash}.{ext}` | `laboratory_downloads` | hash 命名 | 基于文件 hash |
| **其他（独立）** | `other/other_{hash}_{timestamp}.{ext}` | `other_files` | 时间戳+hash命名 | 基于文件 hash |
| **大创** | `other/other_{hash}_{timestamp}.{ext}` | `innovation_projects` | 时间戳+hash命名 | 基于文件 hash |

### 5.4 文件管理模块

所有文件操作通过 `UnifiedFileManager` 统一管理：

- **上传阶段**: `FileUploadService.upload_file()` → 保存到 `temp_upload/{session_id}/{hash}.{ext}`
- **提交审核**: `UnifiedFileManager.move_to_review(session_id, file_path)` → 移动到 `review/{session_id}/{hash}.{ext}`
- **审核通过**: `UnifiedFileManager.move_from_review_to_business(review_path, file_type, image_hash)` → 移动到业务目录
- **审核拒绝**: 直接删除 `review/` 中的文件，并清理空目录

**空目录清理**：
- 文件移动/删除后，自动清理 `temp_upload/` 和 `review/` 中的空目录
- 通过 `_cleanup_empty_parent_dirs()` 方法实现

## 十、总结

### 核心改进

1. **简化状态管理** - 只有两个持久化状态（pending、submit）
2. **原子审核操作** - 审核通过/拒绝作为事务处理

7. **空目录自动清理** - 文件移动/删除后自动清理空目录，避免目录堆积

- 事务一致性保证
- 基于实验室归属的动态权限分配
- 文件生命周期管理（temp_upload → review → 业务目录）
- 统一文件管理器，路径统一配置，无硬编码
- 空目录自动清理机制
- 渐进式实施策略

## 十一、文件管理集成说明

### 11.1 统一文件管理器

所有文件操作通过 `UnifiedFileManager` 进行，确保：
- **路径统一管理**: 所有路径从配置文件读取，无硬编码
- **目录自动创建**: 目标目录不存在时自动创建
- **空目录清理**: 文件移动/删除后自动清理空目录
- **错误处理**: 文件不存在或操作失败时抛出明确异常

### 11.2 文件流转路径

```
上传 → temp_upload/{session_id}/{hash}.{ext}
  ↓ (用户提交审核)
review/{session_id}/{hash}.{ext}
  ↓ (审核通过)
业务目录/{hash或timestamp}.{ext}
  ↓ (审核拒绝)
删除文件 + 清理空目录
```

### 11.3 特殊说明

1. **实验室封面图片**: 不通过文件管理，直接保存到 `app/static/images/laboratory_covers/`
2. **Other类型文件**: 
   - 图片 → `laboratories/{lab_id}/photos/` 或 `other/`
   - 文档 → `laboratories/{lab_id}/downloads/` 或 `other/`
3. **空目录清理**: 文件移动/删除后，自动清理 `temp_upload/` 和 `review/` 中的空目录
