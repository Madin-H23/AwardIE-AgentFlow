# extract 模块测试用例设计

## 测试概述

本文档针对 `backend/extract` 模块设计三层测试方案：

1. **第一层：API测试** - 测试抽取框架的接口和方法
2. **第二层：数据验证测试** - 基于真实图片的抽取准确性验证
3. **第三层：业务流程测试** - 端到端的业务流程验证

## 测试环境

### 模块版本
- `backend/extract` 模块：重构版本（替代旧的 `document_extract`）
- `backend/ocr` 模块：OCR引擎
- `backend/extract/llm` 模块：LLM引擎

### 测试数据
- 测试图片目录：`images/测试图片/`
- 标准答案：`tests/reports/批量图片抽取测试(标准答案）.html`

### 配置文件
- 主配置：`config/settings.json`
- API密钥：`apikey/apikey.json`

## 第三层：业务流程测试

### 目标
验证完整的业务流程：文件上传 → 用户审核 → 提交到主数据库

### 业务流程概述

```
用户上传文件
    ↓
FileUploadService（去重、保存临时文件）
    ↓
ExtractFramework（OCR + LLM + 验证）
    ↓
PendingAchievement（存储到 pending_achievements 表）
    ↓
用户查看/编辑（可选）
    ↓
提交审核
    ↓
ReviewService（审核通过/拒绝）
    ↓
提交到主数据库（awards/patents/software_copyrights/innovation_projects/other_files）
    ↓
文件移动到正式目录
```
