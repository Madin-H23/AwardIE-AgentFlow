# 业务流程详细分析

本文档详细分析成果提交与审核的完整业务流程，包括所有分支场景。

## 一、业务流程概览

### 1.1 完整流程图

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                              成果提交审核流程                                 │
└─────────────────────────────────────────────────────────────────────────────┘

┌──────────────┐
│  用户上传文件  │ (学生/教师/管理员)
└──────┬───────┘
       │
       ↓

│  2. 检查去重: file_hash在pending_achievements中查找                           │

│  4. 创建pending记录                                                          │
└────────────────────────────┬────────────────────────────────────────────────┘
                             │
                             ↓ (重复返回已存在pending_id)

                                  │  5. 更新pending记录:                      │
                                  │     - achievement_data (JSON)             │

                                  │     - ocr_text, llm_prompt, llm_response  │

                              │  └────────────────────────────────────────┘  │
                              │                                               │

                              │  │  2. 调用验证器重新验证                   │  │

                              │  │  4. 更新status为'submit'                │  │
                              │  │  5. 进入审核队列                         │  │
                              │  └────────────────────────────────────────┘  │
                              └──────────────────────────────────────────────┘
                                                    │
                                                    ↓ (status='submit')

                              │  │  2. 删除pending记录                      │  │
                              │  │  3. 删除临时文件                         │  │
                              │  └────────────────────────────────────────┘  │
                              │                                               │
                              │  ┌────────────────────────────────────────┐  │
                              │  │ 分支3: 批量操作 (approve/discard_batch) │  │
                              │  │  - 循环调用单个操作方法                  │  │
                              │  │  - 返回每个操作的结果                    │  │
                              │  └────────────────────────────────────────┘  │
                              └──────────────────────────────────────────────┘
                                                    │
                                                    ↓ (审核通过)
                              ┌──────────────────────────────────────────────┐
                              │              普通用户验证阶段                   │
                              │  1. 学生登录查看成果列表                     │
                              │  2. 教师登录查看成果列表                     │
                              │  3. 验证数据可见性:                          │
                              │     - 自己提交的成果可见                     │
                              │     - 自己关联的成果可见 (获奖者/指导教师)    │
                              └──────────────────────────────────────────────┘
```

### 1.2 状态转换图

```
pending (初始状态)
    │
    ├─→ [用户删除] → 记录删除
    │
    ├─→ [用户直接提交] → submit
    │
    ├─→ [用户修改并提交] → submit (伴随validation_result更新)
    │
    └─→ [管理员批量操作] → submit 或删除

submit (已提交待审核)
    │
    ├─→ [管理员审核通过] → 写入主表 → 记录删除
    │
    ├─→ [管理员放弃] → 记录删除
    │
    └─→ [管理员批量操作] → 批量写入主表或删除
```

### 2.5 实验室关联逻辑

```
┌─────────────────────────────────────────────────────────────┐
│                    实验室关联决策树                          │
└─────────────────────────────────────────────────────────────┘

1. 成果中有指导教师?
   ├─ 是 → 使用第一位指导教师所在实验室
   └─ 否 ↓

2. 提交人是教师?
   ├─ 是 → 使用提交人所在实验室
   └─ 否 ↓

3. 不关联实验室 (laboratory_id = NULL)

特殊说明:
- 学生提交人所在实验室不作为判断依据
- 一个学生可能属于多个实验室
- 学生提交的成果不一定与其所在实验室相关
```

```
阶段1: API测试 (不涉及数据库写入)
    ├── ExtractFramework 单元测试

    ├── 验证器单元测试

阶段3: 业务流程测试 (需要数据库写入)
    ├── 文件上传流程
    ├── 用户审核分支 (删除/提交/修改提交)
    ├── 管理员审核分支 (通过/放弃)
```
