# 大创项目数据对接设计文档

## 一、概述

本文档描述了大创项目从抽取器输出到数据库存储的完整数据流转过程，重点关注三个数据结构之间的映射关系、格式转换，以及学生关联的实现方案。

## 二、数据结构映射关系

### 2.1 三个数据结构

#### 2.1.1 抽取器输出结构（ExtractResult.data）

从 `大创抽取器设计.md` 中，抽取器输出的项目数据结构为：

### 2.3 格式转换说明

#### 2.3.1 other_members 转换

**抽取器输出**：数组格式
```python
"项目其他成员信息": [
    {"姓名": "张三", "学号": "2022001"},
    {"姓名": "李四", "学号": "2022002"}
]
```

**InnovationProject.other_members**：JSON字符串
```python
other_members = '["张三(2022001)", "李四(2022002)"]'
# 或
other_members = '[{"姓名":"张三","学号":"2022001"},{"姓名":"李四","学号":"2022002"}]'
```

**当前实现问题**：
- `InnovationProject.get_members_list()` 方法尝试解析JSON，但格式不统一
- 没有保留学号信息，导致无法精确匹配学生

**建议格式**：使用JSON数组存储完整信息
```json
[
    {"姓名": "张三", "学号": "2022001"},
    {"姓名": "李四", "学号": "2022002"}
]
```

#### 2.3.2 supervisors 转换

**抽取器输出**：字符串数组
```python
"指导教师": ["王老师", "赵老师"]
```

```python
supervisors = "王老师,赵老师"
```

**转换逻辑**：
```python
# 抽取器 → InnovationProject

```

## 三、学生关联方案设计

### 3.1 问题分析

#### 3.1.1 当前问题

1. **other_members 存储不完整**：
   - 当前 `other_members` 字段只存储姓名列表，丢失了学号信息
   - 无法通过学号精确匹配学生，只能通过姓名模糊匹配（存在重名问题）

2. **缺少学生关联表**：
   - 数据库中没有 `innovation_project_students` 关联表
   - 学生登录后无法查询到自己参与的大创项目

3. **匹配逻辑不完善**：
   - 没有类似 `Award.refresh_associations()` 的方法来建立学生关联
   - 保存项目时没有自动创建学生关联记录

#### 3.1.2 优势条件

相比 Award 类，大创项目有以下优势：
- **有学号信息**：负责人和其他成员都有学号，可以精确匹配
- **结构清晰**：负责人和成员角色明确，便于区分

### 3.2 方案设计

#### 方案一：参考 Award 类的关联表设计（推荐）

**设计思路**：
- 创建关联表存储项目-学生关系
- 保存项目时自动建立关联
- 支持通过学号精确匹配，姓名作为备用

**数据库设计**：

```sql
-- 大创项目学生关联表
CREATE TABLE innovation_project_students (
    project_id INTEGER NOT NULL,
    student_id INTEGER NOT NULL,
    role TEXT NOT NULL CHECK(role IN ('leader', 'member')),  -- 角色：负责人或成员
    student_name TEXT,                                        -- 原始姓名（用于显示）
    student_id_str TEXT,                                       -- 原始学号（用于匹配）
    match_type TEXT,                                          -- 匹配类型（见3.3节）
    PRIMARY KEY (project_id, student_id),
    FOREIGN KEY (project_id) REFERENCES innovation_projects(id) ON DELETE CASCADE,
    FOREIGN KEY (student_id) REFERENCES students(id) ON DELETE CASCADE
);

-- 索引
CREATE INDEX IF NOT EXISTS idx_innovation_project_students_student 
    ON innovation_project_students(student_id);
CREATE INDEX IF NOT EXISTS idx_innovation_project_students_project 
    ON innovation_project_students(project_id);
```

**匹配类型（match_type）**：

| match_type | 说明 | 前端显示 |
|-----------|------|---------|
| `student_id_exact` | 学号精确匹配成功 | 绿色："张三 (2022001) ✓" |
| `name_only` | 仅姓名匹配（学号不存在或未匹配） | 黄色："张三 (学号未匹配)" |
| `id_not_found` | 学号在数据库中不存在 | 橙色："2022001 (学号不存在)" |
| `id_name_mismatch` | 学号与姓名不匹配 | 红色："张三/2022001 (信息不符)" |
| `unmatched` | 完全未匹配 | 红色："张三 (未找到)" |

**实现要点**：

1. **InnovationProject 类扩展**：
   ```python
   @dataclass
   class InnovationProject:
       # ... 现有字段 ...
       
       # 对象关联（不存入主表，存入关联表）
       student_leader_obj: Optional[Student] = field(default=None, init=False)
       student_members: List[Student] = field(default_factory=list, init=False)
   ```

2. **匹配逻辑**：
   ```python
   def refresh_student_associations(self, student_manager: StudentManager) -> bool:
       """
       刷新学生关联：匹配负责人和成员
       返回 True 表示所有关联都成功，False 表示存在未匹配项
       """
       all_matched = True
       
       # 1. 匹配负责人（优先使用学号）
       if self.student_leader_id:
           student = student_manager.get_student_by_student_id(self.student_leader_id)
           if student:
               # 验证姓名是否匹配
               if student.name == self.student_leader_name:
                   self.student_leader_obj = student
                   match_type = "student_id_exact"
               else:
                   # 学号存在但姓名不匹配
                   all_matched = False
                   match_type = "id_name_mismatch"
           else:
               # 学号不存在，尝试用姓名匹配
               found = student_manager.find_students_by_name(self.student_leader_name)
               if len(found) == 1:
                   self.student_leader_obj = found[0]
                   match_type = "name_only"
               elif len(found) > 1:
                   all_matched = False
                   match_type = "name_ambiguous"
               else:
                   all_matched = False
                   match_type = "unmatched"
       elif self.student_leader_name:
           # 只有姓名，没有学号
           found = student_manager.find_students_by_name(self.student_leader_name)
           if len(found) == 1:
               self.student_leader_obj = found[0]
               match_type = "name_only"
           elif len(found) > 1:
               all_matched = False
               match_type = "name_ambiguous"
           else:
               all_matched = False
               match_type = "unmatched"
       
       # 2. 匹配成员（从 other_members 解析）
       self.student_members = []
       members_data = self._parse_other_members()  # 解析JSON
       
       for member in members_data:
           member_name = member.get("姓名")
           member_id = member.get("学号")
           
           if member_id:
               student = student_manager.get_student_by_student_id(member_id)
               if student:
                   if student.name == member_name:
                       self.student_members.append(student)
                       # match_type = "student_id_exact"
                   else:
                       all_matched = False
                       # match_type = "id_name_mismatch"
               else:
                   # 学号不存在，尝试姓名匹配
                   found = student_manager.find_students_by_name(member_name)
                   if len(found) == 1:
                       self.student_members.append(found[0])
                       # match_type = "name_only"
                   else:
                       all_matched = False
                       # match_type = "unmatched"
           elif member_name:
               # 只有姓名
               found = student_manager.find_students_by_name(member_name)
               if len(found) == 1:
                   self.student_members.append(found[0])
               else:
                   all_matched = False
       
       return all_matched
   ```

3. **保存关联**：
   ```python
   def _save_student_associations(self, cursor, project_id: int):
       """保存学生关联到关联表"""
       # 删除旧关联
       cursor.execute(
           "DELETE FROM innovation_project_students WHERE project_id = ?",
           (project_id,)
       )
       
       # 保存负责人
       if self.student_leader_obj:
           cursor.execute("""
               INSERT INTO innovation_project_students 
               (project_id, student_id, role, student_name, student_id_str, match_type)
               VALUES (?, ?, 'leader', ?, ?, ?)
           """, (
               project_id,
               self.student_leader_obj.id,
               self.student_leader_name,
               self.student_leader_id,
               "student_id_exact"  # 根据实际匹配结果设置
           ))
       
       # 保存成员
       members_data = self._parse_other_members()
       for i, member in enumerate(members_data):
           # 找到对应的 Student 对象
           member_student = None
           for s in self.student_members:
               if s.student_id == member.get("学号"):
                   member_student = s
                   break
           
           if member_student:
               cursor.execute("""
                   INSERT INTO innovation_project_students 
                   (project_id, student_id, role, student_name, student_id_str, match_type)
                   VALUES (?, ?, 'member', ?, ?, ?)
               """, (
                   project_id,
                   member_student.id,
                   member.get("姓名"),
                   member.get("学号"),
                   "student_id_exact"  # 根据实际匹配结果设置
               ))
   ```

**优点**：
- ✅ 结构清晰，与 Award 类保持一致
- ✅ 支持精确匹配（学号）和模糊匹配（姓名）
- ✅ 记录匹配状态，便于前端显示和后续处理
- ✅ 学生登录后可通过关联表快速查询
- ✅ 支持级联删除，数据一致性好

**缺点**：
- ⚠️ 需要创建新表，需要数据库迁移
- ⚠️ 保存时需要额外操作关联表

#### 方案二：仅改进 other_members 存储格式（不推荐）

**设计思路**：
- 不创建关联表，只改进 `other_members` 的存储格式
- 保留学号和姓名信息
- 学生查询时通过 `other_members` 字段搜索


## 五、边界情况处理

### 5.1 学号不存在

**场景**：抽取的学号在 students 表中不存在

**处理**：
1. 记录 `match_type = "id_not_found"`
2. 尝试用姓名匹配
3. 如果姓名匹配成功，记录 `match_type = "name_only"`
4. 如果都匹配失败，记录 `match_type = "unmatched"`，但不阻止保存

### 5.2 学号与姓名不匹配

**场景**：学号存在，但对应的学生姓名与抽取的姓名不一致

**处理**：
1. 记录 `match_type = "id_name_mismatch"`
2. 不建立关联（或建立关联但标记为异常）
3. 前端显示警告信息

### 5.3 姓名重名

**场景**：只有姓名，没有学号，且姓名在数据库中有多个匹配

**处理**：
1. 记录 `match_type = "name_ambiguous"`
2. 不建立关联（或让管理员手动选择）
3. 前端显示提示信息

### 5.4 other_members 格式不统一

**场景**：历史数据可能是逗号分隔的字符串，新数据是JSON

**处理**：
```python
def _parse_other_members(self) -> List[Dict[str, str]]:
    """解析 other_members，兼容多种格式"""
    if not self.other_members:
        return []
    
    # 尝试解析JSON
    try:
        data = json.loads(self.other_members)
        if isinstance(data, list):
            # 检查元素格式
            if data and isinstance(data[0], dict):
                return data  # 新格式：[{"姓名":"...","学号":"..."}]
            elif data and isinstance(data[0], str):
                # 旧格式：["张三(2022001)", "李四(2022002)"]
                return self._parse_legacy_format(data)
    except:
        pass
    
    # 尝试逗号分隔
    if "," in self.other_members:
        names = [n.strip() for n in self.other_members.split(",")]
        return [{"姓名": name, "学号": None} for name in names]
    
    return []
```

### 8.2 保存关联时的注意事项

1. **事务处理**：确保主表插入和关联表插入在同一事务中
2. **去重处理**：避免重复插入相同的关联关系
3. **错误处理**：如果关联失败，记录日志但不阻止主表保存

### 8.3 other_members 格式统一

在保存前，确保 `other_members` 统一为JSON格式：

```python
def _normalize_other_members(self, members_data: List[Dict]) -> str:
    """将成员数据标准化为JSON字符串"""
    if not members_data:
        return None
    return json.dumps(members_data, ensure_ascii=False)
```

### 8.4 数据迁移策略

对于已有数据：
1. 先创建关联表（不影响现有数据）
2. 可选：编写数据迁移脚本，从 `other_members` 字段解析并建立关联
3. 新导入的数据自动建立关联
