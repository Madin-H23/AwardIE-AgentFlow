## 概述

“前端控制台与公共交互”是控制台化改造与请求安全的前端基础设施。它由三部分组成：

- **控制台启动**：`base_console.html` 提供控制台基类布局，并在首屏内联 `boot-core`，完成安全存储封装、全局异常捕获、白屏检测。
- **深色主题**：`console_theme.js` 双轨同步 `data-theme` 与 `data-bs-theme`，实现 CSS 变量主题与 Bootstrap 5.3 暗色模式联动。
- **CSRF 注入**：`csrf.js` 从 `<meta name="csrf-token">` 读取令牌，自动为 fetch、XMLHttpRequest、原生 POST 表单注入 CSRF 令牌。
- **通用工具函数**：`common.js` 提供动画降级、事件绑定、图表初始化等公共交互能力。

## 模块职责

### 1. 控制台启动与兜底

`base_console.html` 是控制台体系的基础布局模板，包含：

- 左侧固定侧边栏 + 顶栏 + 内容区；
- 页面头部内联主题引导脚本，在渲染前读取 `localStorage` 或系统偏好，防止跨页闪烁（FOUC）；
- 头部的 `boot-core` 内联脚本，提供：

```js
window.__safeLocal = { get, set, remove }
```

当 `localStorage` 不可用时（如 WebView、严格隐私模式），自动降级为内存对象，绝不抛出异常。

同时注册全局 `error` 与 `unhandledrejection` 监听器，将异常显示为右上角 `bootError` 浮层，并打印到 `console.error`，避免白屏静默。

`console_boot.js` 是同一逻辑的外置版本，供三个基础布局页面共享使用；`base_console.html` 将其内联，减少首屏外部请求。

### 2. 深色主题

`console_theme.js` 实现亮/暗主题切换：

- 持久化 key 为 `console-theme`；
- 初值优先级：`localStorage` > 系统 `prefers-color-scheme` > 默认亮色；
- 切换时同时设置：

```js
document.documentElement.setAttribute('data-theme', theme);
document.documentElement.setAttribute('data-bs-theme', theme);
```

`data-theme` 驱动项目自定义的 CSS 变量令牌，`data-bs-theme` 驱动 Bootstrap 5.3 原生暗色模式，两者双轨同步。

任何带有 `data-console-theme-toggle` 属性的按钮都会自动绑定切换逻辑，并更新月亮/太阳图标的可见性与 `aria-pressed` 状态。

### 3. CSRF 注入

`csrf.js` 是前端 CSRF 全局防护层，负责三件事：

1. **fetch 自动注入**：对同源写请求（POST/PUT/PATCH/DELETE）自动添加 `X-CSRF-Token` 头；
2. **XHR 自动注入**：patch `XMLHttpRequest.prototype.open` 与 `send`，在写请求发送时补带头；
3. **POST 表单自动补 token**：为所有 `method=POST` 的原生表单动态追加隐藏字段 `csrf_token`，避免逐一改造模板。

令牌来源是页面头部：

```html
<meta name="csrf-token" content="{{ csrf_token() }}">
```

### 4. 通用工具函数

`common.js` 是学生活动管理系统的公共 JavaScript，提供：

- `anime.js` 缺失时的 CSS 过渡降级实现；
- 活动/成果筛选、标签页切换、文件上传事件绑定；
- 带 `data-validate` 的表单提交拦截（排除登录表单）；
- ECharts 饼图/折线图初始化；
- 仪表板统计数字动画。

其中仍保留部分演示用的静态活动/成果数据，迁移到真实后端时应由服务端渲染或 `/api` 异步数据替代。

## 调用链与装配顺序

```mermaid
flowchart TD
    REQ[浏览器请求控制台页] --> TPL[base_console.html 渲染]
    TPL --> THEME[内联主题引导<br/>读取 localStorage console-theme / 系统偏好]
    THEME --> ATTR[设置 html[data-theme] 与 html[data-bs-theme]]
    TPL --> META[渲染 meta[name=csrf-token]]
    TPL --> BOOT[内联 boot-core<br/>__safeLocal + error/unhandledrejection 捕获]
    TPL --> LOAD[加载 console_tokens.css / bootstrap / bootstrap-icons]
    LOAD --> JS1[console_theme.js 绑定主题切换与侧栏折叠]
    LOAD --> JS2[csrf.js 注入 fetch/XHR/POST 表单]
    LOAD --> JS3[console_boot.js 三基类共享兜底]
    LOAD --> JS4[common.js 通用交互工具]
```

图的关键节点：

- **内联主题引导**在 CSS 和外部 JS 之前执行，保证首帧即处于正确主题；
- **内联 boot-core**不依赖外部资源，即使后续脚本加载失败，也能捕获异常；
- **csrf.js**在 DOM 解析时读取 meta 令牌；若页面尚在加载，则等待 `DOMContentLoaded` 再处理表单。

## CSRF 注入流程

```mermaid
sequenceDiagram
    participant Page as 浏览器页面
    participant Fetch as window.fetch
    participant XHR as XMLHttpRequest
    participant Form as HTML form

    Note over Page: csrf.js 从 meta[name=csrf-token] 读取 token
    Page->>Fetch: fetch('/api/submit', { method: 'POST' })
    Note over Fetch: 同源 + 写方法 ⇒ 自动注入 X-CSRF-Token 头
    Page->>XHR: xhr.open('POST', '/api/submit'); xhr.send()
    Note over XHR: open 记录 _csrfWrite<br/>send 时若未设置过 X-CSRF-Token 则自动补头
    Page->>Form: 用户提交 method=POST 表单
    Note over Form: DOMContentLoaded 时已注入 hidden csrf_token
```

要点：

- 只有同源写请求才注入，跨域请求不泄露令牌；
- 如果调用方已显式设置 `X-CSRF-Token`，XHR 分支不会重复注入；
- 如果传入的是 `Request` 对象，fetch patch 会重建 `init`，并保留 method 与 body。

## 关键状态

| 状态 | 位置 | 说明 |
|---|---|---|
| `__safeLocal` | `window` | 安全 localStorage 包装；不可用时降级为内存对象 |
| `console-theme` | localStorage | 主题持久化 key，只允许 `dark` / `light` |
| `data-theme` / `data-bs-theme` | `<html>` | 双轨主题状态 |
| `meta[name=csrf-token]` | `<head>` | 全站 CSRF 令牌来源 |
| `_csrfWrite` | XHR 实例 | 当前请求是否为同源写请求 |
| `_csrfSent` | XHR 实例 | 是否已手动设置过 `X-CSRF-Token` 头 |
| `input[name=csrf_token]` | DOM 表单 | POST 表单动态追加的隐藏 CSRF 字段 |

## 边界条件

- **localStorage 不可用**：`__safeLocal` 降级为内存存储，`get/set/remove` 都不会抛异常。
- **模板没有 CSRF meta**：`csrf.js` 直接 `return`，不执行任何 patch，保证不破坏旧页面。
- **跨域请求**：只有同源请求才注入 `X-CSRF-Token`，避免令牌跨域泄露。
- **请求头已存在**：XHR 分支通过 `_csrfSent` 判断，避免重复注入。
- **表单已有 csrf_token**：`injectForms` 跳过已包含 `input[name=csrf_token]` 的表单。
- **白屏检测误报**：4 秒后仅当页面几乎没有文本且不存在 `.console-shell`、`.portal-shell`、`#app`、`nav`、`main`、`.container` 时才提示未渲染，兼容旧体系页面。
- **错误浮层安全**：消息会替换 `<` 为 `&lt;`，避免异常信息直接注入 HTML。

## 扩展点

- **CSRF 防护**：新区块只要沿用 `base_console.html` 或引入 `csrf.js`，即可自动获得 fetch / XHR / 原生表单三层防护，无需逐个模板手动添加隐藏字段。
- **主题切换**：任何按钮只要添加 `data-console-theme-toggle` 属性并包含 `.theme-icon-moon` / `.theme-icon-sun` 图标，即可自动接入主题切换；切换时会派发 `console-theme-changed` 自定义事件，便于图表或第三方组件联动。
- **启动兜底**：`__safeLocal` 暴露在 `window` 上，其他脚本可直接复用，避免重复编写 storage 安全逻辑。
- **侧边栏折叠**：任意 `.console-sidebar .sb-group-title` 点击后自动切换所属 `.sb-group` 的 `collapsed` 状态，新增分组无需额外注册。
- **基类迁移**：`base_console.html` 的块结构对齐 `base.html`（`title` / `extra_head` / `content` / `extra_scripts`），旧页面可平滑迁移到控制台体系。
