## 3. 偏差与教训（按价值排序）

1. **Jinja dict 键名陷阱**：`current_user` 是 context processor 注入的 dict，键为 `name` 非 `username`——原 `{{ username }}` 靠 Jinja Undefined 静默成空白；头像 `.username[:1]` 切片抛 500（Undefined 不可切片）。教训：**模板访问对象属性前先核对注入结构**。
2. **SQL 三值逻辑**：`WHERE NOT (granted_role='教师')` 会把 `granted_role IS NULL` 行滤掉（NULL 不确定），需显式 `IS NULL OR <> '教师'`。教训：**ANY NOT 表达式对可空列必须显式 NULL 分支**。
3. **统计口径争论本质是缺细分**：先统一到管理口径 173 被"总数197"质疑 → 改回全量 + 细分（173 管理/24 教师）并用注脚化解。教训：**数字冲突时给"总数=组成之和"的可见分解，而非二选一**。
4. **JS 运行时 TypeError（`const list` 后又赋值）**：`node --check` 查不出语义错误，靠 console 定位。教训：**手写 JS 除语法检查外必须跑通冒烟**。
5. **端口残留旧进程**：多进程同听 5001 致请求随机路由旧代码、接口 404 假象。教训：**冒烟前 netstat 查监听数、杀净再起**。
6. **CSS 缓存致"改后不见"**：用户侧旧 `console_tokens.css` 与新版混用白底白字。修复=资源加 `?v=2` cache-bust（开发期）。教训：**静态资源改版要带版本串/强刷验证**。
7. **"死模板"调查比直接改更重要**：`review/list.html` 无任何引用者（review_list 只 302→results.html 工作台）——若照字面只改它等于空改。教训：**改造前先确认模板真实渲染链（grep render_template/include 引用）**。
8. **Bootstrap 组件双重样式**：`dropdown-toggle` 自带 `::after` 三角与自定义 chevron 重复 → CSS 隐藏伪元素。
9. **门户评估推翻了主观判"不可行"**：原假设"无 node_modules=门户换壳不可行"；实测 Tailwind 编译产物已在 static（换壳≠重编译）且 node/npm 本机可用 → P2-B 分 A（公共层，已做）/B（重编译 dark:，待做）。教训：**大工程先做 5 分钟实证评估再下结论**。
10. **`data_export` 存量 500**：后端调废弃 API + 前端对 DataFrame 直接 if——路由扫描（test client 全量 GET）暴露两处，修复后门户 15 路由全绿。教训：**面向"无渲染错误"的验收要用全路由扫描而非抽查**。
