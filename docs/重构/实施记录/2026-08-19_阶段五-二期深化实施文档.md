- **测试视图化**：schemas.py 新增三视图 DDL（与迁移单一来源）；`test_cache_targeted` 改视图 fixture 保读路径；`test_alembic_0002` 迁移往返回归（2 用例）；删 `test_manager_restrictions`（语义由 UserRepository 白名单测试覆盖）

- **重大教训（本阶段最深）**：**alembic env.py 的 online 模式绕过 `_db_url()` 直接 `build_engine()`（默认 config 路径）→ `-x db=` 只对 offline 生效，测试迁移误跑生产库**，导致真实库被反复 upgrade/downgrade、备份库被误改（DROP VIEW 测试）。已修复：online 模式经 `_resolve_db_path()`（环境变量 `ALEMBIC_DB` > `-x` > config），并新增 `test_alembic_0002` 护栏 + 备份纪律（迁移前必须 cp 备份）
- 次要教训：SQLite 视图化前必须清 FK 引用（DROP 被引用表失败）；downgrade 回拷须 COALESCE（users 允许 NULL 而旧表 NOT NULL——真实数据漂移信号）；`python -m alembic` 的 `-c/-x` 须置于子命令前

### 2.8 M1 后半：类型规范全表重建（③③，M1 后半收官）
- **迁移 0003**（`2174336`）：18 表短字段 TEXT → VARCHAR(N)（严格映射表 2026-08-19 §2 清单）；长文本保留 TEXT（§3 列表）；**存量数据最大长度实测全部 < VARCHAR 目标**（无截断风险）后才落地
- **保留完整性**：pending.is_valid 生成列（VIRTUAL，真实库已存在则去重）、42 个索引/唯一约束（DROP 前抓取、RENAME 后重建）、三视图（DROP 被引用表前先删视图、完成后原样重建）、关联表 FK→users、行数校验（每表 INSERT SELECT 后断言）
- **双写收尾**（`4667999`）：`users_sync` 退役写桥函数 `sync_user_row`/`insert_user_row`（视图化后已无调用点），仅保留 `to_users_id` 业务号→users.id 桥接；TestDualWrite 随退役删除
- **GUI 冒烟**（playwright）：类型重建后 admin 登录 → 成果 173 条/学生 1793 条/审核页 pending——应用读写链路全通
- **教训（正则替换要严谨）**：`\S+` 贪婪会吞掉行内逗号（`col TEXT, next` 被替换成 `col VARCHAR(n) next` 致语法错）——类型匹配须用 `\w+`；引号表名（`CREATE TABLE "pending_achievements"`）须正则兼容；SQLite DROP 被视图引用表会让视图**永久失效**（非惰性恢复）——须先删视图后重建
- **教训（迁移健壮性）**：迁移须容忍"覆盖字段缺失/表缺失"（模拟库可只建部分表），未定位列跳过而非报错；head 推进后旧迁移测试须显式指定目标 rev（0002 测试 `upgrade 0002_...` 而非 head）
