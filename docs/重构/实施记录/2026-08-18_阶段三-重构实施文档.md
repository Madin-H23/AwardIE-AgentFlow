## 2. 阶段三关键决策

| 决策 | 理由 |
| --- | --- |
| users 合并采用渐进三批而非一步到位 | 8.4 纪律：每批独立可测可回退；认证切换即刻兑现核心收益 |
| auto 模式流式选节点级 progress 而非 token 级 | 多智能体场景用户要的是"过程可见"；token 级由 qa 单独覆盖 |
| run_stream 末尾 invoke 兜底（双跑） | LangGraph updates 不回传终态；单机成本可接受，诚实标注 |
| 动作 5（复核查看）暂缓 | 查看动作无决策价值，留痕徒增噪声 |

## 3. 偏差与教训（全程如实记录）

1. settings.json 同名键陷阱：新配置插入顶层被原键覆盖（并入原对象解决）
2. monkeypatch 命名空间：`from X import Y` 后须 patch 消费方命名空间
3. users 测试 DDL 须真实反射（best-effort 函数吞列缺失错误）
4. 前端 JS 改前必核实辅助函数存在（scrollChat 不存在即抓即改）
5. 既有测试随行为切换同步更新（qa 流式后 SSE 序列用例改 tools 模式）
