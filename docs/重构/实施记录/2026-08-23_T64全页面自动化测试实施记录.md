# T64 全页面自动化测试体系实施记录（2026-08-23）

> 目标：全站页面路由的自动化冒烟覆盖（清单驱动两层 + CI 种子库 + 防腐自检）。
> 终验：**743 passed + 157 skipped + 0 failed**；页面路由覆盖率 **75/77（97%）**；
> 无库模拟 **115 passed 非 skip** 且真实库零接触；gui_smoke 17/17 不回归。

## 1. 架构

- **清单唯一事实源** `tests/fixtures/page_inventory.py`：
  PAGES 四元组 (role/url/expected/anchor) 正例 + EXEMPT 单一豁免表
  （type=not_page JSON·导出·重定向端点 / bad_page 存量坏页），带理由。
- **CI 种子库** `tests/fixtures/seeded_db.py`：
  full_schema.sql（scripts/dump_schema.py 反射导出，77 对象）建 tmp 库 + 最小数据集
  （users 三角色+awards 三态含教师证书+pending 三态+laboratories 系+各成果表各 1）。
- **DATABASE_PATH 双路径 patch**：app.config（多数路由 current_app.config 读）
  + get_config() 配置类类属性（auth.py 登录限流/verify_user 直读）——缺一会静默查真实库。
- **三重隔离复位**：reset_app_context()（backend 全局单例）+ app.utils 与
  app.utils_module 双命名空间 _managers.clear()（importlib 双加载缓存）+
  teardown 还原配置类属性。三者任缺其一即"冒烟静默查真库"事故。
- **防腐 meta-test**：url_map 扫描 GET+render_template 路由（_norm 归一
  werkzeug <int:x> 与清单 {x} 两形态），断言全部登记于清单或豁免表；
  豁免表漂移检查；PAGES 重复检查。

## 2. 实测数字

- 页面路由覆盖率：**75/77 = 97%**（豁免：/student/activities 存量坏页、
  achievement-review 三参子路由由具体形态正例覆盖）。
- 冒烟执行：种子库上 118 passed + 7 skipped（labs 深链 anon 公开设计跳过登录维度）。
- 无库模拟：真实库移走后冒烟 **115 passed 非 skip**、真实库文件未重建（零接触佐证）。
- 全量回归：743 passed + 157 skipped + 0 failed。

## 3. 过程中发现并处理的问题

1. **存量坏页 /student/activities**：activities_ref.html 模板不存在致 500
   （遗留"参考风格假数据页"）→ EXEMPT bad_page 登记，待修复后移入 PAGES。
2. **测试顺序污染链（本体系的价值实证）**：全量跑时 test_main_services 先清空真实库，
   smoke 种子 fixture 若不复位 _managers 缓存，深链页将静默查真实库——
   首轮全量 19 个深链失败由此暴露，修复=双命名空间缓存清理+teardown 复位。
3. **teacher/achievement-review 是智能路由**：单一类型有数据时 302 直达详情，
   空/多类型渲染列表——断言按 (200,302) 兼容。
4. seed 数据须对齐 full_schema 的 NOT NULL 约束与列名（patent_name/software_name/
   other_files.file_name 等与直觉不同的列名逐一修正）。

## 4. 使用与维护

- 新增页面路由：在 page_inventory.PAGES 加一行（或 EXEMPT 登记理由），否则 meta 红。
- 迁移变更表结构后：重跑 `python scripts/dump_schema.py` 刷新 full_schema.sql。
- 回归约定：核心链路改动前后跑 gui_smoke（见 P1 实施记录 §3）+ 本清单冒烟随 CI 自动执行。
