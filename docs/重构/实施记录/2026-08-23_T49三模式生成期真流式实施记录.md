# T49 三模式生成期真流式 实施记录（2026-08-23 开工）

## §0 流式改造技术定案（步骤0 探针实测，langgraph 1.2.11 / langchain 1.3.15 / langgraph-prebuilt 1.1.0）

### 0.1 多模式流支持 ✅
`graph.stream(..., stream_mode=["updates","messages","values"])` 原生支持，
事件为 `(mode, payload)` 元组交错产出。三通道语义：
- `updates`：每 super-step 后 `{node: patch}`——progress 节点事件来源；
- `messages`：`(AIMessageChunk, metadata)`——**metadata.langgraph_node 即白名单依据**
  （探针②实测节点内 LLM 流的 chunk 携带 `langgraph_node='qa'`、`langgraph_step=1`）；
- `values`：每 super-step 后全量 state，**末次 values 即终态** → 双跑消灭的终态来源。

### 0.2 tools 侧过滤规则（create_agent 工具轮次实测）
messages 通道事件序列（工具轮次场景）：
```
tool_call_chunk(node=model, content='')   ← 决策轮，无文本
ToolMessage                               ← 工具执行结果，非答案
ai_content × N (node=model, content=增量) ← 最终答案逐 token
ai_empty                                  ← 收尾空块
```
**过滤规则：仅透出「content 非空的 AIMessageChunk」为 delta；
tool_call_chunk / ToolMessage / 空块一律静默。**

### 0.3 auto 侧白名单与合并策略
- 答案白名单 = **`metadata.langgraph_node == 'qa'`**（auto 的 answer 取自
  终态 qa_context.answer，review/extraction 路径为固定文案无 LLM 流）；
- supervisor/路由决策等其余节点的 messages 一律不透出（附专项单测）；
- progress 事件继续走 updates 通道（中文标签映射不变）。

### 0.4 终态获取（消灭双跑）
终态从 **values 通道末次**获取；仅当 values 通道异常中断时保留 invoke 兜底
（兜底触发将记 warning 并在实施记录量化）。

### 0.5 降级口径
- 工具执行回合天然无 token：SSE 静默（前端已有进度提示）；
- `_answer_pieces` 保留为流异常时的降级路径（代码不删，现有 5 例兼容测试保留）；
- create_agent 需模型实现 bind_tools（真实 ChatModel 天然满足）；
- tool_call_chunks.args 必须为 JSON 字符串片段（str(dict) 单引号会致工具解析失败——探针踩坑实录）。

### 0.6 多轮输出语义定案（实测补充）
真实模型常「先解说→调工具→再作答」：各轮 AIMessageChunk 均已流式呈现给用户，
故 **done.output ≡ delta 拼接（所见即所得）**；仅零增量降级路径才回退
_extract_final_answer(终态末条)。护栏测试的一致性断言据此成立。
