## 3. 出站直连（代理开/关均正常访问）

**根因**：openai/httpx 默认 `trust_env=True` 读环境变量 `HTTP_PROXY=127.0.0.1:3067`；本机代理软件未启动时该端口无监听 → LLM 请求全被发给死代理 → `Connection error`（multi_agent 层表现为「工作流未产生回答」）。开关代理行为不一致。

**修复（双保险）**：
- `run.py` 启动即 `os.environ.pop("HTTP_PROXY"/"HTTPS_PROXY"/"ALL_PROXY")` + `NO_PROXY=*`（覆盖应用内所有出站：LLM/OCR/RAG）；
- `llm_adapter.build_chat_model` 注入 `http_client=httpx.Client(trust_env=False)`（非 run.py 启动如 gunicorn 亦直连，extra_kwargs 可覆盖）。

**实测**：清代理直连 api.deepseek.com 调用成功 + playwright 在代理关闭态页面提问正常。**边界**：若部署环境「必须经代理才能出外网」（墙内），直连会失败——届时需改为"代理可用才走、否则直连"的自动降级。

### 4.1 V2 外观恢复（fc66e9a）

### 4.2 三模式输出 markdown 排版（35a9840）
根因：LLM 答案 markdown 源码（`###`/`1. `列表/`|表格|`/`**加粗**`）仅 escapeHtml 原文展示。
修复：前端 `renderMarkdown`——
- **安全**：先 `escapeHtml` 再渲染，仅白名单标签（h2-h5/p/ul/ol/li/strong/em/code/pre/blockquote/table/a），`<script>`/`<img onerror>` 实测转义为纯文本（对齐 P0-10 教训）；
- **能力**：全局逐行状态机，支持跨空行连续有序/无序列表、表格段聚合、代码块占位、标题/引用/链接；
- **接入**：`appendMessage` 与 SSE `done` 终态（打字机中间态保持纯文本，完成才渲染防闪烁）；
- CSS 排版（标题/列表/表格边框/引用/行内码）在 `_chat_head.html`，亮暗双主题。

### 4.3 三模式独立对话窗口（68f41b2）
根因：三模式切换只更新 `currentMode`，消息区共享一份历史。
修复：前端 `modeHistories` 按模式 innerHTML 快照，`renderModePanel` 切窗时先存当前窗口→恢复目标窗口（空窗种子 `MODE_WELCOME` 专属欢迎语）；生成中（sendBtn.disabled）禁止切窗防串窗；清空只当窗；初始化即 `renderModePanel('auto')`（顺带修复最初模式面板空白）。纯前端，无服务端持久化（刷新回到初始）。

### 4.4 multi_agent/single_agent 全流式（982eb1d）
现状：仅 rag_qa 生成期真流式；auto/tools 整段 delta。
修复：`chat.py` 新增 `_answer_pieces(text)`（按 token 分片，呈现层），两条路径（auto 分支 + _dispatch 回退）把整段 delta 改逐片下发；前端 delta 通用消费零改动，done 仍回传完整答案排版；**零重复 LLM 调用、内容与 done 完全一致**。
实测 SSE：tools=138 片、auto=进度3+8 片，均 done 收尾。
**诚实边界**：auto/tools 是"答案就绪后流式分片呈现"，非生成期并行（后端由 workflow/create_agent 整体生成不可中断）；若要求生成期真流式需改 LangGraph 节点/tools agent，留作后续。

## 5. 5001 端口澄清与三端并行测试手法

- **5001 可用**（实测 200/17ms）：历史上"被网络层拦截"为误判（更可能是残留进程/服务未起净或代理变量干扰 curl 的假象）。已从 5002 切回默认 5001。
