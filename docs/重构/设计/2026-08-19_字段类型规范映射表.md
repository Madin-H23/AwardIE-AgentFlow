# 数据库字段类型规范映射表（TEXT → VARCHAR 规划）

| 项目 | 内容 |
| --- | --- |
| **编写日期** | 2026-08-19 |
| **依据** | 全库实测字段扫描（21 张表 100+ 短字段误用 TEXT）；企业标准：短字段须 VARCHAR(N) 表达长度语义，长文本保留 TEXT |
| **执行方式** | 与 **M1 后半（ORM 化）** 合并——SQLAlchemy 模型按本表定义，Flask-Migrate 首次迁移=全表重建时一次性落地（G6 建新替旧），不单独重建避免重复劳动 |
| **SQLite 说明** | 当前动态类型无行为差异；本规范为**可移植性/语义明确**（未来 MySQL/PG 迁移、长度隐式校验） |

## 1. 类型长度规划总则

| 类别 | 建议类型 | 说明 |
| --- | --- | --- |
| 标识/编码 | VARCHAR(50) | login_code/student_id/teacher_id/username/session_id 等 |
| 姓名/角色/短枚举 | VARCHAR(20-50) | name/title/role/submitter_type/status/action_type 等 |
| 联系方式 | VARCHAR(20) | phone |
| 凭证哈希 | VARCHAR(255) | password_hash |
| 文件路径/哈希 | VARCHAR(500) | file_path/image_path/file_hash/certificate_file 等 |
| 名称/奖项信息 | VARCHAR(100-200) | competition_name/winner_name/award_level/issuer 等 |
| 长文本（保留 TEXT） | TEXT | ocr_text/llm_response/achievement_data/validation_result/ext_info/description/skills/remark/comment 等 |

## 4. 执行注意事项（ORM 化时）

1. **生成列保留**：pending_achievements.is_valid（VIRTUAL）在重建时须按原 DDL 重建（`GENERATED ALWAYS AS ... VIRTUAL`）
2. **索引/唯一约束保留**：awards.uk_awards_image_hash、idx_pending_is_valid、关联表 PK/FK、各 submitter 索引
3. **数据对账**：重建后行数一致、生成列推导一致、submitter_id 全落 users.id（M1 已统一）
4. **迁移幂等**：脚本可重放；备份 → 建新表 → INSERT SELECT → 校验 → DROP 旧表（G6）
5. **长度校验**：VARCHAR(N) 落地前先查存量数据最大长度，避免超长截断（如 name 最长可能 >50，需实测调整）
