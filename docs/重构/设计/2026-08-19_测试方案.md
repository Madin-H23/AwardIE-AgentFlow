## 1. 测试目标与原则

### 1.1 总目标

> **"改坏有感知，回归有护栏，上线有证据。"**

对应 SRS 7.5 根因复盘 R3（无测试防护网）的制度补丁——历史教训表明，大量问题（状态机绕过 P1-14、重复入库 P0-9）若有最小回归用例早已暴露。

### 1.2 核心原则

| 原则 | 内容 | 来源 |
| --- | --- | --- |
| **零 mock 等价测法** | 优先使用真实组件（真实 SQLite、真实 OCR/LLM provider 调用路径），仅在"调用真实外部 API 会产生费用或不可控"时才用 monkeypatch 替换消费者方命名空间。禁止用 mock 对象伪造业务逻辑行为——mock 只替换 I/O 边界，不替换业务断言 | 阶段一 §3 教训 5（三次测试返工换来的纪律） |
| **DB 变更后必须起真实 app 冒烟** | 任何 DDL/迁移/ORM 模型变更后，除 DB 层断言外，必须启动真实 Flask app 跑冒烟（首页 200 / 登录 200 / 受保护页 302 / 无 token POST 400），防 dataclass 解包炸毁等"DB 层不可见"的存量炸弹 | 阶段一 §0 热修（version 列炸毁 `PendingAchievement(**data)`） |
| **测试环境自持** | 测试不依赖宿主环境变量——`dotenv` 在收集期注入 `FLASK_ENV` 已造成污染；测试 fixture 自建临时库、自控配置注入，与生产环境完全隔离 | 阶段一 §3 教训 2、上下文交接 §5 教训 6 |
| **每修复一个 P 编号同步补一个回归测试** | 执行纪律：每个修复的 P0/P1/P2 问题，必须同步编写至少一个回归测试用例，锁定修复行为，防回归 | SRS v1.8 修订记录 / 7.5 R3 制度补丁 |
| **批量改码必须逐文件 diff 全量核对** | 批量替换（正则/脚本）完成后，必须逐文件 diff 全量核对，不可只看测试绿即放行——L3 事故 38 处中 20+ 是残留真 bug | 阶段五 §2.1 T23 教训升华 |

### 1.3 测试金字塔

```
           ╱ E2E ╲          ← 少量，高价值（GUI 冒烟、核心链路）
          ╱───────╲
         ╱ 集成测试 ╲        ← 中量，跨模块协作验证
        ╱───────────╲
       ╱   单元测试   ╲      ← 大量，快速隔离反馈
      ╱───────────────╲
```

本项目当前以**单元测试为主（占 ~85%）**，集成测试为辅（~13%），E2E 通过 Playwright GUI 冒烟补充（~2%）。后续迭代逐步提升集成与 E2E 比重。

## 2. 测试分层策略

### 2.1 单元测试（Unit Tests）

**目标**：验证单个函数/类/模块的行为正确性，毫秒级反馈。

| 维度 | 内容 |
| --- | --- |
| **工具** | pytest + pytest-cov |
| **目录** | `tests/unit/`（当前 40+ 文件） |
| **隔离方式** | `tmp_path` 临时 SQLite 库 + `monkeypatch` 替换外部调用边界 |
| **命名规范** | `test_<被测模块>_<行为>.py`（如 `test_db_connection.py`、`test_audit_logger.py`） |
| **fixture 策略** | `conftest.py` 提供 `temp_db`（建表+种子数据）；`tests/fixtures/schemas.py` 提供 DDL 常量（与真实库反射一致）；ORM 测试通过 `reset_engine()` 注入临时 engine |
| **断言风格** | 显式 `assert` + `pytest.raises`，不使用 unittest 风格 |
| **速度要求** | 全量单元测试 ≤ 30s |

**单元测试覆盖模块**：

| 模块 | 对应测试文件 | 覆盖重点 |
| --- | --- | --- |
| `backend/utils/db_connection` | `test_db_connection.py` | 三契约（FK/WAL/busy_timeout）、row_factory、持久化 |
| `backend/utils/audit_logger` | `test_audit_logger.py`、`test_audit_complete.py` | append-only、不阻塞、11 种动作、change_detail diff |
| `backend/utils/circuit_breaker` | `test_circuit_breaker.py` | 三态机、双维度（LLM/OCR）、降级 |
| `backend/utils/app_error` | `test_app_error.py` | 统一包装 `{trace_id,code,message,data}`、Retry-After |
| `backend/utils/idempotency` | `test_idempotency.py` | SQLite 共享表、防双击 |
| `backend/utils/metrics` | `test_metrics_backup.py` | Prometheus 指标采集、best-effort 降级 |
| `backend/utils/seed` | `test_seed.py` | 84 白名单、默认管理员 |
| `backend/utils/users_sync` | `test_users_merge.py`、`test_users_ref_rewrite.py` | 三表合并、双写同步、to_users_id 映射 |
| `backend/orm/base` | `test_orm_base.py` | engine 工厂复用、session 单例、reset_engine 测试钩子 |
| `backend/agent/*` | `test_workflow*.py`、`test_llm_adapter.py`、`test_rag.py`、`test_tools.py` | 工作流单例、流式 SSE、RAG 检索、LLM 适配器 |
| `backend/agent/decision` | `test_stage3_batchA.py` | 决策逻辑公共模块 |
| ORM 写路径 | `test_user_repo_write.py`、`test_pending_write_orm.py`、`test_admin_write_to_users.py` | 幂等 upsert、改密、审核写入切 ORM |
| 迁移 | `test_alembic_0002.py`、`test_alembic_0003.py`、`test_alembic_0004.py` | 迁移往返回归、FK 改指、类型重建、teacher FK 补漏 |
| 登录限流 | `test_login_guard.py`、`test_login_rate_limit.py` | P2-25 落库版账号/IP 锁定、auth 登录集成 |
| 前端组件 | `test_frontend_timeline.py`、`test_timeline_ui.py`、`test_reject_button_embedding.py` | 时间线渲染、驳回按钮嵌入 |
| SSE 流 | `test_sse_stream.py`、`test_true_stream.py` | 事件协议、逐 token 增量 |

### 2.2 集成测试（Integration Tests）

**目标**：验证跨模块协作、真实数据流、外部依赖边界。

| 维度 | 内容 |
| --- | --- |
| **工具** | pytest + 真实 SQLite 临时库（不 mock 数据库） |
| **目录** | `tests/integration/`、`tests/extract/integration/` |
| **策略** | 数据库操作用真实 SQLite（WAL 模式），外部 API（百度 OCR / DeepSeek LLM）用 monkeypatch 替换为固定响应——仅替换 I/O 边界，不替换业务逻辑 |
| **速度要求** | 全量集成测试 ≤ 120s |

**集成测试场景**：

| 场景 | 文件 | 验证内容 |
| --- | --- | --- |
| Agent 全链路 | `integration/agent/test_agent_integration.py` | 提交→抽取→AI 审核→入库多模块协作 |
| RAG 检索 | `integration/agent/test_rag_integration.py` | Chroma 索引→检索→阈值过滤→MMR 排序 |
| 抽取框架 | `extract/integration/test_*.py` | OCR→模板匹配→LLM 提取→校验 |
| 数据分析 | `integration/test_data_analysis.py` | 贡献度统计、实验室维度查询（须补关联表 fixture） |

### 2.3 端到端测试（E2E / Smoke Tests）

**目标**：验证核心业务链路在真实部署下的可用性。

| 维度 | 内容 |
| --- | --- |
| **工具** | Playwright（GUI 冒烟） + 手动验证（DoD 9.1） |
| **策略** | 启动真实 Flask app + 真实 SQLite 库，模拟真实用户操作 |
| **执行时机** | 每个 stage tag 打点前、迁移变更后、上线前 |

**E2E 冒烟矩阵**：

| 角色 | 操作 | 预期 | 执行方式 |
| --- | --- | --- | --- |
| 管理员 | 登录→学生列表→教师列表→审核页 | 数据可见、console 无报错 | Playwright |
| 学生 | 登录→个人中心→资料页 | 正常渲染 | Playwright |
| 教师 | 登录→审核页→pending 数据 | 数据可见 | Playwright |
| 未认证 | 访问受保护路由 | 302 重定向 | pytest |
| 无 token | POST 请求 | 400 拒绝 | pytest |
| 核心链路 | 上传→OCR→LLM 抽取→AI 审核→教师复核→入库 | 全流程跑通 | 手动/半自动 |

### 2.4 安全测试（Security Tests）

**目标**：验证安全基线不可回退。

| 维度 | 内容 |

| **策略** | 独立于功能测试，专测安全属性（非业务行为） |

| 文件 | 验证内容 | 对应问题 |

**目标**：迁移/重构后验证前端读写链路无回归。

| 维度 | 内容 |
| --- | --- |
| **工具** | Playwright（headless browser） |

### 3.3 覆盖率策略

1. **CI 硬门禁只覆盖核心模块**——当前 12 个模块，`--cov-fail-under=70`。新增核心模块须同步加入 `--cov=` 列表
2. **全量覆盖率不设硬门禁**——存量代码覆盖率提升是渐进过程（T24），不可一次性拉高门禁致 CI 长期红
3. **新增代码必须覆盖**——新写的功能模块必须同步写测试，PR 审查时检查覆盖率不回退
4. **覆盖率≠质量**——100% 覆盖率不代表测试有效；关注断言深度和边界覆盖

## 5. 测试环境隔离原则

### 5.1 核心原则

> **测试不依赖宿主环境，不污染生产数据，不依赖外部网络。**

### 5.2 隔离规则

| 规则 | 内容 | 教训来源 |
| --- | --- | --- |
| **R1 临时库隔离** | 每个测试用例使用 `tmp_path` 创建独立临时 SQLite 库，不复用生产库文件。仓库不跟踪 `*.db`，CI 环境无真实库可反射 | 阶段三 §3 教训 3（users 测试 DDL 须真实反射） |
| **R2 环境变量隔离** | 测试不依赖宿主 `FLASK_ENV` / `DATABASE_PATH` 等环境变量。`dotenv` 在收集期注入 `FLASK_ENV` 已造成污染——fixture 显式设置测试环境 | 阶段一 §3 教训 2 |
| **R3 配置注入隔离** | `load_config` 会读取真实 `apikey.json` 并注入真实 API key，monkeypatch env 变量无效（文件读取覆盖 env patch）。涉及配置的测试须 patch `load_config` 函数本身或注入临时配置文件 | T21 修复（test_llm_adapter fixture 隔离 apikey.json） |
| **R4 fixture 独立性** | 测试 fixture 之间不共享状态。注册表单例跨用例污染（circuit_breaker → SSE）已发生过——使用 `@pytest.fixture()`（函数级）而非 `@pytest.fixture(scope="session")`，除非显式需要共享只读状态 | 阶段二 §2 教训（测试隔离 ×3） |
| **R5 DDL 同步** | `tests/fixtures/schemas.py` 中的 DDL 必须与真实库表结构一致。表结构变更时须同步本文件并加对应测试——不可依赖运行时反射（CI 环境无真实库） | `schemas.py` 文件头注释 |
| **R6 ORM engine 注入** | ORM 测试通过 `reset_engine(test_engine)` 注入临时 engine，不复用生产 engine。临时库须完整 DDL（列不全 ORM SELECT 误判） | 阶段五 §2.5 教训 |
| **R7 命名空间 patch** | `from X import Y` 后 monkeypatch 须 patch 消费方命名空间（`module_under_test.Y`），而非源模块（`X.Y`） | 阶段三 §3 教训 2 |
| **R8 测试 DDL 完整性** | 临时测试库须包含被测代码引用的全部表——`test_data_analysis` 曾因缺 4 张关联表（award_teacher_winners/award_supervisors/teachers/laboratories）而 `no such table` | T21 修复 |

    bug_id: str
