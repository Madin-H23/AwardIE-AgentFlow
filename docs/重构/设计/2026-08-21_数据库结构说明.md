## 3. 核心表

### 3.1 users（账号统一表，三表合并产物）
- `id INTEGER PK`：**全系统主键**（提交人/审核人/获奖者/实验室学生一律存 users.id）
- `login_code VARCHAR(50)`：业务号（学号/工号/admin）；`name`、`role`（student/teacher/admin）
- `password_hash VARCHAR(255)`（强随机+首登强制改密 `needs_password_change`）
- 其余：phone/qq/skills/major/grade/title/department/id_number/profile_is_public/user_activated
- 旧三表数据经 `old_user_map` 迁移映射（1832 对账一致）

### 3.2 pending_achievements（待审成果）
- `achievement_type`(award/patent/software/innovation/other)、`achievement_data`(TEXT JSON)、`validation_result`
- `submitter_type/submitter_id`：提交人（submitter_id=users.id）
- `status`：pending→submit→rejected/archived（approved 软归档保留 AI 结论）；`version` 乐观锁防并发
- `session_id`：批量导入会话；`file_hash/ocr_text/llm_response/ext_info`

### 3.3 awards（成果主表，197 条）
- 奖状核心字段：image_hash/certificate_id/competition_name_in_file/track/issuer/province/group_name/winner_name/supervisor_name/award_level/competition_level/date/year/edition/project_title/granted_role
- `competition_id` FK→competitions；`laboratory_id` FK→laboratories；`submitter_id`=users.id
- `is_abnormal` 标记异常；`ocr_result/llm_prompt/llm_response/extract_json/validation_result` 保留识别链路
- **入库来源**：审核通过 → `submit_to_main_db` 写入，返回自增 id（留痕动作 8 指向该 id）

### 3.4 achievement_audit_log（审核留痕，append-only）
- `achievement_id`：动作 6 及待审类存 **pending.id**；动作 8/12（入库/成果删除）存 **awards.id**
- `action_type` 枚举（CHECK 1-12）：1提交 2AI审核 3AI通过 4AI驳回 5教师复核 6审核通过 7驳回打回 8入库 9修改字段 10删除/放弃 11撤回 **12成果删除**
- `operator_id/operator_code/operator_name`：冗余快照（M1 后曾存 users.id，展示层按 id 或 login_code 双路解析"学号 姓名"）
- `operator_role`：1学生 2教师 3AI 4管理员；`trace_id`、`change_detail`(JSON)、`remark`
- `created_at`：**应用本地时间（中国时间）**（0007 起；旧 UTC 行已迁移 +8h）
- `is_redundant`：0009 去重标记（0=有效，1=同一成果重复删除留痕；查询默认过滤）
- 写入：`backend/utils/audit_logger.py`（best-effort，失败不阻塞主业务）

### 3.5 system_event_log（系统事件日志，阶段六 L1）
- `event_category`(ocr/llm/breaker/auth/upload/db/security/system)、`event_level`(debug..critical)
- `trace_id` 全链路、`operator_id/code`、`detail`(JSON)、`source_module/file/line`
- **注意：created_at 仍为 SQLite CURRENT_TIMESTAMP(UTC)**——与 audit 表基准不一致，清理/告警窗口逻辑依赖 UTC，展示需转换（待办：统一时间基准）

### 3.6 关联表
- 学生获奖：`award_student_winners(award_id, student_id)`（FK→users）
- 教师获奖：`award_teacher_winners(award_id, teacher_id)`
- 关联学生：`award_related_students(award_id, student_id)`；指导教师：`award_supervisors(award_id, teacher_id)`
- 实验室：`laboratories` + `laboratory_students/laboratory_assistants/laboratory_instructors/laboratory_images/laboratory_downloads`（students/teachers 关联指向 users.id）
- 其他成果：`patents`/`software_copyrights`/`other_files`（各 0-1 条，低活跃）；`innovation_projects`(20) + `innovation_project_students`

### 3.7 运维/支持表
- `competitions`(130)：白名单竞赛（white_list/watch_list）；`laboratories`(4)
- `templates`(20)：证书模板；`user_photos`(0)：头像（半成品冻结）
- `failed_logins`：账号 5 次/15 分 + IP 限流；`idempotency_keys`：批量审核防重
- `action_plans`：告警→行动计划（阶段六 L3）；`metrics_snapshot`：prometheus 指标归档
- `auto_archive_config`：自动归档配置；`review_logs`(1946)：旧留痕表（冻结只读，由 audit 接管）
- `old_user_map`(1832)：M1 用户迁移映射（旧 id→users.id）

## 4. 关键重构决策 / 约定

1. **三表合并**：students/teachers/admins 物理合并为 `users`，旧表转**只读视图**（查询兼容，不写）。
2. **主键语义统一**：所有 `submitter_id/reviewer_id/winner/teacher/laboratory` 关联一律 `users.id`；业务号经 `backend/utils/users_sync.py::to_users_id` 映射（认证分支保留业务号登录）。
3. **留痕操作人**：快照形态历史上有 users.id 与业务号两种，展示层 `AuditLogger.resolve_display_names` 按 id 或 login_code 双路解析。
4. **时间基准**：audit 已统一应用本地时间；system_event_log 仍 UTC（**待办**，改前须评估 90 天清理/每日 09:00 报告窗口逻辑）。
5. **审计表 append-only**：只 INSERT 不删改；数据订正用标记列（is_redundant）而非物理删。
6. **测试纪律**：CI 用 `tests/fixtures/schemas.py` 共享 DDL（与生产反射一致）；改表结构须同步测试 DDL + 跑 `_require_real_db` 守卫用例。
