## 1. 概览

| --- | --- |

## 9. 关键重构决策 / 约定

1. **三表合并**：students/teachers/admins 物理合并为 `users`，旧表转**只读视图**（查询兼容，不写）。
2. **主键语义统一**：所有 `submitter_id/reviewer_id/winner/teacher/laboratory` 关联一律 `users.id`；业务号经 `backend/utils/users_sync.py::to_users_id` 映射（认证分支保留业务号登录）。例外：`innovation_projects.student_leader_id` 为 VARCHAR(50) 文本业务号（历史遗留，成员明细走 innovation_project_students.student_id→users.id）。
3. **留痕操作人**：快照形态历史上有 users.id 与业务号两种，展示层 `AuditLogger.resolve_display_names` 按 id 或 login_code 双路解析。
4. **时间基准**：audit 已统一应用本地时间；**system_event_log 保持 UTC（2026-08-22 A4 评估定稿，T55 关闭）**——评估结论：①写入层 UTC 与 `log_scheduler._cleanup_capacity`/`_reopen_ignored` 的 SQLite `datetime('now')`（恒 UTC）天然自洽，改本地写入需连带改清理 SQL 与存量迁移，收益仅"直查库少心算 8h"；②展示层 `LogQueryService._utc_to_local` 已转换，日志管理页输出为本地时间；③按表区分基准约定（LogAnalyzer 对 system 用 utcnow）继续遵守。运维直查库如需本地显示：`SELECT datetime(created_at, '+8 hours') ...`。
5. **审计表 append-only**：achievement_audit_log 只 INSERT 不删改；数据订正用标记列（is_redundant）而非物理删；system_event_log 例外（有 90 天清理任务可删）。
6. **测试纪律**：CI 用 `tests/fixtures/schemas.py` 共享 DDL（与生产反射一致）；改表结构须同步测试 DDL + 跑 `_require_real_db` 守卫用例。
7. **FK 现状提示**（0002/0003 重建的副作用）：awards 无 FK 定义（competition/laboratory 为逻辑外键）；award_student_winners / award_related_students / laboratory_students / laboratory_assistants / innovation_project_students 无主键约束；laboratory_assistants 丢失了旧 schema 的"每生仅一室"唯一约束。重构时未修属刻意最小改动，业务层防重兜底；如后续要补，走新迁移并同步测试 DDL。
8. **类型规范（0003 + 0010 收尾）**：短字段统一 VARCHAR(n)（语义/长度见各表），时间戳统一 TIMESTAMP，**TEXT 仅保留大文本**（JSON/OCR 全文/LLM 链路/描述备注）。例外（刻意保留）：`achievement_audit_log`/`system_event_log` 的 `created_at` 为 TEXT（时间基准待办未了，见约定 4）；`idempotency_keys.key` 为 TEXT（客户端任意字符串幂等键）、`created_at/expires_at` 为 REAL（Unix 秒设计）。SQLite 动态类型下类型声明的改动无存储/行为差异，0010 为一致性收尾（文档与未来换库友好）。
