## 1. 模板体系现状与收敛路线

| 项 | 现状 | 设计 |
| --- | --- | --- |
| 基础模板 | 双体系并存：`base.html`（Bootstrap5，admin/chat 用）+ `user_base.html`（Tailwind，学生/教师用） | **阶段四收敛到 Tailwind**（P3-1）；本次改造的新组件一律用 **Tailwind + 原生 JS** 实现，不再引入新 Bootstrap 组件，避免加重分裂 |
| JS 架构 | 无框架，`fetch` + `innerHTML`（均经 escapeHtml） | 维持无框架；新增统一 `api.js` 封装（自动注入 CSRF Token / trace_id 读取 / 统一错误码 toast） |
| 图标/组件库 | 无 | 不引入；时间线/进度等组件手写（见下） |

## 2. 组件设计（按 FR-UI 逐条）

### 2.1 审核轨迹时间线（FR-UI-01，数据源 `GET /api/audit/timeline/<kind>/<id>`）

- 垂直时间轴：每项 = 动作图标 + 操作人 + 操作角色徽章 + 相对时间（hover 显绝对时间）+ 变更摘要（`change_detail` 的 diff 键值对，最多展开 5 条）。
- 角色徽章配色：学生=蓝 / 教师=绿 / **AI=紫（机器人图标，明确非人类操作）** / 管理员=橙 / 系统=灰。
- 空态："暂无审核记录"；加载态：骨架条×3。

### 2.2 批量上传进度（FR-UI-02，轮询 `GET /achievement-submit/progress`）

- 文件卡片列表，单文件状态机：`排队 → OCR识别中 → LLM抽取中 → 校验中 → 完成 ✅ / 失败 ❌ / 待人工 🖐️`。
- 顶部总进度条（n/总数）+ 阶段统计徽章；失败/待人工卡片置顶并提供"重试 / 转手动导入"操作（衔接 2.5）。
- 全部终态后停止轮询；阶段四后端迁 Redis 后接口不变。

### 2.3 AI 对话流式渲染（FR-UI-04，对接 API §5 SSE 协议）

- `EventSource` + 打字机效果（60ms/字渐进，缓冲追赶时加速）。
- 事件渲染：`tool_call`→灰色"正在查询…"胶囊；`source`→引用卡片（文档名+相似度，点击展开原文片段）；`error(4003)`→熔断提示 + 倒计时自动重试一次；`done`→渲染用量角标。
- 断线重连：`Last-Event-Id` 续传，重连期间显示"连接中断，正在恢复…"横幅。

### 2.4 危险操作二次确认（FR-UI-05）

- 统一确认弹窗组件（原生 dialog）：标题 + **影响条数清单**（列出将处理的记录名）+ 输入无需键入，点击确认。
- 提交按钮点击后 **disabled + loading**，直至响应返回（防双击，配合 Idempotency-Key 双保险）。
- 适用：批量通过 / 批量放弃 / 批量驳回 / 撤回 / 删除。

### 2.5 失败原因友好展示（FR-UI-06，衔接 FR-EXTRACT-07）

- 错误分级：**可自助**（4001 OCR 失败→"照片模糊？请重拍或转手动导入"）/ **需等待**（4003 熔断→倒计时）/ **需联系**（5xxx→显示 trace_id 短码，"凭此编号联系管理员"）。
- 所有失败卡片必带一个行动入口，不允许"只有错误没有出路"。

## 3. 全局交互规范

| 态 | 规范 |
| --- | --- |
| 加载态 | 骨架屏（列表）/ 居中 spinner（按钮内）/ 顶部细进度条（路由切换）三选一，禁止白屏 |
| 空态 | 插图 + 一句话说明 + 主行动按钮（如"上传第一份奖状"） |
| 错误码 → UI | 统一经 `api.js` 拦截：1xxx→跳登录、3xxx→黄色横幅（业务冲突说明）、4xxx→AI 降级卡、5xxx→红色 toast + trace_id |
| CSRF | 所有表单/JS 写请求经 `api.js` 自动注入 `X-CSRF-Token` |

## 4. 验收

① 时间线含 AI 节点且徽章区分人类/AI；②上传进度状态机六态全覆盖（构造 mock）；③ SSE 打字机 + 断线续传实测；④ 双击提交仅产生一条记录（按钮 disabled + 幂等键双保险）。（v1.1：原"375px 移动端单手操作"验收项随取舍 D6 移除）
