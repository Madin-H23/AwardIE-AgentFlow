## 1. 背景与目标

### 1.1 三方输入

| 来源 | 核心主张 |
| --- | --- |
| **DeepSeek 方案** | 转向百度云/阿里云风格白色控制台；GLM 打设计地基（base_console 基类）+ Flash 批量迁移；Tailwind `dark:` + Alpine.js 暗黑切换；品牌色 #1677ff；**铁律：不要一次重写 79 个页面** |

| critical | `#7f1d1d` | `#fee2e2` | `#fca5a5` | `rgba(127,29,29,.25)` |

### 3.3 字体（三角色）

| 角色 | 字体 | 应用 |
| --- | --- | --- |
| 界面正文 | 系统中文栈（PingFang SC / Microsoft YaHei，现状沿用） | 导航/按钮/正文 |
| **数据等宽** | `ui-monospace, 'Cascadia Mono', Consolas` | 时间戳/日志行/ID/指标数字（`tabular-nums`） |
| 不引 web font | — | 离线部署约束，务实 |

### 3.4 签名元素：生命体征带（Vitals Strip）

看板顶部四张 Metric Card 组成的横条：**今日审核量 / 待审积压 / AI 服务状态 / 活跃告警数**。AI 状态卡含**呼吸圆点**（teal `#0f766e` 正常呼吸；熔断开红色急促脉动），告警非零时数字脉动。全页唯一动效，`prefers-reduced-motion` 时全部停用。
**立意**：日志页第一问"系统活着吗、病在哪"，体征带直接回答；呼吸点即"活着"的隐喻。明确拒绝"大数字+渐变 accent"模板答案。

### 3.5 一个有理由的审美风险

**日志级别不用圆角 pill，改用 3px 左竖条 + 同色文字**（`.severity-bar`）。理由：日志流数百行滚动，pill 占宽且圆角在等宽流中破坏对齐；竖条在纵向滚动时形成连续色纹，级别分布一眼可读（Datadog 等日志工具成熟模式）。现有 badge 用于低密度表单区不受影响，两制并存各司其职。

### 8. 门户双体系与 tokens 扩展（2026-08-20 追加）

#### 8.1 门户双体系决策（P2-B 评估实证）

门户（student/teacher 14 页 extends `user_base.html`）与 admin 是**两个受众/两种风格**——门户为对外展示 + 个人中心（Tailwind 展示风），admin 为管理控制台（tokens 体系）。**决策：不把门户强行并入控制台风**，而是"公共层统一、页面展示风不变"：

| 事实（实证） | 值 |
| --- | --- |
| Tailwind 编译产物 | `static/css/tailwind.css`（34KB）已在并被引用 → 换壳无需重编译 |
| 重编译前置 | `tailwind_input.css` + `tailwind.config.js`(v3) + node v24/npm 本机可用 |
| 门户 Tailwind 依赖 | 7985 次出现 / 404 个去重类，页面深度绑定 |
| 已落地（P2-B-A） | `user_base` 公共层：用户下拉（与后台同款）+ 主题切换按钮（console_theme.js 同源），页面 Tailwind 类零改动 |
| 待做（P2-B-B） | 重编译 Tailwind + 门户 `dark:` 暗黑适配（`html[data-theme]` 已由 console_theme.js 驱动，产物需含 dark: 变体） |
