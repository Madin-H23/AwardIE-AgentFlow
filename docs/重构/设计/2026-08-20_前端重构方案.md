## 1. 背景与目标

### 1.1 三方输入

| 来源 | 核心主张 |
| --- | --- |
| **DeepSeek 方案** | 转向百度云/阿里云风格白色控制台；GLM 打设计地基（base_console 基类）+ Flash 批量迁移；Tailwind `dark:` + Alpine.js 暗黑切换；品牌色 #1677ff；**铁律：不要一次重写 79 个页面** |
| **项目现状**（实测核实 2026-08-20） | admin 侧 41 页 extends base.html（Bootstrap 5.3.2 CDN + custom.css）；门户 14 页 user_base（本地编译 Tailwind 3.4，**无 node_modules 无法重编译**）；无 Alpine、无暗黑基础；ECharts 纯 CDN（npmmirror+回退）；共 79 模板（admin 54）；sidebar 为独立 include（单一真源） |

### 1.2 目标

建立"控制台新体系"的**地基**（基类 + 主题 + 三组件），并以 **L5 日志页作为首个落地页**验证地基；不动任何旧页面。终点（T9 后续）：旧页面批量迁入新基类后 base.html 退役。

## 2. 技术裁决（对 DeepSeek 方案的两处改道）

| # | 议题 | DeepSeek 建议 | 现状约束 | **裁决** | 理由 |
| --- | --- | --- | --- | --- | --- |
| D1 | 暗黑实现 | Tailwind `dark:` 前缀 | admin 侧不用 Tailwind；Tailwind 是门户编译产物且无 node_modules **无法重编译** | **CSS 变量双主题**（`:root` 亮 / `[data-theme="dark"]` 暗）+ **Bootstrap 5.3 原生 `data-bs-theme="dark"`** 双轨同步 | 项目用的 Bootstrap 5.3.2 原生支持 data-bs-theme；切换 JS 同步设置两个属性即全组件跟色，零新依赖、零编译链 |

| D5 | 范围 | 警告别一次重写 79 页 | admin 54 页 | **本轮=地基+3 组件+L5 一页**；批量迁移列 T9 | 与 DeepSeek 分阶段战术一致 |

## 3. 视觉规格（Design Tokens）

### 3.1 色板（亮色 / 暗色成对——**铁律：所有颜色必须成对定义，禁止暗黑用纯黑 #000/纯白 #fff**）

| Token | 亮色 | 暗色 | 用途 |
| --- | --- | --- | --- |
| `--bg` | `#f4f5f7` | `#141414` | 页面底 |
| `--panel` | `#ffffff` | `#1f1f1f` | 卡片/面板 |
| `--line` | `#e6e8eb` | `#303030` | 边框/分隔 |
| `--brand` | `#1677ff` | `#1677ff` | 主操作/高亮（仅按钮与高亮，克制使用） |
| `--ink` | `#1f2329` | `rgba(255,255,255,.85)` | 主文字 |
| `--ink-2` | `#646a73` | `rgba(255,255,255,.55)` | 次文字 |
| `--sb-bg` | `#141414` | `#141414` | 侧边栏（两态恒深，控制台惯例） |

### 3.2 Severity 五级阶（L5 日志场景信息设计核心）

| 级别 | 亮色文字 | 亮色底 | 暗色文字 | 暗色底 |
| --- | --- | --- | --- | --- |
| debug | `#94a3b8` | 透明 | 同亮 | 透明 |
| info | `#2563eb` | `#eff6ff` | `#60a5fa` | `rgba(37,99,235,.15)` |
| warning | `#d97706` | `#fffbeb` | `#fbbf24` | `rgba(217,119,6,.15)` |
| error | `#dc2626` | `#fef2f2` | `#f87171` | `rgba(220,38,38,.15)` |
| critical | `#7f1d1d` | `#fee2e2` | `#fca5a5` | `rgba(127,29,29,.25)` |

### 3.3 字体（三角色）

| 角色 | 字体 | 应用 |
| --- | --- | --- |
| 界面正文 | 系统中文栈（PingFang SC / Microsoft YaHei，现状沿用） | 导航/按钮/正文 |
| **数据等宽** | `ui-monospace, 'Cascadia Mono', Consolas` | 时间戳/日志行/ID/指标数字（`tabular-nums`） |
| 不引 web font | — | 离线部署约束，务实 |

### 3.4 签名元素：生命体征带（Vitals Strip）

看板顶部四张 Metric Card 组成的横条：**今日审核量 / 待审积压 / AI 服务状态 / 活跃告警数**。AI 状态卡含**呼吸圆点**（teal `#0f766e` 正常呼吸；熔断开红色急促脉动），告警非零时数字脉动。全页唯一动效，`prefers-reduced-motion` 时全部停用。
**立意**：日志页第一问"系统活着吗、病在哪"，体征带直接回答；呼吸点即"活着"的隐喻。明确拒绝"大数字+渐变 accent"模板答案。

### 3.5 一个有理由的审美风险

**日志级别不用圆角 pill，改用 3px 左竖条 + 同色文字**（`.severity-bar`）。理由：日志流数百行滚动，pill 占宽且圆角在等宽流中破坏对齐；竖条在纵向滚动时形成连续色纹，级别分布一眼可读（Datadog 等日志工具成熟模式）。现有 badge 用于低密度表单区不受影响，两制并存各司其职。
