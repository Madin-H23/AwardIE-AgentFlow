## 1. 总则

### 1.1 统一响应包装（SSE 端点除外）

```json
{ "trace_id": "550e8400-e29b-41d4", "code": 0, "message": "ok", "data": { } }
```

- `code=0` 成功；非 0 见 1.2 错误码。`message` 面向用户（中文、脱敏，禁止透出 `str(e)`，P2-8）。
- HTTP 状态码与 code 并用：4xx/5xx 语义不变，body 仍用统一包装。
- 所有响应头带 `X-Trace-Id`（见 §7）。

### 1.2 统一错误码（对照需求 8.6.2 状态机 / P 级问题）

| 段 | 含义 | 示例 |
| --- | --- | --- |
| 0 | 成功 | — |
| 1xxx 认证/授权 | 1001 未登录；1002 密码错误（限流计数）；1003 CSRF Token 缺失/失效（P1-1）；1004 角色越权；1005 资源非本人（IDOR，P1-4/P0-10） |
| 2xxx 参数/校验 | 2001 参数格式（Pydantic）；2002 文件类型不在白名单（P0-10）；2003 超过大小上限（P1-23）；2004 重复上传同 file_hash（幂等命中，返回既有 pending） |
| 3xxx 业务状态机 | 3001 状态机非法转换（乐观锁/version 冲突，P1-15）；3002 非 submit 不可审核（P1-14）；3003 已入库重复（唯一索引冲突，P0-9）；3004 驳回后未修改不可重交 |
| 4xxx AI 服务 | 4001 OCR 全链失败；4002 LLM 超时/重试耗尽（P1-20）；4003 熔断中（P1-10，附 Retry-After）；4004 LLM 输出校验失败（Pydantic 拒收） |
| 5xxx 系统 | 5001 DB 锁等待超时；5002 内部错误（详情仅入日志） |

### 1.3 鉴权与幂等通则

- 页面路由：`@require_user_type(...)` 跳转登录；API 路由：`@require_role_api_json(...)` 返回 1001/1004 JSON。
- 写操作：`POST` + CSRF Token（`X-CSRF-Token` 头或表单字段，P1-1）。
- **幂等键**：批量审核/导入类接口必传客户端生成的 `Idempotency-Key`（UUID），服务端 10 分钟窗口内同 key 直接返回上次结果——防双击重复提交（P0-9 前端侧配合 FR-UI-05）。**存储介质（CR-4）**：阶段二落 SQLite 共享表 `idempotency_keys(key TEXT PK, response_json, expires_at)`（多 worker 可见；内存字典在多 worker 下失效，双击两请求落不同 worker 即重复执行），阶段四迁 Redis。

---

### 1.4 异常契约（CR-9）

- 统一异常基类 `AppError(code, message, http_status)`；**业务侧只抛异常、不自行 jsonify 错误**（P2-8 根治的执行机制）。
- 业务异常映射表：`StateConflictError→3001`、`NotSubmittableError→3002`、`DuplicateEntryError→3003`、`RejectWithoutEditError→3004`、`FileTypeDenied→2002`、`FileTooLarge→2003`、`BreakerOpenError→4003（响应附 Retry-After）`。
- 全局 `app.errorhandler(AppError)` 统一翻译为 §1.1 包装；未捕获异常收口为 `5002`（详情仅入日志，携带 trace_id）。
- Service 层**禁止 bare except**（P3-11；CI lint 门禁见部署 §7），吞异常须显式 `except SpecificError` 并记录 warning。

## 4. 成果/审核层核心接口详设

### 4.1 提交（pending→submit）

```json
POST /student/achievement-submit/submit
Headers: X-CSRF-Token, Idempotency-Key: <uuid>
Body: { "pending_ids": [11,12], "expected_versions": { "11": 3, "12": 1 } }
→ 200 { code:0, data:{ "submitted":[11], "failed":[{"id":12,"code":3001}] } }
```

`expected_versions` 来自页面渲染时的 pending.version——**乐观锁贯通到前端**（P1-15）。

### 4.2 审核通过（submit→archived+入库）

```json
POST /teacher/api/review/approve
Body: { "pending_id": 11, "expected_version": 4, "force": false }
→ 200 { code:0, data:{ award_id, audit_log_id } }
→ 409 { code: 3002|3003 }   # 非 submit / 唯一索引冲突(重复入库被拦截)
```

服务层顺序（单事务）：条件 UPDATE 状态守卫 → 入库（ON CONFLICT 查旧返回 3003）→ 写 review 决策 → **事务外** AuditLogger 异步留痕（8.6.3 不阻塞）。

### 4.3 批量审核【新增】

```json
POST /teacher/api/review/batch
Headers: Idempotency-Key 必填
Body: { "action": "approve|reject|discard", "items": [{"pending_id":11,"expected_version":4}] }
→ 200 { code:0, data:{ "succeeded":[11], "failed":[{"id":12,"code":3001,"reason":"已被撤回"}] } }
```

**部分成功语义**：逐条独立小事务（避免一条失败全批回滚，P2-15 教训），结果分列返回；整批幂等由 Idempotency-Key 保证。

### 4.4 驳回【新增，FR-APPROVE-07】

```json
POST /teacher/api/review/reject
Body: { "pending_id": 11, "expected_version": 4, "reason": "证书照片模糊，请重拍" }
→ 200 { code:0 }   # status→rejected；提交人列表高亮"已驳回"；修改后可重新 submit（rejected→submit 需 data 变更）
```

## 5. SSE 流式对话【新增】`GET /assistant/chat/stream?mode=auto`

**事件协议**：

| event | data 格式 | 时机 |
| --- | --- | --- |
| `open` | `{trace_id}` | 连接建立 |
| `delta` | `{"text": "…"}` | LLM 增量 token |
| `tool_call` | `{"tool": "query_awards", "args": {...}}` | Function Calling 触发 |
| `source` | `{"docs": [{"name", "score"}]}` | RAG 检索命中（FR-CHAT-06） |
| `error` | `{"code": 4003, "retry_after": 60}` | 熔断/超时降级 |
| `done` | `{}` | 结束（含 usage 统计） |

- 心跳 `: ping\n\n` 每 15s（防代理断连）；`Cache-Control: no-cache`；`X-Accel-Buffering: no`（nginx 透传）。
- 前端 `EventSource` 自动重连：携带 `Last-Event-Id` 续传（服务端按 trace_id 缓冲最近 200 事件）。
- 同步 `/assistant/chat` 保留为降级路径（熔断中/老旧客户端）。
- **连接级限流（CR-6）**：每用户同时 SSE 连接 ≤2，超出新连接返回 429；连接建立即计入 limiter（SSE 属计费 GET）；`done` 后服务端主动关闭连接。

## 6. 文件下载安全接口【新增】`GET /files/achievements/<int:id>`

设计要点（P1-4 / P0-10 根治）：

1. **按 ID 不按路径**：`id` → 查 pending/awards 取 `file_path`，杜绝路径猜解；
2. **归属校验**：`resource.submitter_id == session.users_id` 或审核关系（教师查所属实验室），否则 403/1005；
3. **响应头**：`Content-Disposition: attachment; filename*=UTF-8''<原名>`（强制下载，杜绝 inline XSS）+ mimetype 白名单（jpg/png/pdf/xlsx/zip）；
4. 旧路径式 `/achievement-submit/file/<path>` 保留 302 跳转到新端点一个迭代后废弃。

## 7. trace_id 注入规范

```
TraceIdFilter(before_request):
  trace_id = request.headers.get('X-Trace-Id') or uuid4().hex   # 支持网关/上游传入
  ctx = contextvars.ContextVar('trace_id'); ctx.set(trace_id)
  g.trace_id = trace_id; response.headers['X-Trace-Id'] = trace_id
```

- 透传链：路由 → 服务层（dataclass 携带）→ AuditLogger（写入 audit_log.trace_id）→ LLM 请求头（Provider 支持时）→ 日志格式 `%(trace_id)s`（P2-11）。
- 后台任务（归档/清理）：以 `task:<name>` 前缀生成，区别于请求态。
