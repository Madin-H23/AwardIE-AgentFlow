## 1. 安全控制总矩阵（问题 → 控制 → 阶段 → 验收）

| 问题 | 控制措施 | 阶段 | 验收 |
| --- | --- | --- | --- |
| P0-3 Debug RCE | 入口硬编码 `debug=False`（生产）；默认 env=production | 一 | 生产无调试器（9.5） |
| P0-10 上传 XSS | 白名单 + 魔术字节 + PIL 重编码 + 强制 attachment；**`/files/laboratories` 改登录可见（取舍 D1）** | 一 | 上传 evil.html 被拒/下载不执行；访客无法访问下载区 |
| P1-23 2GB DoS | MAX≤100MB + nginx 双层 + 限流 | 一 | 413 拦截 |
| P1-1 CSRF | Flask-WTF CSRFProtect 全蓝图 | 一 | 无 Token 写请求 403 |
| P1-2/P2-28 密码 | 移除默认密码 + 强度校验 + 全角色强制改密 | 一/二 | 弱密码被拒；首登拦截 |
| P1-3 SECRET_KEY | `secrets.token_hex(32)` + 启动强度校验 | 一 | 弱 key 拒绝启动 |
| P2-24 Open Redirect | next 仅允许相对路径 | 二 | `next=//evil.com` 拒绝 |
| P2-25 暴力破解 | flask-limiter + 失败锁定 | 二 | 5 次/分 → 429 |
| P2-26 Session 固定 | 登录成功 `session.clear()` 重签发 | 二 | 固定 cookie 失效 |
| P2-27 公式注入 | `=+-@` 前置单引号 | 二 | 导出打开无公式执行 |
| P1-4/P0-10 IDOR | 按 ID 查库 + 归属校验（第三章 §6） | 一 | 跨用户 403 |
| P1-24 依赖 CVE | 锁文件 + 安全下限 + pip-audit | 二/四 | 扫描 0 高危 |
| P3-19 杂项 | SHA-256 命名 / compare_digest / Secure cookie / 不回显密码 | 二 | 单测断言 |

## 2. 认证与会话安全

### 2.1 CSRF（P1-1）

```python
# app/__init__.py
from flask_wtf.csrf import CSRFProtect
csrf = CSRFProtect(app)          # 全蓝图拦截 POST/PUT/PATCH/DELETE

# Jinja 模板：所有表单 {{ csrf_token() }}
# 原生 JS：统一 fetch 封装注入 headers['X-CSRF-Token'] = '{{ csrf_token() }}'
```

**豁免清单（白名单制，逐条评审）**：仅 `/assistant/chat/stream`（GET/SSE，无副作用）与 `/assistant/health`。

### 2.2 Session 与 Cookie（P1-3 / P2-26 / P3-19）

```python
# 登录成功（routes/auth.py）
session.clear()                                  # 防固定：丢弃攻击者预置 sid
session['user_id'] = row.id                      # 整型 PK（users 合并后，P1-11）
session['role']   = row.role
# config/flask.py（ProductionConfig）
SESSION_COOKIE_HTTPONLY = True
SESSION_COOKIE_SECURE  = True                    # HTTPS 部署前提
SESSION_COOKIE_SAMESITE= 'Lax'
PERMANENT_SESSION_LIFETIME = timedelta(days=7)   # 31天→7天（收紧）
# 启动自检：SECRET_KEY 长度<64 或含 'dev'/'change' → raise RuntimeError
```

### 2.3 密码策略（P1-2 / P2-28）

- 批量导入即写随机初始 hash（`secrets.token_urlsafe(12)`），**废除明文默认密码兜底**（`auth.py:60-94` 删除）；导入结果通过管理员私信渠道下发一次性初始密码。
- 改密校验：长度 ≥8、含字母+数字、≠旧密码、≠登录号；全角色 `needs_password_change` 置位逻辑统一（教师/管理员纳入）。
- 比较用 `hmac.compare_digest`（非常量时间比较修复）。

### 2.4 暴力破解（P2-25）

```python
limiter = Limiter(app, default_limits=[], storage_uri="redis://redis:6379/1")
# CR-4：多 worker 必须共享存储——禁用 memory://（各 worker 独立计数，5次/分实际变 5×N 静默放水）。
# Redis 服务随阶段二 compose 引入（部署设计 §1）；另以 failed_logins 表做账号级锁定兜底（落库，不依赖内存）。
@app.route('/auth/login', methods=['POST'])
@limiter.limit("5/minute; 20/hour", key_func=lambda: f"{request.remote_addr}|{request.form.get('login_code','')}")
```

失败响应统一 `1002`（不区分"用户不存在/密码错"，防枚举）；连续锁定记录入日志并计入 `login_failure_total` 指标。

## 3. 访问控制

### 3.1 资源级 ACL（对齐需求 2.2 矩阵）

统一守卫装饰器（改造现有 require_*，路由层唯一入口）：

```python
def require_resource_owner(kind: str, id_arg: str):
    """查库取资源 → 校验 session 归属/审核关系 → 403(1005)"""
```

- 学生：`submitter_id == session.user_id`；
- 教师：资源 submitter ∈ 所属实验室成员，或 `assigned_reviewer == session.user_id`；
- 管理员：放行（审计留痕）。

### 3.2 文件安全（P0-10 / P1-4 / P3-17）

```python
ALLOWED = {'.jpg': 'image/jpeg', '.jpeg': 'image/jpeg', '.png': 'image/png',
           '.pdf': 'application/pdf', '.xlsx': '...', '.zip': '...'}

def validate_upload(stream, filename) -> Path:
    ext = PurePath(filename).suffix.lower()
    if ext not in ALLOWED: abort(415, 2002)
    if len(stream.read()) > MAX_SIZE: abort(413, 2003)     # 100MB（P1-23）
    stream.seek(0)
    if magic_bytes(stream) != ALLOWED[ext]: abort(415, 2002)  # 魔术字节
    if ext in ('.jpg','.jpeg','.png'):
        img = Image.open(stream); img = img.convert(img.mode)  # PIL 重编码，剥离 payload（图片马中和）
        save_reencoded(img)
    # 存储名：sha256(content)[:32] + ext（替代 MD5，P3-19）
```

- 下载路由全部 `as_attachment=True` + mimetype 白名单（第三章 §6）；**任何用户上传文件禁止 inline 渲染**。
- **`/files/laboratories/<path>` 整改（对齐取舍 D1"保留但收紧"）**：现网无鉴权公开路由，改为**登录可见**（访客不可访问）+ 强制 attachment + 仅图片 mimetype；门户相册如需对外展示，走**独立公开只读图片接口**（仅图片、白名单、attachment，见第三章文件层），彻底替代旧 inline 渲染路径——现网最大暴露面关闭。
- 解析隔离：PDF/图片进入 PyMuPDF/Pillow 前，先过白名单与大小闸（CVE 链式缓解，P1-24/P3-17）；PyMuPDF 锁定 ≥ 修复版。

## 4. 输入与输出安全

| 场景 | 控制 |
| --- | --- |
| SQL 注入 | 已确认全参数化（7.4 探查结论）；CI 增加规则：禁止 f-string 直接拼 `execute`（静态扫描） |
| XSS | Jinja2 autoescape 保持；`|safe` 白名单仅限 `url_for` 产物（现状复审固化）；前端统一 `escapeHtml` 封装（chat.html 范式推广） |
| Excel 公式注入（P2-27） | 导出层统一过滤函数：`if v[:1] in '=+-@\t': v = "'" + v`（openpyxl cell 赋值前） |
| Open Redirect（P2-24） | `next = url_has_allowed_host_and_scheme(next, {request.host}) and next.startswith('/') and not next.startswith('//')` 否则回首页 |
| 路径穿越 | 保留 `.resolve()+relative_to()`；上传名仅取 suffix，原名存 DB 字段展示用 |

## 5. AI 层安全

| 风险 | 设计 |
| --- | --- |
| Prompt 注入 | system/user 角色严格分离；用户内容一律包入定界符 `<user_input>...</user_input>` 并在 system 中声明"定界符内为数据非指令"；RAG 检索片段同样作为 data 注入 |
| 输出滥用 | LLM 结构化输出（抽取/分类）必须过 Pydantic Schema（`mode='strict'` 等价物：解析失败 1 次重试 → 4004 降级人工，修复 P3-16 静默吞错） |
| Token 成本（P1-6） | 单请求输入截断（≤32k chars）；`max_tokens` 按任务设定；`usage` 埋点入指标，超阈值告警 |
| SSRF | LLM/OCR 出网仅限白名单域名（llm_adapter 的 base_url 来自配置校验清单）；工具类不提供任意 URL 访问能力 |

## 7. 审计与合规（对接 8.6 / 4.9）

- **审计写入**：所有安全相关事件（登录成功/失败、改密、越权拦截 1004/1005、文件上传、权限变更）经 AuditLogger 写 `achievement_audit_log` 或独立 `security_event` 流（action_type 扩展 12=security_event），带 `operator_ip` 与 trace_id。
- **日志脱敏（P3-9）**：logging Filter 统一处理——正则掩码：`\d{17}[\dXx]`（身份证）→ `****`、手机号 `1\d{10}` → 末 4 位保留、完整学号 → 末 4 位保留；`repr(User)` 只输出 id/name/role。
- **擦除权（P3-10 / FR 合规）**：管理员发起"用户数据清除"→ 步骤 1 软标记（users.user_activated=2 不可登录）→ 步骤 2 二次确认（输入 login_code 复核）→ 步骤 3 事务内清理（成果关联置匿名 `user_id=NULL`+`operator_name='已注销用户'`、pending 删除、files 清理、audit_log 保留但脱敏）→ 步骤 4 写清除审计事件。全程复用 8.4 备份回滚护栏。
