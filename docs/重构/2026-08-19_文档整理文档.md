## 1. 项目背景与目标

### 1.1 项目简介

AwardIE-AgentFlow 是基于大模型的信息抽取（IE）与多智能体协作的**计算机系学生竞赛成果智能管理系统**。

- **技术栈**：Python 3.11 / Flask 3.0+ / SQLite / LangChain + LangGraph / ChromaDB / PaddleOCR / SQLAlchemy + Alembic / Tailwind CSS
- **核心能力**：OCR + LLM 智能抽取、RAG 知识库问答、多智能体协作审核、奖状/专利/软著全生命周期管理
- **业务价值**：掌握系里师生课堂之外的科研学习活动数据（只关注开始与成果），支撑学校数据分析、统筹规划、项目申报与总结

### 1.2 文档现状成因

项目经历了三个文档代际，这是当前文档混乱的根源：

| 代际 | 时间 | 产物 | 现状 |
| --- | --- | --- | --- |
| 第一代：随手记录 | 项目初期~2025-01 | `任务说明文档.md`、`TODO/`、`设计.md`、`设计原则.md` | 零散，部分已失效 |
| 第二代：中间代设计 | 2026-01~02 | `plans/`（15 篇）、`设计文档/`（30+ 文件）、`迁移/`、`modifications/` | 功能设计详尽，但已被重构取代 |
| 第三代：重构权威体系 | 2026-08-14 起 | `重构/`（SRS + SDD + 实施记录 + 测试方案 + 风险登记册 + TODO 索引） | **当前唯一权威标准** |

### 1.3 本文档的目标

1. 为新成员（或 AI 协作者）提供一份"看这一个文件就知道文档在哪、该读哪个"的导航
2. 明确文档分类与命名规范，杜绝"同一主题三处散落"
3. 指出缺失、重复、待补充部分，形成可执行的改进清单
4. 建立文档更新维护的规范，保证体系不再腐化

## 3. 文档分类方式与目标目录结构

### 3.1 分类维度

采用**三层分类**，优先级从高到低：

1. **按生命周期阶段**（第一层目录）：现行有效 → 待归位 → 已归档
2. **按文档类型**（第二层目录）：需求 / 设计 / 实施 / 测试 / 运维 / 用户指南 / 过程管理
3. **按受众**（在文档头部标注）：`全员` / `开发` / `运维` / `最终用户` / `AI 协作`

### 3.2 目标目录结构

```
docs/
├── README.md              # 【新增】文档总索引：一页导航，按受众/任务分类入口
├── 重构/                  # ✅ 权威体系（现有，原样保留）
│   ├── 2026-08-14_需求分析文档.md
│   ├── 2026-08-14_SRS-SDD交叉审查报告.md
│   ├── 2026-08-19_上下文交接摘要.md
│   ├── 2026-08-19_文档整理文档.md   ← 本文档
│   ├── 风险登记册.md
│   ├── 设计/              # SDD v1.2 系列 + 测试方案 + TODO索引 + 字段映射 + 日志系统设计
│   └── 实施记录/          # 阶段一~五实施文档
├── 运维指南/              # 【P1 归位】日志配置指南 / 安装和运行记录 / path-portability

├── TODO/                  # 仅保留 md：bug.md / 修改讨论.md / 自动化测试用例.md
└── 归档/                  # 【P0 归档】历史文档，只进不出
    ├── 旧计划/            # ← plans/ 15 篇
```

## 4. 文档命名规范

### 4.1 现行规则（重构体系已采用，全项目推广）

1. **日期前缀**：长期有效的正式文档用 `YYYY-MM-DD_主题.md`，如 `2026-08-19_测试方案.md`（版本演进在文档内 `> 版本` 行记录，不用日期后缀堆叠）
2. **中文名为主**：面向人读的文档用中文命名；仅代码关联物（`CLAUDE.md`、`README.md`、模块内文档）保留英文名
3. **动词性命名用于记录**：实施记录用 `阶段N-主题实施文档.md`；计划用 `主题设计.md`
4. **目录即分类**：文件名不重复目录语义（`测试方案/核心业务测试方案.md` 而非 `测试方案/测试方案目录下的核心业务测试方案.md`）

### 4.2 归档命名

- 归档文件**不改名**（保留原路径可考据），仅在 `归档/README.md` 中列索引说明归档原因与替代文档指向
- 已被取代的文档，归档时在文件头插入一行标注：

  ```markdown
  > ⚠️ 已归档（2026-08-19）：本文档已被 `docs/重构/设计/xxx.md` 取代，仅供历史考据。
  ```

### 4.3 版本管理

- 文档头部统一格式：`> 版本：vX.Y ｜ 日期：YYYY-MM-DD ｜ 维护人：xxx`
- 小版本（v1.1）= 内容补充；大版本（v2.0）= 结构性重写，需在 git commit message 中说明
- 重构体系文档（SRS/SDD/测试方案）的版本演进**必须**在 TODO 索引或实施记录中留痕
